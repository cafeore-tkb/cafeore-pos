# Quickstart: 提供時間モデル（stack モデル）の当日当てはめタブの確かめ方

実装（`/speckit-implement`）のあとに、機能が仕様どおりに動くことを確かめる手順。コードの中身は [contracts/](./contracts/)、データの定義は [data-model.md](./data-model.md) を参照。

## 0. 前提

- `pnpm i` 済みであること（ルート README の Get Started）。
- 作業ブランチは `feat/pos-dashboard-stack-model`。
- backend（Go）は**起動するだけで、コードは変えない**。

## 1. Go・DB・API に差分が無いこと（最初と最後に確かめる）

```bash
git diff --stat main -- api openapi modules .github
```

**期待**: 何も出ない。変更は `services/pos/app/`・`documents/analytics/dashboard.md`・`specs/` だけに限られる。

```bash
git diff --stat main
```

## 2. 単体テスト（計算の正しさ）

```bash
pnpm pos test:unit
```

**期待**: すべて通る。とくに次を確かめる（テストの対応は contracts/stack-model-module.md の不変条件 1〜7）。

| 確かめること | 期待値 |
|---|---|
| SC-001（2025 年 978 件、N = 6） | a1 = 7.28 杯、b1 = −0.554、c1 = 5.99 分、b = 0.444 分/杯（有効数字 3 桁） |
| 時点の切り詰め（2025-11-02 13:00） | 154 件、a1 = 5.40、b1 = −0.803、c1 = 6.89 |
| 推移の最後の点 | 係数の欄と一致する |
| 件数不足（19 件）・収束しない | 係数を持たない結果（`ok: false`）と理由 |
| 固定モデルの予測 | `predictReadyMinutes` と一致する。既存の `readyTimeEstimate.test.ts` も通る |

## 3. 品質ゲート（憲法の「開発ワークフローと品質ゲート」）

```bash
pnpm run lint
pnpm pos typecheck
pnpm common typecheck
cd api && go test ./...   # Go は無変更。影響が無いことの確認として流す
```

**期待**: すべて通る。`go test` は、`TEST_DATABASE_URL` が無ければ DB のテストを手元ではスキップしてよい（README「backend のテスト」）。

## 4. 画面で確かめる（手元）

1. 既存の手順で backend と DB を起動する（コードは変更しない）。
   ```bash
   docker compose -f api/compose.yaml up -d db
   ```
   backend の起動と環境変数は、ルート README の「backend の環境変数」の表のローカルの値に従う。
2. POS を起動する。
   ```bash
   pnpm pos dev
   ```
3. `/dashboard` を開き、次の点を確かめる。

| # | 操作 | 期待（対応する要件） |
|---|---|---|
| 1 | 広い画面で左ナビを見る | 7 番目に「提供時間モデル」がある。ほかの 6 ページの並び・既定の「売り上げ」は変わらない（FR-001、SC-004） |
| 2 | ナビで矢印キーを押す | 7 ページを循環する。狭い画面の上部の選択欄にも出る（FR-001） |
| 3 | 注文が 0〜19 件の日に開く | 「当てはめ不能（件数不足）：あと k 件」と、固定モデルの値・予測だけが出る。当てはめの数値は出ない（US1-3、SC-006） |
| 4 | 別のタブ・端末でレジから注文を入れ、提供画面で提供可能にする（20 件を超えるまで） | 再読み込みなしで、件数・係数・いまの stack が 10 秒以内に変わる（US1-2、SC-002） |
| 5 | 散布図の点にカーソルを合わせる・タップする | 注文番号・stack・実測・予測が数値で出る（US2-3） |
| 6 | 集計間隔を 15 分 → 60 分にする | 推移の点の間隔が 60 分になる。最後の点は係数の欄と同じ値になる（US3-1・3） |
| 7 | 終了時刻を過去にする | 見出しが「期間末（HH:MM）時点の状況」になる（FR-009） |
| 8 | 開始時刻を未来にする | 既存のエラーが出て、図表が隠れる（Edge Cases） |
| 9 | ページの全体を見る | 指名やコメントの文字列がどこにも出ない（FR-018）。すべての軸に単位がある（FR-019） |
| 10 | ほかの 6 ページを順に開く | 実装前と同じ表示・操作である（SC-004） |

**実データに近い量での確認**（SC-003）: 注文が数百〜1,000 件ある日（プレビュー環境の Neon ブランチ、またはリハーサル用に生成した注文）を選ぶ。ブラウザの Performance タブで、ページの切り替えと表示条件の変更から、表示まで 2 秒以内であることを確かめる。超えた場合は、research.md R9 の次の手段（推移のメモの見直し、Web Worker）を検討する。
