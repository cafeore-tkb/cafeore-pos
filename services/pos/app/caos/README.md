# CaOS — Cafeore Operating System

コーヒー提供現場で、6人のドリッパー（抽出担当者）へ注文を割り当て、進行状況を一画面で把握するためのタッチ操作向けの画面です。iPadの横画面を想定し、管制盤を常に表示したまま操作できます。

画面・操作・業務ルール（割当・指名・最大2杯・統合・`次へ`・入れ直し・カードの色・タッチ操作）は、[画面設計・操作要件](./DESIGN_REQUIREMENTS.md)にまとめています。

## 公開

POS の画面の1つとして `/master-sheet` で配信します（<https://cafeore-pos.cafeorepos.workers.dev/master-sheet>）。入口は `services/pos/app/routes/master-sheet.tsx` で、POS のヘッダーは付けません。旧リポジトリ `cafeore-tkb/CaOS` から公開していた [GitHub Pages の版](https://cafeore-tkb.github.io/digital-master-sheet-pages/) は、こちらに切り替えたら止めます。

## 画面

- **A**: NOW線を基準に、6人のレーンと時間軸で進行・待機カードを確認する管制盤
- **C**: 担当者ごとに現在の抽出と待機を横に並べ、次に空く担当者を確認する比較案
- **D**: 紙のマスターシートを画面上に再現する案。6人を列、注文番号を行とした表に、右の注文カードを選んで枠をタップするか、列へドラッグして割り振ります（[cafeore-pos#699](https://github.com/cafeore-tkb/cafeore-pos/pull/699) のコンセプトを移植）
- 最上段のヘッダーからA/C/Dを切り替えます。
- 補助情報は右側パネルに表示し、管制盤全体を隠しません。

### 管制盤A・C・Dの比較

3案とも同じ注文データ・業務ルール（オーダー番号順、指名、最大2杯、`次へ` で完了、緊急の入れ直し）を共有し、違うのは見せ方と割当の操作だけです。

| | A：タイムライン | C：ドリッパー行 | D：マスターシート |
|---|---|---|---|
| 担当者の並び | 6レーン（横軸＝時刻） | 6行（左半分） | 6列（表の列） |
| 待機列の見え方 | 時間軸上のカード位置で全件 | 現在＋待機を横並びで全件 | 注文番号の行に全件（全注文番号に行があり、列を上から読むと担当者の順番） |
| 時間の情報 | NOW線と時刻目盛り、開始・終了予定、次に空く上位3人 | 現在の残り時間、次に空く上位3人 | 列見出しの残り時間のみ |
| 完了済みの表示 | NOW線の左（過去90秒）に薄く | なし | すべて元の行に薄く残す（行は動かさず下へ積む） |
| 未割当の置き場所 | 下段の横帯（先頭12件） | 右半分の縦リスト（全件） | 右の注文カード（全件） |
| 未割当の単位 | 抽出カード | 抽出カード | 注文（割当済み分も薄く表示） |
| 割当操作 | タップで1〜6ボタン／なぞり／ドラッグ | タップで1〜6ボタン／なぞり／ドラッグ | カードを選んで表の「ここに配置」をタップ／列へドラッグ |
| 割当後の移動・戻し | レーン間ドラッグ、タップで1〜6／×で戻す | 詳細モーダル | 列間ドラッグ、右の注文内容へドラッグで戻す、詳細モーダル |
| 1杯カードの統合 | あり | なし | あり（統合した2注文の行を、間の行ごと大きな枠で囲む） |
| 主な実装 | `ControlViewA`（`DispatchBoard` + `UnassignedOrdersPanel`） | `ControlViewC` | `ControlViewD` |

- **A：タイムライン**　時間の流れを最も正確に表す基準案です。待ち時間の偏りや「誰がいつ空くか」が位置で読めて、ドラッグで再配置できます。代わりに情報量が多く、横スクロールやカードの小ささで一覧性が落ちやすくなります。
- **C：ドリッパー行**　担当者を行にして、現在の抽出と待機列を横に並べる案です。未割当を右半分に全件並べます。待機列が長くなると行内の横スクロールになります。
- **D：マスターシート**　紙運用をそのまま置き換える案です。行＝注文番号（未割当や抽出のない番号も詰めずに1行ずつ）なので「どの注文を誰が淹れるか」と注文ごとの杯数が表で揃い、紙に慣れた人が移行しやすいです。淹れ終わっても行は動かず、新しい注文は下へ積まれていきます。割当は2回のタップか列へのドラッグで済み、割当後もドラッグで列を移したり未割当に戻したりできます。統合した1杯同士は、2注文の行とその間の行をまとめて囲む大きな枠で表示します。注文が増えると表が縦に伸びてスクロールが要ります（開いたときは淹れ終わっていない最初の注文付近を表示）。

## cafeore-pos 連携

- 注文は常に cafeore-pos と同じDBから取り込みます。ヘッダーのDBアイコンの点が接続状態で、緑は接続済み、黄は接続中・再接続中です。
- 実データテスト中はDBからの取り込みを止め、テストの注文だけで動かします。終了後の実績表示中も止めたままで、リセットするとDBの注文に戻ります（未準備の注文を取り込み直します）。
- 注文は、POS の画面全体で共有している WebSocket（`/api/ws/orders`、root の `OrdersWSProvider`）から受け取ります。CaOS 用に別の接続は張りません。当日の注文のうち、準備完了・提供済みでないものを未割当に追加し、POS側で準備完了・提供済み・削除になった注文は、未割当に残っている分だけ外します。
- 読み取り専用です。ドリッパーへの割当や `次へ` はCaOSの画面内だけの状態で、DBには書き込みません。
- 注文の明細は、同じ商品・同じ指名の杯を 1 枚のカードにまとめます（2 杯ずつに分ける）。カードの名前は商品の略称、区分は商品の種類の表示名をそのまま出します。カードの豆は、POS の在庫の設定の「商品ごとの使用量」（`GET /api/inventory/usages`）でカードの商品が使う豆の在庫対象を引き、在庫対象の名前をそのまま出します（豆と区分はカードの札。在庫の設定に「商品 → 豆」が無い商品は豆を出しません）。統合できるのも同じ商品・同じ指名の 1 杯どうしだけです。アイスミルクとグッズは除外します。
- POSの指名は、`1`〜`6` の番号のときだけその列に固定し、それ以外はカードに「（指名:名前）」と表示します。
- API の URL は POS と同じ `VITE_API_BASE_URL` です（未設定ならローカルの `http://localhost:8080`）。origin も POS と同じなので、API の `FRONTEND_ORIGINS` に足すものはありません。

## 実データ・テストプレイ

- ヘッダーの「実データテスト」から、過去の祭の実注文を使ったテストプレイを開始できます。
- データは開始の画面で手元の JSON ファイルを選んで読み込みます（ドラッグでも可）。読める形は [cafeore-tkb/sohosai-analysis](https://github.com/cafeore-tkb/sohosai-analysis) の `YYYY/data/day*.json`（`{ orders: [...] }`）と、cafeore-pos の `GET /api/orders` の応答を保存したものです。day1・day2・day12 のように複数選ぶと、重なる注文は 1 件にまとめます。
- 読み込みはこの端末のブラウザの中だけで、担当者名・指名・コメント・お預かりなどは読み込むときに落とします（`@cafeore/common` の `caosPracticeData.ts`）。サーバーには送らず、画面を開き直したら選び直しです。テストプレイ中は POS の注文の取り込みを止め、API にも書かないので、本番の盤面・注文・在庫には混ざりません。リセットすると本番の盤面に戻ります。
- 開始前に時間帯と30分／1時間を選択します。ヘッダーの `1x / 2x / 5x / 10x` に合わせて、時計・タイムライン・注文到着・抽出時間が実時間基準で一緒に進みます。
- 「終了・実績」を押すと、売上、商品構成、ピーク、提供時間、担当量、分割注文の仕上がりΔを表示します。
- 過去の注文データはリポジトリに入れません。

## 開発

POS の一部なので、コマンドも POS と同じです（`pnpm pos dev` で開き、`/master-sheet` に行く）。型チェックとビルドも `pnpm pos typecheck`・`pnpm pos build` に含まれます。

lint は POS と同じ決まりです（`biome.json` に CaOS だけの除外はありません）。スタイルは `caos.css` で `.caos-root` の中に閉じ、POS のほかの画面に漏らさないようにしています。

## コードの分け方

- `components/`：部品（表示だけ）。受け取った値を出し、押されたら受け取った関数を呼ぶ。カードは `OrderCard` 1 つで、管制盤 A・C・D と右のパネルで共通。見出し・列の番号・「次へ」・空きスロットは `BoardParts`、右のパネル（割当・詳細・入れ直し・補助のタブ）は `SidePanels` の `SidePanel`。
- `logic/`：盤面の決まり（純粋な関数）と型（カードの `DripCard`・`OrderTicket` は `cards`、列と盤面の `Barista`・`Board` は `board`。実データの注文は `@cafeore/common` の `PracticeDataOrder`）。カードの組み立て（`posOrders`）・統合と並び（`cards`）・割当や移動や「次へ」や入れ直し（`board`）・列の予定時刻（`queue`）・D の表（`sheet`）・A の目盛りと置く時刻（`timeline`）・入れ直しの選び方（`rebrew`）・実績の集計（`analytics`）・実データテスト（`historical`）・カードの豆（`beans`）。
- `hooks/`：状態と副作用。盤面の状態とタイマー（`useBoardState`）、注文の取り込み（`usePosIngest`）、POS の在庫と「商品 → 豆」の読み込み（`useBeanInventory`）、実データテスト（`useTestPlay`。読み込んだ JSON は `usePracticeData`）、それらをまとめる `useCaosSession`、選んでいるもの（`useBoardSelection`・D の `useSheetSelection`）、ドラッグ（`useCardDrag`）、A の横スクロール（`useTimelineScroll`）など。`App.tsx` はフックを呼んで部品に渡すだけ。
