# CaOS — Cafeore Operating System

コーヒー提供現場で、6人のドリッパー（抽出担当者）へ注文を割り当て、進行状況を一画面で把握するためのタッチ操作向けの画面です。iPadの横画面を想定し、管制盤を常に表示したまま操作できます。

画面・操作・業務ルール（割当・指名・最大2杯・統合・`次へ`・先頭へ・途中への差し込み・カードの色・タッチ操作）は、[画面設計・操作要件](./DESIGN_REQUIREMENTS.md)にまとめています。

## 操作ログ

`/master-sheet` のログは端末に残してから `POST /api/caos/logs` でDBに保存します。コンソールには出しません。通信に失敗したログは残し、接続回復後に再送します。同じ `(tabId, sequence)` の再送はDBで重複保存しません。

POSトップ画面から開く「各種データ書き出し」の「CaOS 操作ログ」にある「ログを保存」で、DBのログをJSONファイルとしてダウンロードできます。`GET /api/caos/logs/export` は同じDBスナップショットで全件を書き出し、ファイルが完成してから返します。JSONの `entries` は端末イベント、`operations` は成功した盤面操作、`cups` はcup単位の履歴、`exportedAt` は書き出し時刻です。未送信の端末ログは、DBへの送信が済んでからの書き出しに含まれます。

一覧取得は `GET /api/caos/logs?limit=100&offset=0` です。`event=ui.click` や `tab_id=UUID` で絞り込めます。応答は `{ entries, limit, offset, hasMore }`、新しい時刻順です。`limit` は1〜1000、`hasMore` が true なら `offset` を進めて続きを読みます。

端末イベントの共通項目は `at`（UTCのイベント時刻）、`tabId`（ページ読込ごとのUUID）、`sequence`（読込内の連番）、`event`（イベント名）、`details`（内容）です。取得時には `receivedAt`（サーバーでの保存時刻）も付きます。`details` は次のような内容です。

- `ui.*`：操作対象のタグ・ラベル・ID。入力欄の値は記録しません。
- `operation.accepted`：操作名 `label` と操作ID `ids`。
- `outbox.response`：`request`・`pressedAt`・`result`・`durationMs`。
- `board.changed`：`changed` は追加・変更されたカードの現在値、`removed` は消えたカードのキー。

DBには次の3テーブルを追加します（既存の起動時AutoMigrateで反映）。

- `caos_client_logs`：端末イベント。失敗・テストプレイも含みます。
- `caos_operations`：成功したPUTの盤面更新・「次へ」・緊急追加/取消・担当者の交代/入れ替え/上級生属性の更新。担当者変更の `details.before` / `details.after` は変更前後の6人、緊急操作の `details` は理由と入れ直しIDです。`occurred_at` は端末時計を補正した押下時刻、`recorded_at` はサーバーでの処理時刻、`context_at` は周囲の杯を観測した処理時点の時刻です。
- `caos_operation_cups`：`(operation_id, unit_id)` ごとに1行。`cup_id`・親の `order_id`・当時の注文番号と操作前後の状態を持ちます。`assigned_at` は未割当からの割当て・別ドリッパーへの移動時刻（同じドリッパー内の並べ替えは含まない）、`merged_at` は統合時刻です。緊急の行には `added` / `removed` と理由 `emergency_reason` を保存し、取消後も元cup/orderと入れ直しIDを引けます。統合元の行に `merge_target_unit_id`・`merge_target_cup_id`・`merge_target_order_id` を残します。入れ直しは `unit_id` が入れ直しID、`cup_id` が元cupのIDです。

操作履歴は盤面更新と同じトランザクションで保存します。拒否・ロールバックされた操作は成功履歴に残りません。過去の割当て・統合時刻を現在の状態から推測して埋めることはしません。

同時間窓は、その日の注文受付後、まだreadyでないCaOS対象cupです。操作直前のサーバーのスナップショットを `in_window = true` の行として残します。入れ直しは元cupのreadyを基準に窓を判定します。オフラインで遅れて届いた操作では、窓はサーバーで適用した時点のものです。端末が押下時に表示していた盤面そのものの再現ではありません。

親・統合先はUUIDで `orders`・`order_cups` にJOINできます。注文編集でcupを削除・再作成する既存仕様に合わせ、現行表への外部キー制約は張りません。削除後も履歴のIDと注文番号は残ります。取得例は [log-queries.sql](./log-queries.sql) にあります。

操作ごとの確認結果とイベント一覧は [LOGGING_COVERAGE.md](./LOGGING_COVERAGE.md) にまとめています。

StrictModeによるEffectの再実行では、同じ接続状態・キューのログと仮の画面開閉を重複保存しません。1回のタップで生じる `ui.pointerdown` → `ui.pointerup` → `ui.click` は別イベントとして残します。

## 公開

POS の画面の1つとして `/master-sheet` で配信します（<https://cafeore-pos.cafeorepos.workers.dev/master-sheet>）。入口は `services/pos/app/routes/master-sheet.tsx` で、POS のヘッダーは付けません。盤面を閲覧だけで映す画面は `/master-sheet/view`（`routes/master-sheet_.view.tsx` → `caos/ReadOnlyBoard.tsx`）で、管制盤 A のタイムラインに同じ盤面を映します（終わったカードは出さず、抽出中・待機だけ）。空きスロットは出さず、カードを押してもアイコンを出さず（未着手の ✋ の印は出す）、盤面への書き込みも送りません。リベロ（ドリッパーにお湯を持って回る係）が見る画面は `/master-sheet/libero`（`routes/master-sheet_.libero.tsx` → `caos/LiberoBoard.tsx`）で、同じ盤面を読むだけです（下の「リベロビュー」）。閲覧の 2 つの画面はヘッダーの「タイムライン」「リベロ」で行き来できます（操作の画面のヘッダーにはリベロビューへのボタンを置きません。トップページの一覧から開きます）。旧リポジトリ `cafeore-tkb/CaOS` から公開していた [GitHub Pages の版](https://cafeore-tkb.github.io/digital-master-sheet-pages/) は、こちらに切り替えたら止めます。

## 画面

- **A**: NOW線を基準に、6人のレーンと時間軸で進行・待機カードを確認する管制盤
- **C**: 担当者ごとに現在の抽出と待機を横に並べ、次に空く担当者を確認する比較案
- **D**: 紙のマスターシートを画面上に再現する案。6人を列、注文番号を行とした表に、右の注文カードを選んで枠をタップするか、列へドラッグして割り振ります（[cafeore-pos#699](https://github.com/cafeore-tkb/cafeore-pos/pull/699) のコンセプトを移植）
- 最上段のヘッダーからA/C/Dを切り替えます。
- 補助情報は右側パネルに表示し、管制盤全体を隠しません。
- iPad で画面全体が動かないよう、CaOS の 3 つの画面（`/master-sheet`・`/master-sheet/view`・`/master-sheet/libero`）を開いているあいだは、ページのスクロール・はね返り・ピンチとダブルタップの拡大を止めます（`caos.css` の `html:has(.caos-root)` で `overflow: hidden`・`overscroll-behavior: none`・`touch-action: pan-x pan-y`、盤面は `h-dvh` で見えている高さに収める。`hooks/useFixedViewport.ts` で viewport に `maximum-scale=1, user-scalable=no` を足し（入力欄を押したときの自動の拡大も止まる）、Safari の `gesturestart`・`gesturechange` を止める）。枠の中のスクロールとスクロールバー・カードのドラッグ・入力欄は今まで通りです。

### 管制盤A・C・Dの比較

3案とも同じ注文データ・業務ルール（オーダー番号順、指名、最大2杯、`次へ` で完了）を共有し、違うのは見せ方と割当の操作だけです。

| | A：タイムライン | C：ドリッパー行 | D：マスターシート |
|---|---|---|---|
| 担当者の並び | 6レーン（横軸＝時刻） | 6行（左半分） | 6列（表の列） |
| 待機列の見え方 | 時間軸上のカード位置で全件 | 現在＋待機を横並びで全件 | 注文番号の行に全件（全注文番号に行があり、列を上から読むと担当者の順番） |
| 時間の情報 | NOW線と時刻目盛り、開始・終了予定、未割当タブのNEXT担当者 | 現在の残り時間、未割当タブのNEXT担当者 | 列見出しの残り時間のみ |
| 列の状態 | ドリッパーの番号（数字だけの細い札）の色と札（空き・待機・抽出中・まもなく・継続中・要確認、待っている指名の杯数）。3案とも同じ `DripperIndicator`。押すと列の操作（交代・待機をまとめて移す） | 同じ | 同じ |
| ドリッパーのカードを押す | カードの上にその段階の操作のアイコン（未着手は ▶、着手後60秒未満は ✋、以降は 🚨・✓、終わりは 🚨。未着手は1〜6・✕、コメントがあれば💬）を出し、アイコンを押して決める。長押しで待機は詳細、抽出中・終わりは緊急のパネル | 同じ（終わったカードは出さない） | 同じ（終わったカードは出さない） |
| 完了済みの表示 | NOW線の左（過去2分半）に、点線の枠で薄く | 出さない | 表の枠には出さない（淹れ終わった行は灰色で残し、行は動かさず下へ積む） |
| 未割当の置き場所 | 下段の横帯（注文番号を左から横に並べ、同じ注文のカードは細幅・1 行表示で縦に並べる。「未割当」タイトル右のスクロールバーで全件を見る） | 右の注文の列（注文番号の行に未割当のカードだけ） | 右の注文カード（未割当のカードだけ） |
| 未提供のタブ | 下段の横帯を「未提供」にすると、まだ提供していない注文を左から横に | 右の注文の列を「未提供」にすると上から縦に | 右の注文内容を「未提供」にすると上から縦に |
| 未割当の単位 | 抽出カード | 抽出カード | 注文 |
| 割当操作 | タップで1〜6ボタン／選択後に空きスロットをタップ／なぞり／ドラッグ | タップで1〜6ボタン／なぞり／ドラッグ | カードを選んで表の「ここに配置」をタップ／列へドラッグ |
| 割当後の移動・戻し | レーン間ドラッグ、長押しで詳細のパネル | 長押しで詳細のパネル | 列間ドラッグ、右の注文内容へドラッグで戻す、長押しで詳細のパネル |
| 1杯カードの統合 | あり（未割当・待機・抽出中へタップ、待機・抽出中の真ん中へドラッグ） | あり（同じ） | あり（右の注文内容・表の待機・抽出中へタップ、表の待機・抽出中の真ん中へドラッグ。統合した2注文の行を、間の行ごと大きな枠で囲み、カードは注文ごとの段に分ける） |
| 主な実装 | `ControlViewA`（`DispatchBoard` + `UnassignedStrip`） | `ControlViewC`（右は `OrderQueuePanel`） | `ControlViewD` |

- **A：タイムライン**　時間の流れを最も正確に表す基準案です。待ち時間の偏りや「誰がいつ空くか」が位置で読めて、ドラッグで再配置できます。代わりに情報量が多く、横スクロールやカードの小ささで一覧性が落ちやすくなります。
- **C：ドリッパー行**　担当者を行にして、現在の抽出と待機列を横に並べる案です。未割当を右半分に全件並べます。待機列が長くなると行内の横スクロールになります。
- **D：マスターシート**　紙運用をそのまま置き換える案です。行＝注文番号（未割当や抽出のない番号も詰めずに1行ずつ）なので「どの注文を誰が淹れるか」と注文ごとの杯数が表で揃い、紙に慣れた人が移行しやすいです。淹れ終わっても行は動かず（終わったカードは表の枠から消え、行は灰色で残ります）、新しい注文は下へ積まれていきます。割当は2回のタップか列へのドラッグで済み、割当後もドラッグで列を移したり未割当に戻したりできます。統合した1杯同士は、2注文の行とその間の行をまとめて囲む大きな枠で表示し、縦に長いカードを注文ごとの段（注文番号と杯数）に分けて、それぞれの注文の行の高さに置きます（間の行に別のカードがあって囲めないときは、小さい注文の行の中で段を並べます）。注文が増えると表が縦に伸びてスクロールが要ります（開いたときは淹れ終わっていない最初の注文付近を表示）。

## cafeore-pos 連携

- 注文は常に cafeore-pos と同じDBから取り込みます（画面内でモック注文を作る機能はありません）。ヘッダーのDBアイコンの点が接続状態で、緑は接続済み、黄は接続中（最初の注文が届くまでを含む）・再接続中です。その下に重ねたプリンターのアイコンの点は、この端末のシールのプリンター（印刷の設定の `label_printer_ip`）の接続状態で、緑は接続完了、黄は接続中、赤は未接続です。未接続のときは、ヘッダーの下（「未送信」「未印刷」と同じ所）にレジと同じ「ラベルプリンター未接続」と、証明書を許可するページ（`https://<プリンターの IP>`）の案内を出します。
- 実データテスト中は cafeore-pos の注文を使わず、ブラウザの中の練習の盤面で動かします（下の「実データ・テストプレイ」）。テストの盤面のあいだ（テスト中も、終えて実績を見ているあいだも）は盤面の上に「テストの盤面です」の帯と「本番に戻る」を出し続け、ヘッダーの「テスト」も本番と違う色にします。「本番に戻る」、またはテストを終えたあとに実績のパネルを閉じると、テストの盤面を捨てて cafeore-pos の注文に戻ります。
- 盤面は注文のカップ（`order_cups`）の列で持ちます。CaOS が決めたこと（ドリッパーの番号 `dripper`・ドリッパーの中の順番 `dripper_position`・同じカードで淹れるカップの印 `drip_id`・抽出の開始 `brew_started_at` と終了 `brew_finished_at`）をカップに書き、注文の応答（`OrderResponse` の `cups`）に載ります。CaOS 以外の画面は読みません。
- カードの状態は時刻で決まります（終了あり＝終わり、開始あり＝抽出中、どちらも無くドリッパーあり＝待機、ドリッパーなし＝未割当）。カードが終わるのは CaOS の「次へ」（`brew_finished_at`。カードの ✓）だけで、提供の画面でカップを準備完了（提供可能）・提供済みにしても、抽出中・待機のカードはそのままです（提供済みのカップのあるカードには「提供済」（一部なら「提供済 1/2」）の札を付けます）。準備完了・提供済みのカップを盤面に出さないのは、まだドリッパーに置いていない未割当だけです。
- 終わったカードは、管制盤 A のタイムラインの NOW 線より左にだけ、点線の枠・地の色なしで薄く残します（抽出中・待機と見分けるため）。管制盤 C・D・閲覧の画面・リベロビューには出しません（その列は抽出中・待機だけ。未割当の置き場所には、もともと未割当のカードだけを置きます）。終わったカードから入れ直すときは、A のタイムラインのカードを押して 🚨（長押しでも同じパネル）か、ヘッダーの「緊急」で注文番号を入れます。
- 抽出の開始・終わりと、準備完了（提供可能）・提供は別々の時刻で持ち、どの画面がどれを書くかは次の表のとおりです。盤面（抽出の開始・終わり・待機）を書くのは CaOS（マスターシート）の操作だけで、提供の画面は準備完了・提供だけを書きます。CaOS の「次へ」は抽出の終わりだけを付け、提供可能にはしません（呼び出し画面で呼ぶのは、提供の画面で提供可能を押してから）。提供の画面で提供可能・提供を押しても、CaOS の「次へ」は進みません。

  | 時刻（列） | 意味 | 付ける | 外す |
  |---|---|---|---|
  | `brew_started_at`（カップ・入れ直し） | 抽出の開始 | CaOS：割当（空いていれば始める）・先頭へ（`PUT /api/caos/cups` の `start_brew`）、カードの ✓（終えて待機の先頭）・未着手のカードの ▶（`POST /api/caos/drippers/{dripper}/next`） | CaOS：抽出中のカードを動かす・未割当に戻す・✋（未着手に戻す） |
  | `brew_finished_at`（カップ・入れ直し） | 抽出の終わり | CaOS の「次へ」：カードの ✓（待機の先頭も始める） | （CaOS からは外さない） |
  | `ready_at`（カップ・注文） | 準備完了（提供可能。呼び出し画面で呼ぶ） | 提供の画面（`/serve`）のカップのボタン・呼び出しのベル（`PATCH /api/orders/{id}/cups/{cupId}/ready`・`PATCH /api/orders/{id}/ready`）。提供済みにしたとき、付いていなければいっしょに付く | 提供の画面の同じボタン・提供の取り消し |
  | `served_at`（カップ・注文） | 提供 | 提供の画面（`PATCH /api/orders/{id}/cups/{cupId}/served`・`PATCH /api/orders/{id}/served`） | 提供の画面・過去の注文の取り消し |

  注文の `ready_at`・`served_at` はカップから決まります（全部のカップに付いたら注文にも付く）。入れ直しは準備完了・提供を持ちません。
- 抽出の開始・終了の時刻は、操作を押した時刻でサーバーが付けます。画面は「次へ」（✓・▶）・割当・先頭へなどの書き込みに、押した時刻と送った時刻（どちらも iPad の時計のエポックのミリ秒。`press`）を付けて送ります。電波が切れていたあいだに押して後で届いた操作も、押した時刻になります。サーバーは次のように決めます（押した時刻を送らない古い画面からの書き込みは、今までどおりサーバーの今）。
  - 送った時刻がサーバーの今より 5 秒より後（iPad の時計が進んでいる）か、30 秒より前（遅れている。30 秒までは通信にかかった長さかもしれないのでずれとみない）なら、サーバーの今から「押してから送るまでの長さ」を引いた時刻にします。そうでなければ押した時刻のまま（同じ iPad で押した開始と終了の差が、通信にかかった長さでずれないように）
  - サーバーの今より後（未来）ならサーバーの今。今日（日本時間）より前でもサーバーの今（画面は前の日に押した操作を送りません）
  - 同じドリッパーで前の抽出を終えた時刻より前なら、その終えた時刻（ほかの iPad が先に進めた列に、前に押した操作が後から届いたとき）
- 列の先頭（抽出中）に入れて始めるときは、書き込みの after に時刻の代わりに「始める」の印（`start_brew`）を送ります。抽出中のカードも動かせ、先頭でない所・未割当に動かすと始めた時刻が消え、先頭に入れ直すと今から始め直します。終わったカードは動かせません（終えるのは「次へ」）。
- 画面は、POS の画面全体で共有している WebSocket（`/api/ws/orders`、root の `OrdersWSProvider`）の注文から、今日（日本時間。注文の作成日時で区切る）のカードを組み立てます（`@cafeore/common` の `buildCaosCards`）。未割当は、抽出が要り（商品の種類の「カップを作る」と「抽出が要る」が両方オン。`@cafeore/common` の `cupNeedsBrew`。API と同じ決まり）まだ準備完了でないカップを、注文ごと・商品ごと・指名の番号ごとに最大2杯で組み立てます。注文の編集・削除で消えたカップはカードから抜けます。CaOS 用に別の接続は張りません。
- カードの名前は商品の略称をそのまま出します。カードの豆は、カードの商品のアイテムの在庫（`GET /api/inventory` の kind が item のもののうち、抽出が要る（`cupNeedsBrew`）アイテムのもの。豆キューに出すのも同じ。`logic/beans.ts` の `dripItemStatuses`）を引き、在庫対象の名前をそのまま出します（豆はカードの札）。カードは未割当・待機・抽出中・終わりとも（A・C・D と右のパネルで同じ）、いちばん大きく左上に注文番号と、右上に杯数の札（何番が何杯か。提供を合わせるため、何を入れているかより何番を入れているかを先に読む）、次の行に商品を小さく出します（1 杯のカードは統合の判断に商品が要るので、2 行目でも読める大きさ。`OrderCard` の `SIZES` の `no`・`item`。幅の狭いカードでは緊急の札を先に縮めます。統合したカードは、管制盤 A・C では後ろにもう 1 枚重ねた枠で、D では重ねずに入っている注文ごとの段（注文番号・その注文のコメントの印・緊急の理由・杯数。段の間は点線）に分けて出します（`OrderCard` の `byOrder`。商品と合計の杯数はカードの 1 行目。表で元の注文の行をまとめて囲むときは、段を上と下の端に寄せ、元の注文の行の高さに来るようにします。間の行に別のカードがあって囲めないときは、小さい注文の行の中で段の分だけ高くなります）。分けた注文のカードの位置・合計杯数はカードに出しません。ほかの場所にも同じ注文があるかは、カードを押して注文を選んだとき（未割当のカード、ドリッパーのカードの長押しで開く待機の詳細・抽出中・終わりのカードの緊急の入力。閉じると選択を外します）に、どこにあっても同じ注文のカードに選択中の黄の輪が付くことで分かります）。統合したカードの長い番号「#120+#121」は、杯数の札と同じ大きさで字の間を詰め、それでも入らなければ省略して、杯数の札をカードの外へ押し出しません（D の統合したカードは 1 行目が商品で、番号は注文ごとの段に出します）。指名は「指名 2nd」（番号の無い自由記述だけの古い明細は「指名 名前」）、上級生のみのカードは「★上級生」の札を出します。
- 指名は、レジで選んだドリッパーの番号（注文の明細の `dripper`。1st〜6th は 1〜6）です。番号のあるカードはその番号のドリッパーにだけ置けます（1〜6 のボタン・ドラッグ・D の「ここに配置」。`@cafeore/common` の `caosDripperAllowed`・`assignWrites`、サーバーの `PUT /api/caos/cups` の両方で確かめます）。1 枚のカードに違う番号のカップは入れません（指名なしのカップは指名のカードに入れられ、カードはその番号のままです）。指名のカードの色は、POS の色の設定の画面「CaOS（指名）」から引きます（無ければ「マスター」の色）。地の色は商品の色だけに使い、指名は黒い点線の枠と札で出すので、指名の色が商品の色と近くても見分けられます。
- 操作（割当・ドリッパーの移動・先頭へ・途中への差し込み・未割当に戻す・統合）は、カップの書く前と書いたあとの値を `PUT /api/caos/cups` で送ります（`assignWrites`・`unassignWrites`・`mergeWrites`）。書いたカップの注文は、つないでいる画面に配られます。決まりに合わない操作（指名・2 杯まで・終わったカードなど）は、押したときに画面がサーバーと同じ決まりで確かめて止め、理由が POS の通知（sonner の toast）で出ます。
- 画面を先に動かします（楽観的な更新。`hooks/useCaosOutbox.ts`・`@cafeore/common` の `caos-outbox.ts`）。盤面を書き換える操作（割当・移動・先頭へ・未割当に戻す・統合・外す・まとめて移す・次へ（▶・✓）・未着手に戻す（✋）・緊急の取り消し・担当者の交代と入れ替え・上級生の印）は、押した瞬間に画面が変わり、書き込みは後ろで送ります。
  - 押した操作はまずこの端末の localStorage に 1 件ずつ残し（シールの未印刷と同じ置き方。`~/lib/device-store.ts`）、盤面はサーバーから届いた注文と担当者に、残っている操作を古い順に重ねて出します（重ねるのは実データテストと同じ、サーバーの決まりをブラウザで行う関数）。抽出の始めた・終えた時刻は仮に押した時刻で出し、サーバーの値が届いたら差し替わります。
  - 送るのは古い順に 1 つずつです（同じ端末のタブは 1 つだけが送ります。Web Locks で決め、閉じたらほかのタブが引き継ぎます）。送る直前に書き込みの書く前の値をサーバーの今の値に差し替え、カードの場所（ドリッパー・カード・抽出中か・終わりか）が押したときと同じなら送ります（順番の数・時刻はサーバーが決めるので比べません）。通ったら、その結果の注文がサーバーから届くまで（5 秒まで）は重ねたままにし、次を送りません（一瞬前に戻って見えないように）。注文は 1 つずつ届くので、注文をまたぐ書き込み（統合など）で一部の注文だけ届いたあいだは、届いた注文のぶんを除いて残りを重ねます（統合したカードが一瞬分かれて見えないように）。どの操作も押した時刻をいっしょに送ります（送り直しても押した時刻のまま）。「次へ」は、サーバーの始めた時刻が押したときに見ていたより後にずれていて（ほかの iPad が先に進めた列・iPad の時計が進んでいる）、押した時刻ではサーバーの 10 秒の決まりで断られるときだけ、捨てずに始めた時刻の 11 秒後（時計の差に 1 秒みる）に押したことにして、その時刻まで待って送ります。
  - 送れなかった（つながらない・返事が 10 秒来ない・5xx・ログインが切れた 401・403・時間切れ 408・混んでいる 429）ときは、1 秒から倍にして 15 秒までの間をあけて何度でも送り直し、そのあいだ後ろの操作は待ちます。共有の WebSocket がつながっていないあいだは送らず、つなぎ直したらサーバーから全部の注文と今日の担当者が届き直してから送ります（担当者は注文のあとに届くので、注文が届いてから 3 秒まで待ちます。今日の担当者がまだ無ければサーバーは送らないので、3 秒で待つのをやめます）。前の日に押して残っていた操作は、重ねも送りもせずに捨てて知らせます。再読み込み・タブを閉じても残り、次に開いたら送ります。返事が届かなかったものは、サーバーの盤面がもうそのとおりなら送らずに済ませます。
  - ほかの iPad が先に変えた（409）ときは、1 秒待ってサーバーの今の盤面で確かめ直し、カードの場所が同じ（番号がずれただけ）ならその値でもう一度送ります。もうそのとおりなら済みにします。場所が違えば、決まりに合わない（400 など）ときと同じく送り直さずに捨て、盤面はサーバーの今に戻り、「「割当 #038 → 2nd」は通らなかったので、盤面を戻しました」と理由を通知で出します（その操作はヘッダーの「直前の操作」からも消えます）。捨てた操作のあとに押した操作も、場所が合わなければ同じく捨てます。
  - 担当者の交代（見出しの「交代」・交代の画面で選ぶ・名前を入れる・空きにする）と入れ替えは、サーバーが書く前の値を確かめないので、送る直前にサーバーの今の担当者が押したときの担当者のままかを画面が確かめます。ほかの iPad が先に替えていれば送らずに捨て、盤面はサーバーの今に戻り、「1st の交代は、ほかの iPad が先に替えていたので取りやめました」と通知で出します（「直前の操作」からも消えます。続けて押した交代も同じく捨てます）。上級生の印を直すのは、名前が同じときだけ書くので確かめません。押したときの担当者を持たない前の版の交代（端末に残っていたもの）は、確かめずに送ります。
  - 押してから 2 秒を過ぎても送れていない操作があれば、ヘッダーの下に「未送信 N 件」と「もう一度送る」を出します（シールの「未印刷 N 件」と同じ所）。「未送信 N 件」を押すと、送れていない操作の一覧（押した時刻と操作の名前）を開き、1 件ずつ（×）か「全部消す」（2 回押し）で消せます。消した操作は送らず、盤面はサーバーの今に戻ります（ヘッダーの「直前の操作」からも消えます。`hooks/useCaosOutbox.ts` の `discard`・`components/UnsentOps.tsx`）。今送っていて返事を待っている操作（`createCaosOutbox` の `inFlight`）は、もうサーバーに届いているかもしれないので消せず、「送信中」と出します（「全部消す」もそれを除きます）。一覧は外を押すと閉じます。
  - 実データテスト中の操作は練習の盤面の中だけで、残しも送りもしません（テストの前に押した本番の操作は送ります）。閲覧だけの画面は送りません。
  - 緊急（入れ直し）を足すのは、入れ直しの id をサーバーが決めるので、今まで通り応答を待ちます。統合したカードから入れ直したときに 1 枚のカードにまとめる統合は、足した入れ直しが全部盤面に届いたとき（応答より先に届いていれば、応答のすぐあと）に、ほかの操作と同じく端末に残して後ろで送ります（入れ直しは注文ごとに届くので、先に届いた 1 杯のカードが一瞬（手元で 0.1 秒ほど）出てから 1 枚になります）。
- 順番（`dripper_position`）は整数で、サーバーが決めます。画面が送るのは「どのドリッパーの、どのカードの前に入れるか」（after の `insert_before`。`null` なら最後）だけです。サーバーは前に入るカードの番号に入れ、そのドリッパーでそれより後ろの終わっていないカップを +1 します。列から抜けたカードの番号は詰めません。
- 列の先頭は抽出中です。待機のカードの「先頭」ボタンで列の先頭へ（今から始まり、抽出中だったカードは始めた時刻を消して待機の先頭へ下がります）、「待機の先頭」ボタンで抽出中のすぐ後ろへ、番号のボタン（今のドリッパーでも）でその列の最後へ入ります（`@cafeore/common` の `CaosPlace` の `"front"`・`"queueFront"`・無し）。ドラッグでは、列の待機・抽出中のどのカードの上にも落とせ、カードの左の端（幅の 30%）はそのカードの前（`{ beforeKey }`）、右の端（30%）は後ろ（`{ afterKey }`）、真ん中（40%）は統合です（統合できる相手のときだけ。できない相手なら真ん中は近いほうの端。`logic/lanes` の `dropSideAt`・`hooks/useCardDrag` の `dropTargetAt`）。抽出中のカードの前は列の先頭（今から始まる）、後ろは待機の先頭です。落とす前に、指に付いた写しに「#003 の前へ（今から始める）」「#003 の後ろへ（待機の先頭）」「#003 と統合」の札を出し、指の下のカードの左右の縁に入れる所の線、統合なら統合の色の枠を出します（`OrderCard` の `DropMark`）。同じ列の中の入れ替えにも使え、管制盤 A・C・D で同じです（D の表の行は注文番号なので、列の中の順番は札「3rd 2番目」で見ます）。列のカードの無い所や 1〜6 のボタンに落とすとその列の最後へ入ります（札「→ 3」）。運んでいるカード自身の列の空いた所（A のタイムラインの右の空いた所・D の自分の列の枠など）に落としても、ほかの列と同じくその列の待機の最後へ入り、札は「3rd の最後へ」です（抽出中のカードなら、抜けたあと待機の先頭が今から始まります）。もう列の最後にある（動かしても同じ場所の）カードと、掴んだカード自身の上で離したときは何もせず、札も出しません。抽出中も待機も無い列に入れたら、そのまま始めます（抽出中が無く待機のある列の先頭は待機の先頭（未着手）で、▶ で始めます）。

- 「直前の操作」（ヘッダーの時刻の下）：この画面が最後にした操作（割当・移動・並べ替え・未割当に戻す・統合・外す・まとめて移す・次へ・始める・終える・未着手に戻す・緊急・緊急の取り消し・見出しの「交代」）の名前（「割当 #012 → 3rd」「次へ 2nd」「統合 #010 → #011」）を、次の操作をするまで出したままにします（`hooks/useLastAction.tsx`。送って断られた操作・未送信の一覧から消した操作は表示からも消えます。画面のメモリだけで、再読み込みで消えます。ほかの端末の操作は出しません）。戻すボタンはありません。間違えたら、出ている操作の逆の操作（別のドリッパーへ動かす・未割当に戻す・外す・緊急の取り消し・もう一度「交代」など）で直します。

- 開いたパネル（右のパネル：番号の検索・緊急・列の操作・割当・待機の詳細・補助のタブ）とダイアログ（交代・合言葉・テストプレイ）は、その外を押すと閉じます。外を押した 1 回は閉じるだけで、その下のカード・ボタン（ヘッダーのボタンも）は動きません（`hooks/useOutsidePress.ts` の `usePanelOutsidePress`。ダイアログは後ろの幕を押す）。上に重ねて出ているもの（確かめ・ダイアログ・通知）を押しても下のパネルは閉じません。パネルの中の入力欄（緊急の番号・理由、交代の名前、合言葉）で打っているあいだに外を押すと、入力を終える（キーボードを閉じる）だけで閉じず、入れたものは残ります（もう一度外を押すと閉じます）。
- 豆キューは在庫の画面（`/inventory`）と同じカード（`components/organisms/inventory/StockCard`）で、そこからの棚卸し・入荷は POS の在庫に記録します（実データテスト中は記録しません）。豆とカップは、CaOS の抽出ではなく提供の画面でカップを提供可能にしたとき（入れ直しは足したとき）に在庫から減ります（`GET /api/inventory`）。
- API の URL は POS と同じ `VITE_API_BASE_URL` です（未設定ならローカルの `http://localhost:8080`）。origin も POS と同じなので、API の `FRONTEND_ORIGINS` に足すものはありません。

## リベロビュー

- リベロが次にお湯を持っていく人を一目で決められるよう、1st〜6th の抽出中のカードの「入れ始めてからの時間」（抽出の開始 `brew_started_at` から。秒まで、毎秒進む）と、その長い順の順位（1・2・3…）を大きく出します。未割当は出しません。
- 各行には担当者の名前、何を何杯（商品の略称・杯数。地の色はカードと同じ色の設定）と注文番号、予定の抽出時間（`@cafeore/common` の `caosBrewSec`）に対する進み具合の帯を添えます。
- 進み具合を予定の抽出時間までの 4 段に分け、長いほど行の地・枠・順位・帯を濃い紫にします（`caos.css` の `--caos-elapsed-1`〜`4`）。予定の抽出時間を過ぎたら継続中の赤（`--caos-overtime`）にし、帯の横に過ぎた時間（「予定 5:00 ＋0:40」）を出します。決まりは `logic/libero.ts`（`liberoLanes`。経過と継続中はほかの画面の列の状態と同じ `laneStatus` から引きます）です。
- 抽出していない（待機だけ・空き）ドリッパーは薄い灰色で、順位も経過も出しません。
- 並びはヘッダーで切り替えます。「ドリッパー順」（1st〜6th のまま。ドリッパーの並びと同じ位置）と「経過の長い順」（いちばん上が順位 1。抽出していないドリッパーは下に番号の順）。経過の長い順は URL の `?order=elapsed` で、テレビなどで開いたままにできます。
- 閲覧の画面（`/master-sheet/view`）と同じく、いつも cafeore-pos の本番の盤面を映し（実データテストの盤面は映しません）、書き込みは送りません。iPad の横置き（1180×820）からテレビ（1920×1080）まで、文字は画面の高さに合わせて大きくします。
- お湯を渡したら抽出中の行を押すと灰色になります（もう一度押すと戻ります）。印はその端末だけ（`localStorage`。DB には書きません）で、そのドリッパーの抽出が替わったら（「次へ」で別のカードになったら）外れます（`hooks/useHandedWater.ts`）。
- 閲覧の 2 つの画面は、タイムラインに新しく入ったカード（割り当てた・抽出を始めた。`logic/timeline.ts` の `timelineArrivals`）を、通知音と、そのカード（閲覧の画面）・そのドリッパーの行（リベロビュー）の 4 秒の点滅（`caos.css` の `.caos-arrival`）で知らせます（`hooks/useViewBoard.ts`）。音はヘッダーで「音あり」「音なし」を切り替え、その端末に覚えます（はじめは音なし）。iPad は画面に触れるまで音を出せないので、出せない間（開き直したあとなど）はヘッダーに「音あり（触れると鳴る）」と出し、画面のどこかに触れたら鳴るようになります。閲覧の画面の未割当の横帯は「たたむ」でたためます（その端末に覚えます）。

## ドリッパーの担当者と交代

- 「今そのドリッパーに誰がいるか」（名前と、上級生か）はサーバーが日本時間の日付ごとに持ちます（API の表 `dripper_assignees`。`api/internal/handlers/caos_lanes.go`）。全部の iPad に共有の WebSocket の `{"type":"caos_lanes"}` で届き（今日の 6 つ全部）、列の見出しに「1 山田★」のように、数字だけの細い番号の札の横（D は下）に名前を大きく出します（上級生に ★。A・D・閲覧・リベロは入らない名前を 2 行まで折り返して、6 文字ほどは省かずに出す。担当者がいなければ番号だけ）。リベロビューは左の順位と見分けるよう、番号を枠で囲みます。閲覧だけの画面（`/master-sheet/view`・`/master-sheet/libero`）も名前を出しますが、交代はできません。
- 替えるのは人が CaOS で行います（`PUT /api/caos/lanes/{dripper}`）。押したらその場で替わります（抽出中かどうかは見ません。待機のカードも動きません）。
  - 列の見出し（管制盤 A・C・D）と列の操作のパネル（ドリッパーの番号を押して開く）の「交代」は、押したらすぐ次の人に替わります。次の人は sohosai-shift の予定（下の並び）で、今の担当者が出てくる一番うしろの予定より後ろの最初の人です（前の予定の人には戻りません。今の担当者が予定にいなければ先頭から）。次の人はボタンに「交代 → 鈴木」のように出します（A・D は幅が狭いので「交代 →」の下に名前）。次の人がいない（合言葉が無い・予定にその番目の人がいない・予定の人がもう入っている）ときは押せない見た目で「次の人なし」と出し、押すと理由を通知で出します。替えたらヘッダーの「直前の操作」に出します（間違えたら、もう一度替えて直します）。二度押しで 2 人ぶん進まないよう、替えてから 1 秒は同じドリッパーの「交代」を押しても替えません。
  - ヘッダーの「ドリッパー」の各ドリッパーの「交代」は交代の画面を開き、候補から選ぶ・名前を入れる・空き（担当者なし）にする・ほかのドリッパーの担当者と入れ替える（`POST /api/caos/lanes/swap`）ができます。
- 替えるたびに、サーバーが交代の記録（表 `dripper_assignee_changes`。時刻・ドリッパー・前の名前・後の名前・後の人が上級生か。入れ替えは 2 行）を足します。抽出の統計のためのもので、画面には出しません。
- 名前の候補は sohosai-shift の予定から出します。今の枠・次の枠（本番の 30 分ごとの枠）と、オペ練の今と次のラウンドの、そのドリッパーの番目の人です（この順。今そのドリッパーにいる人と空きは除きます。`laneCandidates`、すぐ替える次の人は `nextLaneCandidate`）。候補に無い人はヘッダーの「ドリッパー」の「交代」で自由に入れられます。予定の時刻どおりに自動で替えることはしません。
- 上級生かは、sohosai-shift の上級生の名簿（`seniors`）に名前があるかで、画面が判定してサーバーに持ちます。交代した時点で判定し、予定を読み直したとき（5 分ごと・手で読み直したとき・合言葉を入れたとき。読めたときだけ）にも、今の担当者の分を新しい名簿に合わせます（名前は変えず上級生かだけ。`POST /api/caos/lanes/seniors`。交代ではないので交代の記録は足しません。`hooks/useSeniorRefresh.ts`）。名簿に載った人は上級生にし、名簿から消えた人は外します（外す人のドリッパーに指名の無い上級生のみのカードがあっても外し、カードに警告の印が付きます）。読めない・合言葉が無い・名簿が空のときは何も変えません。閲覧だけの画面と実データテスト中は書きません（テストを終えてから合わせます）。判定するのは画面で、サーバーは名簿を持たず、送られた値（`senior`）をそのまま持ちます（`PUT /api/caos/cups` は上級生かを見ません）。
- 上級生のみのカードも、担当者が上級生でない（担当者なしも）ドリッパーに置けます（ドラッグ・1〜6・統合・まとめて移すのどれでも。画面もサーバーの `PUT /api/caos/cups` も止めません）。置いたら右上に「上級生のみの #012 を上級生でない 3rd 佐藤に置きました」と知らせ（`@cafeore/common` の `nonSeniorPlacement`・`nonSeniorMerge`。別のドリッパーへ置くときだけで、同じドリッパーの中の順番の入れ替えでは知らせません）、上級生でない担当者のドリッパーで待っている・抽出中のあいだは、カードの「★上級生」の札を赤い「⚠上級生」にします（`seniorOnlyOffSenior`。交代で上級生にすれば消えます）。実データテストには担当者がいないので出しません。担当者のいないドリッパーに置いたときは知らせず、警告の印だけです（その列に誰も立っていないので。担当者を空きに替えるときは、下のとおり知らせます。どちらもわざとです）。送った操作が断られて盤面が戻ったときは、その操作の知らせ（上級生のみ・時間のたった統合）も一緒に消します。まとめて移したときは「上級生のみのカード 2 枚を上級生でない 3rd 佐藤に移しました」と 1 つにまとめます。上級生でない人（担当者なしも）に替えるとき、そのドリッパーに指名の無い上級生のみのカード（抽出中・待機。警告の印と同じ数え方）があっても止めずに替え、POS の通知で「交代 1st → 佐藤：このドリッパーに指名の無い上級生のみのカードが1枚あります（佐藤さんは上級生ではありません）」と知らせます（見出しの「交代」ですぐ替えるときも同じ）。どのドリッパーにも上級生がいなければヘッダーに知らせます。
- 指名と上級生のみがぶつかるとき（上級生のみのカードの指名のドリッパーの担当者が上級生でない）は、指名を優先し、知らせも警告の印も出しません。指名のあるカード（指名のカップが 1 つでも入ったカード）は指名のドリッパーにしか置けません。統合は統合したあとのカードで見るので、指名の無い上級生のみのカードも、指名のカードに入れれば知らせません。
- 画面は `hooks/useCaosLanes.tsx`（担当者と交代の流れ。すぐ替えたのは `hooks/useLastAction.tsx` の「直前の操作」に覚える）・`hooks/useShiftFeed.ts`（予定の読み込み）・`hooks/useSeniorRefresh.ts`（読み直したら上級生かを合わせる）・`components/LaneParts.tsx`（見出しの名前と「交代」・ヘッダーの知らせ）・`components/LaneDialogs.tsx`（交代・合言葉）、決まりは `@cafeore/common` の `caosLanes.ts` と `caosShiftFeed.ts` です。

### sohosai-shift の合言葉の入れ方

1. sohosai-shift で CaOS へ配信し、合言葉を受け取ります。
2. 各 iPad の CaOS のヘッダーの鍵のボタン（またはヘッダーの「ドリッパー」の「交代」の中の「合言葉」）を押し、合言葉を入れて「保存」します。その端末にだけ覚えます（`localStorage`。ビルドには入れません）。
3. 予定は Firestore の REST（`https://firestore.googleapis.com/v1/projects/sohosai-shift/databases/(default)/documents/caosFeeds/{合言葉}`）で 5 分ごとに読み直します。
4. 合言葉が無い・読めない端末でも、ヘッダーの「ドリッパー」の「交代」で名前を入れれば交代できます（候補が出ず、見出しの「交代」が押せないのと、上級生と判定できないだけです）。

## 実データ・テストプレイ

- ヘッダーの「テスト」（実データテスト）から、過去の祭の実注文を使ったテストプレイを開始できます。
- データは開始の画面で手元の JSON ファイルを選んで読み込みます（ドラッグでも可）。読める形は [cafeore-tkb/sohosai-analysis](https://github.com/cafeore-tkb/sohosai-analysis) の `YYYY/data/day*.json`（`{ orders: [...] }`）と、cafeore-pos の `GET /api/orders` の応答を保存したものです。day1・day2・day12 のように複数選ぶと、重なる注文は 1 件にまとめます。
- 読み込みはこの端末のブラウザの中だけで、写すのは練習に使う項目だけです（`@cafeore/common` の `caosPracticeData.ts`）。担当者名・コメント・お預かりなどは読み込むときに落とします。サーバーには送らず、画面を開き直したら選び直しです。テストプレイ中は POS の注文の取り込みを止め、API にも書かないので、本番の盤面・注文・在庫には混ざりません。本番に戻ると練習の盤面（テストで作った緊急も）は消えます。
- 開始前に時間帯と30分／1時間を選択します。テストは 10x で始まり（1 時間分の注文が 6 分で流れる）、盤面の上の「テストの盤面です」の帯の `1x / 2x / 5x / 10x` に合わせて、時計・タイムライン・注文到着・抽出時間が一緒に進みます。一時停止・速さのボタンはこの帯（テストの盤面のあいだだけ出る）に置きます（本番の盤面は実時間なので。やめるのは「本番に戻る」）。
- 練習の盤面は、本番と同じ形の注文とカップ（ドリッパー・順番・カード・抽出の時刻の列）をブラウザの中だけで持ちます（`hooks/useTestPlay.ts`）。カードの組み立てと操作の書き込みは本番と同じ関数（`buildCaosCards`・`assignWrites` など。`useCaosSession` が本番と同じものを呼ぶ）で、書き込みを当てる（番号を決め、後ろをずらす）のと「次へ」は API と同じ決まりの `@cafeore/common` の `applyCaosPracticeWrites`・`advanceCaosPracticeDripper` で行います。緊急（入れ直し）も練習の盤面の中だけで足し・取り消します。時刻は練習の時計の今で、本番と同じく同じドリッパーで前の抽出を終えた時刻より前にはしません。サーバー・本番の盤面・注文・在庫・印刷には何も送りません。
- 実データの品物には、テストを始めるときに種類の設定（カップを作る・抽出が要る・上級生のみ）を付けます。注文したときの設定があればそれ、無ければ POS の今の商品の種類から名前で引きます（`logic/historical.ts` の `withPracticeItemTypes`）。どちらにも無い品物はカップにせず、実績の杯数にも数えません。カップを作る種類の品物を 1 杯ずつカップにし（POS が注文を保存したときと同じ）、抽出が要るか・上級生のみかは本番と同じく種類の項目で決めます。種類の ID（色の設定を引く）は POS の商品の種類から引きます（`toPracticeOrders`）。
- 指名は実データの指名を写し、練習の盤面でも本番と同じ札（「指名 2nd」の札と点線の枠）・ドリッパーの番号の「指名 N」・決まり（指名の番号のドリッパーにしか置けない・違う番号は 1 枚のカードにしない・指名なしの 1 杯は指名のカードに入れられ、そのカードは指名のドリッパーへ）で出ます。cafeore-pos の注文は明細の `dripper` をそのまま使います。2024・2025 年の Firestore 版の注文は品物の `assignee`（自由記述）で、「1st」「1st 名前」「1」のように番号があればその番号にし、名前だけのものは本番の番号の無い古い明細と同じく指名なし（札に「指名 名前」と出すだけ）にします。練習には担当者がいないので、上級生のみのカードの知らせと警告の印は出しません。
- 「終了・実績」を押すと、売上、商品構成、ピーク、提供時間、担当量、分割注文の仕上がりΔを表示します。提供時間は練習の結果（抽出の要るカップが全部抽出を終えた時刻。練習には提供の画面が無いので、提供可能の代わりに使います）です。
- 過去の注文データはリポジトリに入れません。

## 開発

POS の一部なので、コマンドも POS と同じです（`pnpm pos dev` で開き、`/master-sheet` に行く）。型チェックとビルドも `pnpm pos typecheck`・`pnpm pos build` に含まれます。

lint は POS と同じ決まりです（`biome.json` に CaOS だけの除外はありません）。スタイルは `caos.css` で `.caos-root` の中に閉じ、POS のほかの画面に漏らさないようにしています。

## コードの分け方

- `components/`：部品（表示だけ）。受け取った値を出し、押されたら受け取った関数を呼ぶ。カードは `OrderCard` 1 つで、管制盤 A・C・D と右のパネルで共通。見出し・列の番号と状態（`DripperIndicator`）・空きスロット・置いた場所の札は `BoardParts`、カードの上の操作のアイコンと印は `CardActions`、右のパネル（割当・詳細・補助のタブ）は `SidePanels` の `SidePanel`。
- `logic/`：盤面の決まり（純粋な関数）。カードと列の型は持たず、`@cafeore/common` の `buildCaosCards` で組み立てた `CaosCard` と `caosLane` の列（`lanes` の `Lane`）をそのまま使う。カードの名前・注文番号・色・分割の表示（`cards`）・列の時刻（`queue`）・D の表（`sheet`）・A の目盛りと置く時刻（`timeline`）・実績の集計（`analytics`）・実データテスト（練習の注文と実績。`historical`）・カードの豆（`beans`）・注文番号の検索（`search`）・注文のコメント（`comments`）。カードの組み立てと書き込みの決まりそのものは `@cafeore/common` の `caos-board.ts`・`caosPractice.ts`。実データの注文は `@cafeore/common` の `PracticeDataOrder`。
- `hooks/`：状態と副作用。本番の盤面（`useLiveBoard`。注文を読み、送れていない操作を重ねる）、送れていない操作を端末に残して送る（`useCaosOutbox`）、POS の在庫の読み込み（`useBeanInventory`）、実データテスト（`useTestPlay`。練習の盤面と時計。読み込んだ JSON は `usePracticeData`）、それらをまとめる `useCaosSession`、選んでいるもの（`useBoardSelection`。右のパネルは同じ位置に出るので、開いているもの 1 つ（`OpenPanel`）だけを持つ。D の `useSheetSelection`）、ドラッグと落とす先（`useCardDrag`。列のカードの前・後ろ・統合は `dropTargetAt`。カードはどの向きになぞってもすぐ掴み、動かさずに 0.6 秒押し続けたら長押し。ドラッグしないカードの長押しは `useCardHold`）、カードを並べた枠のスクロールバー（`useScrollBar`。部品は `components/ScrollArea`）、未割当のカードの操作（`useUnassignedPick`。A の横帯と C の注文の列で共通）、A の横スクロール（`useTimelineScroll`）、注文番号の検索（`useOrderSearch`）、コメントの知らせ（`useCommentNotices`）・予定を大きく過ぎた抽出の音（`useForgottenBrewAlert`）など。`App.tsx` はフックを呼んで部品に渡すだけ。
