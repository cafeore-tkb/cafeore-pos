# CaOS — Cafeore Operating System

コーヒー提供現場で、6人のドリッパー（抽出担当者）へ注文を割り当て、進行状況を一画面で把握するためのタッチ操作向けの画面です。iPadの横画面を想定し、管制盤を常に表示したまま操作できます。

これまでに決定した画面・操作・業務ルールの詳細は、[画面設計・操作要件](./DESIGN_REQUIREMENTS.md)を参照してください。

## 公開

POS の画面の1つとして `/master-sheet` で配信します（<https://cafeore-pos.cafeorepos.workers.dev/master-sheet>）。入口は `services/pos/app/routes/master-sheet.tsx` で、POS のヘッダーは付けません。旧リポジトリ `cafeore-tkb/CaOS` から公開していた [GitHub Pages の版](https://cafeore-tkb.github.io/digital-master-sheet-pages/) は、こちらに切り替えたら止めます。

## 画面

- **A**: NOW線を基準に、6人のレーンと時間軸で進行・待機カードを確認する管制盤
- **B**: 現在・次の抽出と未割当注文を、よりコンパクトに確認する比較案
- **C**: 担当者ごとのドリッパー（H1/H2・I1/I2）と残り時間を並べ、現在の抽出と次に空く担当者を確認する比較案
- **D**: 紙のマスターシートを画面上に再現する案。6人を列、注文番号を行とした表に、右の注文カードを選んで枠をタップするか、列へドラッグして割り振ります（[cafeore-pos#699](https://github.com/cafeore-tkb/cafeore-pos/pull/699) のコンセプトを移植）
- 最上段のヘッダーまたはサイドバーからA/B/C/Dを切り替えます。
- 補助情報は右側パネルに表示し、管制盤全体を隠しません。

### 管制盤A〜Dの比較

4案とも同じ注文データ・業務ルール（オーダー番号順、指名、最大2杯、`次へ` で完了、緊急の入れ直し）を共有し、違うのは見せ方と割当の操作だけです。

| | A：タイムライン | B：コンパクト | C：ドリッパー行 | D：マスターシート |
|---|---|---|---|---|
| 担当者の並び | 6レーン（横軸＝時刻） | 6列 | 6行（左半分） | 6列（表の列） |
| 待機列の見え方 | 時間軸上のカード位置で全件 | 現在＋次の1件のみ | 現在＋待機を横並びで全件 | 注文番号の行に全件（全注文番号に行があり、列を上から読むと担当者の順番） |
| 時間の情報 | NOW線と時刻目盛り、開始・終了予定、次に空く上位3人 | 現在の残り時間、次に空く上位3人 | 現在の残り時間、次に空く上位3人 | 列見出しの残り時間のみ |
| 完了済みの表示 | NOW線の左（過去90秒）に薄く | なし | なし | すべて元の行に薄く残す（行は動かさず下へ積む） |
| 未割当の置き場所 | 下段の横帯（先頭12件） | 下段のグリッド（10注文） | 右半分の縦リスト（全件） | 右の注文カード（全件） |
| 未割当の単位 | 抽出カード | 注文（分割カードをまとめる） | 抽出カード | 注文（割当済み分も薄く表示） |
| 割当操作 | タップで1〜6ボタン／なぞり／ドラッグ | タップで1〜6ボタン | タップで1〜6ボタン／なぞり／ドラッグ | カードを選んで表の「ここに配置」をタップ／列へドラッグ |
| 割当後の移動・戻し | レーン間ドラッグ、タップで1〜6／×で戻す | 詳細モーダル | 詳細モーダル | 列間ドラッグ、右の注文内容へドラッグで戻す、詳細モーダル |
| 1杯カードの統合 | あり | なし | なし | あり（統合した2注文の行を、間の行ごと大きな枠で囲む） |
| 主な実装 | `DispatchBoard` + `UnassignedOrdersPanel` | `ControlViewB` | `ControlViewC` + `DripperOrderCard` | `ControlViewD` |

- **A：タイムライン**　時間の流れを最も正確に表す基準案です。待ち時間の偏りや「誰がいつ空くか」が位置で読めて、ドラッグで再配置できます。代わりに情報量が多く、横スクロールやカードの小ささで一覧性が落ちやすくなります。
- **B：コンパクト**　「今何を淹れているか・次は何か」に絞った案です。1人あたりの表示が大きく遠目でも読みやすい反面、3件目以降の待機が見えず、ドラッグにも対応していません。注文単位でまとめるので、分割注文の行き先を追いやすいです。
- **C：ドリッパー行**　担当者を行にして、現在の抽出と待機列を横に並べる案です。器具ラベル（H1/H2・I1/I2）と上級生の印を担当者ごとに表示し、未割当を右半分に全件並べます。待機列が長くなると行内の横スクロールになります。
- **D：マスターシート**　紙運用をそのまま置き換える案です。行＝注文番号（未割当や抽出のない番号も詰めずに1行ずつ）なので「どの注文を誰が淹れるか」と注文ごとの杯数が表で揃い、紙に慣れた人が移行しやすいです。淹れ終わっても行は動かず、新しい注文は下へ積まれていきます。割当は2回のタップか列へのドラッグで済み、割当後もドラッグで列を移したり未割当に戻したりできます。統合した1杯同士は、2注文の行とその間の行をまとめて囲む大きな枠で表示します。注文が増えると表が縦に伸びてスクロールが要ります（開いたときは淹れ終わっていない最初の注文付近を表示）。

## 主な挙動

- 初期状態は全ドリッパーが空で、cafeore-pos で受けた注文が届いた順に未割当へ追加されます。CaOS の中で注文を作ることはしません。
- 予定時刻は、全ドリッパー同じ抽出時間（1杯 135 秒・2杯 195 秒）で計算します（ドリッパーごとの補正はしません）。
  抽出時間・入れ替えの時間と予定時刻の決め方、その表示の文字は `modules/common/src/lib/caosTiming.ts` の 1 か所にまとめています。
- 「当日」の区切りはサーバーの営業日と同じ日本時間の 0 時です（`modules/common/src/lib/jstDay.ts` の `startOfJstDay`）。端末の時刻帯によらず同じ盤面・同じ時刻で出ます。
- 列は「1st」〜「6th」と番号で呼び、担当者がいれば名前を添えます（例「1st 山田」、上級生には限定の印）。担当者は盤面の一部として API の DB にあり、全部の iPad でそろいます。下の「列の担当者（交代）」を参照してください。
- 未割当注文と各ドリッパーの待機列は、指名注文を含めて原則オーダー番号順です。
- 指名注文は指定されたドリッパーにのみ割り当てられます。
- 1回の抽出は最大2杯です。3杯以上の注文は2杯以下のカードへ自動分割します。
- 同じメニューの1杯カード同士だけ、利用者の判断で2杯の同時抽出へ統合できます。
- `次へ` を押すまで現在の抽出は継続中です。押した時点を基準に、後続カードすべての開始位置を再計算します。
- 抽出前のカードは、別のドリッパーへの移動または未割当に戻す操作だけができます。
- 限定のカード（商品の種類が limited。画面では豆のコード `SP`）は、上級生の列にしか割り当て・移動・入れ直しできません（`utils/lanes.ts` の `isLimitedCard`。あとで商品の種類の `senior_only` に置き換えます）。どの列にも上級生がいなければ、ヘッダーに知らせます。
- 通常のホットは無色、氷・牛乳・指名・`★SP` は識別色で表示します。
- `1/1・計○杯` は省略し、分割された注文だけ `1/3・計4杯` のように全体量を表示します。
- 抽出中・完了済みカードから緊急の入れ直しを開始でき、中断／継続、杯数、担当者、差し込み位置を利用者が選べます。
- アイスミルクは売上分析には残しつつ、ドリップ管制の未割当・タイムラインから除外します。

## cafeore-pos 連携

盤面（抽出カード・割当・抽出の状態）は cafeore-pos の API と DB にあり、複数の iPad で同じ盤面を共有します（API 側の作りは cafeore-pos の README の「CaOS（ドリップ管制）の盤面」）。

- **受け取る：** POS の画面全体で共有している WebSocket（`/api/ws/orders`、root の `OrdersWSProvider`）から、注文と今日の抽出カード・列の担当者（`{"type":"drips"}` の `drips`・`lanes`）を受け取ります。CaOS 用に別の接続は張りません。カードは変わるたびに今日の分が全部届きます。ヘッダーの DB アイコンの点が接続状態で、緑は接続済み、黄は接続中・再接続中です。
- **表示：** カードは注文と商品の参照しか持たないので、注文番号や商品名は受け取った注文から引きます。待機カードの予定時刻は、抽出中のカードの開始時刻から画面で計算します（`live/drips.ts`）。
- **操作：** 割当・戻す・次へ・統合・入れ直し・列の担当者の交代と入れ替えは、`modules/common` の `postCaosOp`（`POST /api/caos/ops`）で送ります。POS のほかの API と同じ口なので、認証が入るときも1か所で足せます。結果のカードは WebSocket で全部の画面に届きます。ルールに合わない操作は、理由を画面の下に出します。
- **準備完了：** 「次へ」で注文のカードが全部終わると、API が同じトランザクションで POS の注文を準備完了にします（画面からは何もしない）。
- **1つ戻す：** 直前の操作の ID を送ると、API が残した操作の記録で、カードも準備完了も列の担当者もそろえて戻します。ほかの端末が後から触っていたら、何も変えずに断ります。
- **カードの作成：** POS で注文が入る・変わる・消える・準備完了になると、API が同じトランザクションでカードをそろえます。
- **実データテスト：** テスト中は本番の盤面の代わりに、API の練習用の盤面（`POST /api/caos/practice`。本番と同じルールで、本番とは別の盤面）を出します。終了後の実績表示中もそのままで、リセットすると練習用の盤面を消して本番の盤面に戻ります（下の「実データ・テストプレイ」）。
- **豆：** カードの豆は、POS の在庫の設定の「商品ごとの使用量」（`GET /api/inventory/usages`）で、カードの商品が使う豆の在庫対象から引き、在庫対象の名前をそのまま出します（名前で豆を決めません）。氷・牛・限定の区分（限定は限定を淹れられるドリッパーにだけ回す）は商品の種類（item_type）で決めます。アイスミルクとグッズはカードになりません（API が除きます）。
- **豆の在庫：** 豆キューは POS の在庫（`GET /api/inventory`）の豆を表示するだけです。CaOS は在庫を持たず、「次へ」でも減らしません（消費は POS が注文から数えます）。棚卸し・入荷は POS の在庫の画面（`/inventory`）で記録します。
- **指名：** レジで選んだドリッパーの番号（注文の明細の `dripper`。1st〜6th は 1〜6）で決めます。サーバーは同じ商品でも指名の番号ごとにカードを分け（カードの `lines[].dripper`）、番号の付いたカードはその番号の列にだけ割り当てられます（名前の照合はしません）。番号の無い自由記述だけの古い明細は指名なしとして扱います。カードの指名の表示は、POS のマスターの画面と同じ `assignmentDisplay`（`modules/common/src/models/dripper.ts`）で、番号は「指名:2nd」、番号の無い古い明細は自由記述をそのまま出します（列には固定しません）。限定のカードに上級生でない列の番号が指名されているときは、ほかの限定のカードと同じく上級生の列にしか割り当てられないので、その列の担当者を上級生に替える（交代・入れ替え）まで割り当てられません。
- **API の URL：** POS と同じ `VITE_API_BASE_URL` です（未設定ならローカルの `http://localhost:8080`）。origin も POS と同じなので、API の `FRONTEND_ORIGINS` に足すものはありません。本番 API につないで操作すると、本番の盤面と注文の準備完了が変わります。

## 列の担当者（交代）

- 担当者は時刻どおりには替えません（本番もオペ練も、予定どおりに替わるとは限らないため）。替わったら人が CaOS で押します。
  - **交代：** 管制盤 A の各列の左の「1st 交代」、またはドリッパーのタブの各列の「交代」。sohosai-shift の予定（今の時刻の枠・次の枠・オペ練の今と次のラウンド）の、その番目の人が候補の上に出ます。候補に無い人は名前を入れられ、「空きにする」で担当者なしにもできます。押したらその場で替えます（抽出中かどうかは見ません）。
  - **入れ替え：** ドリッパーのタブで、列の「入れ替え」を押してから、相手の列の「ここと入れ替え」を押します。
  - どちらも API の盤面に保存され、ほかの iPad にすぐ出ます。「1つ戻す」で戻せます。閲覧のみの画面（`/master-sheet/view`）は表示だけです。実データテスト中は練習用の盤面の列を替えます（本番の列には響きません。練習は本番の列の今の担当者から始めます）。
- **上級生（限定を淹れられる人）：** sohosai-shift の名簿の `seniors` に名前があれば上級生です。交代したときの判定を API に一緒に持つので、合言葉の無い iPad でも同じ表示になります（あとで名簿が変わっても、替えるまではそのまま）。
- **限定の確認：** 上級生でない人に替える列に限定のカードが待っているときだけ、「この列に限定のカードが2枚あります（佐藤さんは上級生ではありません）」と出します。ボタンは［まだ変えない］［変える］だけで、［変える］ならそのまま交代し、限定のカードも列に残ります（未割当への自動の戻しはしません）。
- **sohosai-shift の合言葉：** ヘッダーの歯車（設定）で入れます。合言葉は sohosai-shift の管理者が「配信」を押したときに出る英数字（32〜64 文字）で、ビルドには入れず、その iPad にだけ覚えさせます（localStorage）。設定には読めたか・部屋・最終の配信時刻が出ます。予定は 5 分ごとと、設定で保存・「読み直す」を押したときに読み直します（`hooks/useShiftFeed.ts`。読むのは `https://firestore.googleapis.com/v1/projects/sohosai-shift/databases/(default)/documents/caosFeeds/{合言葉}`、中身の読み方と候補の決め方は `modules/common/src/lib/caosShiftFeed.ts`）。合言葉が無い・読めないときは、名前の候補と上級生の判定が無いだけで、名前を入れての交代はできます（上級生でない人として扱います）。

## 実データ・テストプレイ

- ヘッダーの「実データテスト」から、過去の祭（2024・2025年…）の実注文を流して、1人で割り振りを練習できます。開始前にデータ（手元の JSON を読み込む）・30分／1時間・時間帯（日本時間の 0 分・30 分の区切り）を選びます。
- **盤面とルール：** 練習用の盤面は API にあり（`api/internal/caos/practice.go`）、本番の盤面と同じルール（分け方・割当・次へ・統合・入れ直し・列の担当者・1つ戻す）で動きます。画面の中でルールは作り直しません。本番の盤面・注文・在庫・統計には混ざらず、本番の WebSocket にも流れません（練習している画面が、応答の盤面をそのまま使います）。練習はタブごとに 1 つで、別のタブで開いた CaOS や `/master-sheet/view` は本番の盤面のままです。
- **時計と倍速：** 練習の時計は画面が持ちます。ヘッダーの `1x / 2x / 5x / 10x` で刻みの間隔が変わり（1 回の刻みで練習の時刻を 1 秒進める）、一時停止も画面だけで決まります。時計が次の注文の時刻（API が返す `next_arrival_at`）を過ぎたら API に「進める」を送り、それまでの注文がカードになります。操作にも練習の時刻を付けて送るので、カードの開始・終了・準備完了の時刻は練習の時刻です。予定時刻の計算は本番と同じ `planLane`（日本時間の 0:00 起点の秒）です。
- **終わりと片付け：** 時間帯の終わりで時計が止まります（残ったカードは「次へ」で終えられます）。「終了・実績」で実績を出し、リセットで練習用の盤面を消します。タブを開き直すと続きから（`sessionStorage` に練習の ID）。放置された練習の盤面は、最後に触ってから 12 時間たつと、次に誰かが練習を始めたときに API が消します（200 を超えたら古いものから）。
- **実績：** 「終了・実績」で、売上、商品構成、ピーク、注文→完成（練習の中で準備完了になった時刻まで）、担当量、分割注文の仕上がりΔを表示します。
- **データ：** このリポジトリにも配信にも入れません。実データテストを始める画面で、手元の JSON ファイルを選ぶ（ドラッグでもよい）と、その端末のブラウザの中で読みます。読めるのは private の [cafeore-tkb/sohosai-analysis](https://github.com/cafeore-tkb/sohosai-analysis) の `YYYY/data/day*.json`（Firestore 版の POS の注文。2024・2025 年）と、cafeore-pos の `GET /api/orders` の応答をそのまま保存したものです。day1・day2・day12 のように複数のファイルを一度に選ぶと、重なる注文は 1 件にまとめます（選び直すと入れ替わります）。
  - 読むときに、許可した項目（注文番号・時刻・金額・品物の ID・名前・値段・種類）だけを写し、担当者名・指名・コメント・お預かりなどは落とします（`modules/common/src/lib/caosPracticeData.ts`。テストは同じ場所の `caosPracticeData.test.ts`）。
  - 落とした後のデータだけを、その端末の IndexedDB（`caos-practice-data`）に覚えておき、開き直しても選び直さなくてよいようにします。「読み込んだデータを消す」で消せます。IndexedDB が使えない端末では覚えないだけで、練習はできます（`practice/loaded.ts`）。
  - サーバーに送るのは、今までどおり練習用の盤面を作るときの練習の注文（選んだ時間帯の注文番号・時刻・金額・品物）だけです。

## 置き場所

2026-10 に `cafeore-tkb/CaOS` から cafeore-pos のモノリポへ移し、POS の中（`services/pos/app/caos`）に置きました（履歴は持ってきていません）。実績データ（過去の祭の注文）はこのリポジトリには置かず、使う人が画面で sohosai-analysis の JSON を読み込みます（上の「実データ・テストプレイ」）。

## タッチ操作

- 未割当カードをタップすると、カードを隠さず上下に1〜6の割当ボタンが開きます。
- 指を離さず割当先へなぞる操作と、レーンへのドラッグ操作に対応しています。
- 枠外をタップすると選択状態を解除します。
- タイムライン上の未開始カードも、同じ操作感で割当先を変更できます。
- Dでは右の注文カードを担当者の列へドラッグすると、その担当者に割り当てます。表の未開始カードは別の列へドラッグして移すか、右の注文内容へドラッグして未割当に戻せます。縦の動きはスクロールに使うため、横へ引き出すと掴めます（右で選択中のカードはどの方向にもドラッグできます）。
- Dで1杯カードを選ぶと、統合できる同じメニューの1杯カードに「統合する」が出ます。統合後のカードは前の注文番号の欄に移るため、自動で選択してその位置までスクロールします。

## 開発

POS の一部なので、コマンドも POS と同じです（`pnpm pos dev` で開き、`/master-sheet` に行く）。型チェックとビルドも `pnpm pos typecheck`・`pnpm pos build` に含まれます。

CaOS の元の lint の方針（タッチ操作向けに切っていた a11y のルールなど）は、`biome.json` の `overrides` で `services/pos/app/caos` にだけかけています。スタイルは `caos.css` で `.caos-root` の中に閉じ、POS のほかの画面に漏らさないようにしています。
