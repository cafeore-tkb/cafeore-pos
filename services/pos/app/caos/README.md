# CaOS — Cafeore Operating System

コーヒー提供現場で、6人のドリッパー（抽出担当者）へ注文を割り当て、進行状況を一画面で把握するためのタッチ操作向けの画面です。iPadの横画面を想定し、管制盤を常に表示したまま操作できます。

これまでに決定した画面・操作・業務ルールの詳細は、[画面設計・操作要件](./DESIGN_REQUIREMENTS.md)を参照してください。

## 公開

POS の画面の1つとして `/master-sheet` で配信します（<https://cafeore-pos.cafeorepos.workers.dev/master-sheet>）。入口は `services/pos/app/routes/master-sheet.tsx` で、POS のヘッダーは付けません。盤面を閲覧だけで映す画面は `/master-sheet/view`（`routes/master-sheet_.view.tsx` → `caos/ReadOnlyBoard.tsx`）で、管制盤 A のタイムラインに注文と抽出がリアルタイムに流れます。操作のボタン（次へ・空きスロット）は出さず、盤面への操作も送りません。旧リポジトリ `cafeore-tkb/CaOS` から公開していた [GitHub Pages の版](https://cafeore-tkb.github.io/digital-master-sheet-pages/) は、こちらに切り替えたら止めます。

## 画面

- **A**: NOW線を基準に、6人のレーンと時間軸で進行・待機カードを確認する管制盤
- **B**: 現在・次の抽出と未割当注文を、よりコンパクトに確認する比較案
- **C**: 担当者ごとのドリッパー（H1/H2・I1/I2）と残り時間を並べ、現在の抽出と次に空く担当者を確認する比較案
- **D**: 紙のマスターシートを画面上に再現する案。6人を列、注文番号を行とした表に、右の注文カードを選んで枠をタップするか、列へドラッグして割り振ります（[cafeore-pos#699](https://github.com/cafeore-tkb/cafeore-pos/pull/699) のコンセプトを移植）
- 最上段のヘッダーまたはサイドバーからA/B/C/Dを切り替えます。
- 補助情報は右側パネルに表示し、管制盤全体を隠しません。

### 管制盤A〜Dの比較

4案とも同じ注文データ・業務ルール（オーダー番号順、指名、最大2杯、`次へ` で完了）を共有し、違うのは見せ方と割当の操作だけです。

| | A：タイムライン | B：コンパクト | C：ドリッパー行 | D：マスターシート |
|---|---|---|---|---|
| 担当者の並び | 6レーン（横軸＝時刻） | 6列 | 6行（左半分） | 6列（表の列） |
| 待機列の見え方 | 時間軸上のカード位置で全件 | 現在＋次の1件のみ | 現在＋待機を横並びで全件 | 注文番号の行に全件（全注文番号に行があり、列を上から読むと担当者の順番） |
| 時間の情報 | NOW線と時刻目盛り、開始・終了予定、次に空く上位3人 | 現在の残り時間、次に空く上位3人 | 現在の残り時間、次に空く上位3人 | 列見出しの残り時間のみ |
| 完了済みの表示 | NOW線の左（過去90秒）に薄く | なし | なし | すべて元の行に薄く残す（行は動かさず下へ積む） |
| 未割当の置き場所 | 下段の横帯（先頭12件） | 下段のグリッド（10注文） | 右半分の縦リスト（全件） | 右の注文カード（全件） |
| 未割当の単位 | 抽出カード | 注文（分割カードをまとめる） | 抽出カード | 注文（割当済み分も薄く表示） |
| 割当操作 | タップで1〜6ボタン／なぞり／ドラッグ | タップで1〜6ボタン | タップで1〜6ボタン／なぞり／ドラッグ | カードを選んで表の「ここに配置」をタップ／列へドラッグ |
| 割当後の移動・戻し | レーン間ドラッグ、タップで1〜6／×で戻す | 詳細モーダル | 詳細モーダル | 列間ドラッグ、右の注文内容へドラッグで戻す、詳細モーダル |
| 1杯カードの統合 | あり | なし | なし | あり（統合した2注文の行を、間の行ごと大きな枠で囲む） |
| 主な実装 | `DispatchBoard` + `UnassignedOrdersPanel` | `ControlViewB` | `ControlViewC` + `DripperOrderCard` | `ControlViewD` |

- **A：タイムライン**　時間の流れを最も正確に表す基準案です。待ち時間の偏りや「誰がいつ空くか」が位置で読めて、ドラッグで再配置できます。代わりに情報量が多く、横スクロールやカードの小ささで一覧性が落ちやすくなります。
- **B：コンパクト**　「今何を淹れているか・次は何か」に絞った案です。1人あたりの表示が大きく遠目でも読みやすい反面、3件目以降の待機が見えず、ドラッグにも対応していません。注文単位でまとめるので、分割注文の行き先を追いやすいです。
- **C：ドリッパー行**　担当者を行にして、現在の抽出と待機列を横に並べる案です。器具ラベル（H1/H2・I1/I2）を担当者ごとに表示し、未割当を右半分に全件並べます。待機列が長くなると行内の横スクロールになります。
- **D：マスターシート**　紙運用をそのまま置き換える案です。行＝注文番号（未割当や抽出のない番号も詰めずに1行ずつ）なので「どの注文を誰が淹れるか」と注文ごとの杯数が表で揃い、紙に慣れた人が移行しやすいです。淹れ終わっても行は動かず、新しい注文は下へ積まれていきます。割当は2回のタップか列へのドラッグで済み、割当後もドラッグで列を移したり未割当に戻したりできます。統合した1杯同士は、2注文の行とその間の行をまとめて囲む大きな枠で表示します。注文が増えると表が縦に伸びてスクロールが要ります（開いたときは淹れ終わっていない最初の注文付近を表示）。

## 主な挙動

- 初期状態は全ドリッパーが空で、cafeore-pos で受けた注文が届いた順に未割当へ追加されます。
- CaOS は独自にデータを作りません。データは POS の API と sohosai-shift から取ります（モックの注文、手で注文を足す画面、AI 学習・補正係数、端末だけの豆の在庫、仮の名簿と自動交代はありません）。
- 予定時刻は、全ドリッパー同じ抽出時間（1杯 135 秒・2杯 195 秒）で計算します（ドリッパーごとの補正はしません）。
  抽出時間・入れ替えの時間と予定時刻の決め方、その表示の文字は `modules/common/src/lib/caosTiming.ts` の 1 か所にまとめています。
- 「当日」の区切りはサーバーの今日と同じ日本時間の 0 時です（`modules/common/src/lib/jstDay.ts` の `startOfJstDay`）。端末の時刻帯によらず同じ盤面・同じ時刻で出ます。
- 列は `1st`〜`6th` の番号と担当者の名前で「1st 山田」のように出し、上級生（限定を淹れられる人）には ★ を付けます。担当者がいなければ番号だけです（下の「ドリッパーの担当者と交代」）。限定かは商品の種類の「限定」（`senior_only`）をそのまま使い、カードにその種類の表示名を「（）」で付けて出します。限定のカードは担当者が上級生のドリッパーにしか置けません。
- 豆キューは、POS の在庫（`/inventory`）の豆をそのまま出します（下の「豆の在庫」）。
- 未割当注文と各ドリッパーの待機列は、指名注文を含めて原則オーダー番号順です。
- 指名注文は指定されたドリッパーにのみ割り当てられます。
- 1回の抽出は最大2杯です。3杯以上の注文は2杯以下のカードへ自動分割します。
- 同じメニューの1杯カード同士だけ、利用者の判断で2杯の同時抽出へ統合できます。
- `次へ` を押すまで現在の抽出は継続中です。押した時点を基準に、後続カードすべての開始位置を再計算します。
- 抽出前のカードは、別のドリッパーへの移動・同じドリッパーの先頭へ・未割当に戻す操作だけができます（1〜6 のボタンのうち、今のドリッパーのボタンが「先頭」）。
- カードの色は POS の色の設定（マスターの画面）だけで付けます。設定の無い商品は白です（指名・選択中・終わりのカードは CaOS の色）。
- `1/1・計○杯` は省略し、分割された注文だけ `1/3・計4杯` のように全体量を表示します。
- 抽出の要らない品物（商品の種類の `needs_brew` が false）は売上分析には残しつつ、ドリップ管制の未割当・タイムラインから除外します。
- 抽出中・終わったカードから緊急の入れ直しを始められます（下の「緊急（入れ直し）と緊急のシール」）。入れ直しのカードは未割当のいちばん上に赤で出ます。

## cafeore-pos 連携

- 注文は常に cafeore-pos と同じDBから取り込みます（画面内でモック注文を作る機能はありません）。ヘッダーのDBアイコンの点が接続状態で、緑は接続済み、黄は接続中・再接続中です。
- 実データテスト中は cafeore-pos の注文を使わず、ブラウザの中の練習の盤面だけを動かします（下の「実データ・テストプレイ」）。終了後の実績表示中もそのままで、リセットすると cafeore-pos の注文に戻ります。
- 盤面は注文のカップ（`order_cups`）の列で持ちます。カードの表はありません。CaOS が決めたこと（ドリッパーの番号 `dripper`・ドリッパーの中の順番 `dripper_position`・同じカードで淹れるカップの印 `drip_id`・抽出の開始 `brew_started_at` と終了 `brew_finished_at`）をカップに書き、注文の応答（`OrderResponse` の `cups`）に載ります。CaOS 以外の画面は読みません。
- カードの状態は時刻で決まります（終了あり＝終わり、開始あり＝抽出中、どちらも無くドリッパーあり＝待機、ドリッパーなし＝未割当）。マスター（`/master`）でカップを全部準備完了にしたカードも終わりです。
- 抽出の開始・終了の時刻はサーバーの時刻で、サーバーが付けます（iPad の時計は使いません）。空いているドリッパーに置いてそのまま始めるときは、書き込みの after に時刻の代わりに「始める」の印（`start_brew`）を送ります。抽出中・終わりのカードは `PUT /api/caos/cups` では動かせません（終えるのは「次へ」）。抽出中のカードの残り時間は、この開始の時刻から数えます。
- 画面は、POS の画面全体で共有している WebSocket（`/api/ws/orders`、root の `OrdersWSProvider`）の注文から、今日（日本時間。注文の作成日時で区切る）のカードを組み立てます（`@cafeore/common` の `buildCaosCards`）。未割当は、抽出が要り（商品の種類の `needs_brew`）まだ準備完了でないカップを、注文ごと・商品ごと・指名ごとに最大2杯で組み立てます。注文の編集・削除で消えたカップはカードから抜けます。CaOS 用に別の接続は張りません。閲覧だけの画面（`/master-sheet/view`）も同じ組み立て（`buildCaosCards` と `live/board.ts` の `cardsToBoard`）を使います。
- 操作（割当・ドリッパーの移動・先頭へ・未割当に戻す・統合）は、カップの書く前と書いたあとの値を `PUT /api/caos/cups` で送ります（`assignWrites`・`unassignWrites`・`mergeWrites`）。書いたカップの注文は全部の画面に配られます（ほかのインスタンスへは `orders_changed`）。ほかの iPad が先に書いていた（409）・決まりに合わない（422）ときは何も変わらず、理由が画面の下に出ます。
- `次へ` は `POST /api/caos/drippers/{dripper}/next` です。抽出中のカードを終え、そのカードのカップだけを準備完了にし（POS のカップの準備完了と同じ。注文の準備完了はカップから決まります）、待機の先頭を始めます。
- 「1つ戻す」はありません（あとで、各画面が最後の操作を条件付きで書き戻す形で足します）。
- カードの豆は、POS の在庫の設定の「商品ごとの使用量」（`GET /api/inventory/usages`）で、カードの商品が使う豆の在庫対象から引き、在庫対象の名前をそのまま出します（名前で豆を決めません）。カードの名前は商品の略称（API の `abbr`）をそのまま出します。区分は商品の種類の表示名（`display_name`）をそのまま出します。限定は商品の種類の `senior_only` で決め、印はその種類の表示名を「（）」で付けます。抽出の要らない品物とグッズはカードになりません（商品の種類の `needs_brew`・`makes_cup` が false）。商品の種類の名前（`ice`・`limited` など）や商品の名前で判断・表示・色を決め打ちしません。
- カードの色はマスターの画面と同じく、POS の色の設定（画面 master。商品の設定 > 種類の設定）だけで付けます。設定が無ければ白です（`utils/masterColor.ts`）。
- 豆キューは POS の在庫（`GET /api/inventory`）の豆を表示するだけです。CaOS は在庫を持たず、「次へ」でも減らしません（消費は POS が注文から数えます）。棚卸し・入荷は POS の在庫の画面（`/inventory`）で記録します。
- 指名は、レジで選んだドリッパーの番号（注文の明細の `dripper`。1st〜6th は 1〜6）で決めます。未割当のカードは同じ商品でも指名の番号ごとに分け、番号の付いたカップはその番号のドリッパーにだけ置けます（画面の `assignWrites` とサーバーの `PUT /api/caos/cups` の両方で確かめます）。統合も同じ番号どうしだけです。番号の無い自由記述だけの古い明細は指名なしとして扱います。カードの指名の表示は POS のマスターの画面と同じ `assignmentDisplay`（`modules/common/src/models/dripper.ts`）で、番号は「指名:2nd」、番号の無い古い明細は自由記述をそのまま出します（ドリッパーには固定しません）。
- API の URL は POS と同じ `VITE_API_BASE_URL` です（未設定ならローカルの `http://localhost:8080`）。origin も POS と同じなので、API の `FRONTEND_ORIGINS` に足すものはありません。

## ドリッパーの担当者と交代

- 「今そのドリッパーに誰がいるか」（名前と、上級生か）はサーバーが日本時間の日付ごとに持ちます（API の表 `caos_lanes`。`api/internal/handlers/caos_lanes.go`）。全部の iPad に共有の WebSocket の `{"type":"caos_lanes"}` で届き（今日の 6 つ全部。ほかのインスタンスへは `caos_lanes_changed`）、どの iPad でも同じ担当者が出ます。閲覧だけの画面（`/master-sheet/view`）も名前を出しますが、交代はできません。
- 替えるのは人が CaOS で行います。各ドリッパーの見出しの「交代」から、名前を選ぶか入れて替えます（`PUT /api/caos/lanes/{dripper}`）。空き（担当者なし）にもでき、ほかのドリッパーの担当者と入れ替えもできます（`POST /api/caos/lanes/swap`）。押したらその場で替わります（抽出中かどうかは見ません。待機のカードも動きません）。
- 名前の候補は sohosai-shift の予定から出します。今の枠・次の枠（本番の 30 分ごとの枠）と、オペ練の今と次のラウンドの、そのドリッパーの番目の人です。候補に無い人は自由に入れられます。予定どおりに自動で替えることはしません。
- 上級生かは、sohosai-shift の上級生の名簿（`seniors`）に名前があるかで、交代した時点の判定をサーバーに持ちます（名簿を読めない端末でも同じに出て、サーバーも確かめられるように）。
- 上級生でない人（担当者なしも）に替えるとき、そのドリッパーに限定のカードが待っていれば「このドリッパーに限定のカードが2枚あります（佐藤さんは上級生ではありません）」と出し、［まだ変えない］［変える］だけを出します。［変える］ならそのまま替え、カードもそのドリッパーに残ります（そのドリッパーの中では順番を変えられます）。
- 限定のカードは、担当者が上級生のドリッパーにしか置けません（画面でも `PUT /api/caos/cups` でも確かめます。別のドリッパーへ置くときだけで、同じドリッパーの中の順番の入れ替えは確かめません）。指名のドリッパーの担当者が上級生でない限定のカードは、どこにも置けません（担当者を上級生に替えれば置けます）。どのドリッパーにも上級生がいなければ、ヘッダーに「上級生がいません（限定を置けません）」と出します（幅の狭い画面では「上級生なし」と短く出します）。
- 画面の作りは `lanes/`（`CaosLanesContext.tsx` が担当者と交代の流れ、`LaneName.tsx` が見出しの名前と「交代」、`LaneChangeDialog.tsx`・`LaneConfirmDialog.tsx`・`ShiftFeedSettings.tsx`・`LaneHeaderStatus.tsx`）、決まりは `@cafeore/common` の `caosLanes.ts`（限定を置けるか・確認の文）と `caosShiftFeed.ts`（sohosai-shift の予定の読み方と候補）です。

### sohosai-shift の合言葉の入れ方

1. sohosai-shift で CaOS へ配信し、合言葉を受け取ります。
2. 各 iPad の CaOS のヘッダーの鍵のボタン（または「交代」の中の「合言葉」）を押し、合言葉を入れて「保存」します。その端末にだけ覚えます（`localStorage`。ビルドには入れません）。
3. 予定は Firestore の REST（`https://firestore.googleapis.com/v1/projects/sohosai-shift/databases/(default)/documents/caosFeeds/{合言葉}`）で 5 分ごとに読み直します。設定で「読み直す」「合言葉を消す」ができます。
4. 合言葉が無い・読めない端末でも、名前を入れれば交代できます（候補が出ないのと、上級生の判定ができない＝限定を淹れられない人として扱うだけです）。

## 緊急（入れ直し）と緊急のシール

- 緊急は、カップに印を付けるだけです（`order_cups` の `emergency_at`）。付けるのは 2 か所で、どちらも `POST /api/caos/emergency` を使います。
  - マスター（`/master`）の緊急ボタン：カップの下の「緊急」を押し、「緊急にする」をもう一度押す（`components/molecules/EmergencyCupButton.tsx`）
  - CaOS の入れ直しのパネル：抽出中・終わったカードを押して開く（B 案は NOW の「入れ直し」、`components/RebrewPanel.tsx`）。選ぶのは「どのカップか（杯数）」と「抽出中のカードを中断するか」だけです
- 同じカップは 2 回緊急にしません（もう印があれば何もしません）。緊急にしたカップは、CaOS の列（`dripper`・`dripper_position`・`brew_started_at`・`brew_finished_at`）が空に戻り、最初に淹れたカード（`drip_id`）は残ります。カップの準備完了・提供済みは変えません。
- 中断すると、抽出中のカードのカップを全部緊急にし、カードを終わらせて、そのドリッパーの待機の先頭を始めます（中断を選ばなくても、抽出中のカードのカップが全部緊急になれば同じです）。
- `emergency_at` があって入れ直しのカード（`emergency_drip_id`）がまだ無いカップは、未割当のいちばん上に緊急のカードとして出ます（準備完了・提供済みのカップでも出ます）。割当・「次へ」はふつうのカードと同じで、入れ直しのカードは `emergency_drip_id` で持ちます（`PUT /api/caos/cups` の `drip_id` は、緊急のカップでは `emergency_drip_id` を指します）。入れ直しのカードはふつうのカードと統合できません。
- 入れ直しのカードは準備完了でも終わりにせず、`次へ` で終えます。`次へ` で、カップがまだ準備完了でなければ準備完了にします。
- 緊急のシールは、プリンターにつないだレジの iPad（レジの画面 `/cashier`、`label/useEmergencyLabels.ts`）が印刷します。印刷キューの表はありません。
  - 共有の WebSocket で受けた注文の中に、`emergency_at` があって `emergency_printed_at` が空のカップを見つけたら、先に `POST /api/orders/{id}/cups/{cupId}/emergency-label/claim` で `emergency_printed_at` を「まだ空なら付ける」で付け、付けられたときだけ印刷します。レジやタブが 2 つあっても、付けられるのは 1 つだけなので 2 重に印刷しません。つなぎ直したときも全部の注文を受け直すので取りこぼしません（印刷したカップは印があるので印刷しません）。
  - 印刷に失敗したら（プリンターの返事が失敗・60 秒返事が無い）、`.../emergency-label/release` で `emergency_printed_at` を空に戻し、次の更新（または 15 秒後）に試し直します。プリンターにつながっていないレジは印を付けません。
  - シールは「緊急」とだけ書いたシールを 1 枚出し、そのあとにそのカップの本物と全く同じシールを出します（本物には「緊急」と書きません）。ラベルの中身はレジの会計のラベルと同じ `@cafeore/common` の `lib/label.ts` で作ります。
  - 会計のラベルは今までどおりレジで直接印刷します（保存が失敗しても印刷します）。会計のラベルと緊急のシールが重なっても、同じ iPad の中の待ち行列（`label/print-util.ts`）で 1 件ずつ、前の印刷の返事を待ってから送ります。
- 練習（実データテスト）の盤面では入れ直しを出しません（抽出中・終わったカードを押しても入れ直しのパネルは開きません）。練習の盤面はブラウザの中だけなので、本番の緊急の API にも印刷にも何も送りません。本番の注文で緊急にしたカップも練習の盤面には出ません。

## 実データ・テストプレイ

- ヘッダーの「実データテスト」から、過去の祭の実際の注文を流して、1 人で割り振りを練習できます。開始前に時間帯（日本時間の 0 分・30 分の区切り）と 30 分／1 時間を選びます。ヘッダーの `1x / 2x / 5x / 10x` に合わせて、時計・タイムライン・注文の到着・抽出の残りが一緒に進みます。
- **データは画面で手元の JSON を読み込みます**（リポジトリにも配信にも入れません）。読めるのは sohosai-analysis の `YYYY/data/day*.json` と、cafeore-pos の `GET /api/orders` の応答を保存したものです。複数のファイルを一度に選べ（ドラッグでも可）、重なる注文は 1 件にします。
  読み込みはブラウザの中だけで、許可した項目（注文番号・時刻・金額・品物の ID・名前・略称・値段・種類）だけを写し、担当者名・指名・コメント・お預かりは落とします（`@cafeore/common` の `caosPracticeData.ts`）。落とした後のデータだけをその端末の IndexedDB に覚え、「読み込んだデータを消す」で消せます（`practice/loaded.ts`）。
- **盤面のルールは本番と同じです。** 練習の盤面はブラウザの中だけで、本番と同じ形の注文とカップ（`dripper`・`dripper_position`・`drip_id`・抽出の開始と終了の時刻）を持ちます。カードの組み立て（`buildCaosCards`）と割当・移動・未割当に戻す・統合の書き込み（`assignWrites` など）は本番と同じ関数で作り、本番ならサーバーがする「書き込みを当てる」と「次へ」は、サーバー（`api/internal/handlers/caos.go`）と同じ決まり・同じ理由の文で `@cafeore/common` の `caosPractice.ts` がします。時刻はサーバーの今の代わりに練習の時計の今です（`practice/usePracticeBoard.ts`）。
- 練習中は本番の盤面・注文・在庫・担当者に何も送りません（`PUT /api/caos/cups`・「次へ」・`/api/caos/lanes` も送りません。cafeore-pos から読むのは、商品の種類・色の設定・在庫の「商品 → 豆」と、始めたときの担当者だけ）。
- 指名と限定もサーバーと同じに確かめます。指名は明細のドリッパーの番号（`dripper`）で、その番号のドリッパーにしか置けず、指名の違うカップは統合できません。限定のカップは担当者が上級生のドリッパーにしか置けません。練習の担当者（名前と上級生か）は始めたときの本番の担当者の写しで、練習の中では替えられません（見出しの「交代」と合言葉のボタンは出しません）。上級生のいない担当者で始めると、限定のカードはどこにも置けません。
- 緊急（入れ直し）は練習では出しません（入れ直しのパネルは開かず、緊急の API・緊急のシールの印刷にも何も送りません）。
- 品物の種類（カップを作るか・抽出が要るか・限定か）は、DB の今の商品の種類に同じ名前があればその設定、無ければデータに入っていた種類の設定（cafeore-pos のデータ）、どちらも無い（種類の無い昔のデータ・今は無い種類）ときは API の列の既定値と同じく「カップを作る・抽出が要る・限定でない」として扱います（サーバーも種類の分からない商品は抽出が要るものとして扱います）。今の種類に無い種類があれば、始める前の画面に出します。
- 昔のデータには指名が残っていない（読み込むときに落とす）ので、練習の注文は指名なしです。昔のデータ（sohosai-analysis）の商品の ID は今の DB の商品の ID と違うので、カードの豆は出ません。色は POS の色の設定（DB に同じ名前の種類があれば、その種類の設定）で、設定が無ければ白です。
- 「終了・実績」を押すと、練習の結果から売上、商品構成、ピーク、提供時間（抽出の要るカップが全部「次へ」で終わるまで）、担当量、分割注文の仕上がりΔを出します。

## 置き場所

2026-10 に `cafeore-tkb/CaOS` から cafeore-pos のモノリポへ移し、POS の中（`services/pos/app/caos`）に置きました（履歴は持ってきていません）。実データテストのデータはリポジトリに置かず、画面で手元の JSON を読み込みます。

## タッチ操作

- 未割当カードをタップすると、カードを隠さず上下に1〜6の割当ボタンが開きます。
- 指を離さず割当先へなぞる操作と、レーンへのドラッグ操作に対応しています。
- 枠外をタップすると選択状態を解除します。
- タイムライン上の未開始カードも、同じ操作感で割当先を変更できます。
- Dでは右の注文カードを担当者の列へドラッグすると、その担当者に割り当てます。表の未開始カードは別の列へドラッグして移すか、右の注文内容へドラッグして未割当に戻せます。縦の動きはスクロールに使うため、横へ引き出すと掴めます（右で選択中のカードはどの方向にもドラッグできます）。
- Dで1杯カードを選ぶと、統合できる同じメニューの1杯カードに「統合する」が出ます。統合後のカードは前の注文番号の欄に移るため、自動で選択してその位置までスクロールします。

## 開発

POS の一部なので、コマンドも POS と同じです（`pnpm pos dev` で開き、`/master-sheet` に行く）。型チェックとビルドも `pnpm pos typecheck`・`pnpm pos build` に含まれます。

CaOS の元の lint の方針（タッチ操作向けに切っていた a11y のルールなど）は、`biome.json` の `overrides` で `services/pos/app/caos` にだけかけています。スタイルは `caos.css` で `.caos-root` の中に閉じ、POS のほかの画面に漏らさないようにしています。
