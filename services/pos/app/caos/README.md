# CaOS — Cafeore Operating System

コーヒー提供現場で、6人のドリッパー（抽出担当者）へ注文を割り当て、進行状況を一画面で把握するためのタッチ操作向けの画面です。iPadの横画面を想定し、管制盤を常に表示したまま操作できます。

画面・操作・業務ルール（割当・指名・最大2杯・統合・`次へ`・先頭へ・途中への差し込み・カードの色・タッチ操作）は、[画面設計・操作要件](./DESIGN_REQUIREMENTS.md)にまとめています。

## 公開

POS の画面の1つとして `/master-sheet` で配信します（<https://cafeore-pos.cafeorepos.workers.dev/master-sheet>）。入口は `services/pos/app/routes/master-sheet.tsx` で、POS のヘッダーは付けません。盤面を閲覧だけで映す画面は `/master-sheet/view`（`routes/master-sheet_.view.tsx` → `caos/ReadOnlyBoard.tsx`）で、管制盤 A のタイムラインに同じ盤面を映します。「次へ」・空きスロットは出さず、カードを押しても動かさず、盤面への書き込みも送りません。リベロ（ドリッパーにお湯を持って回る係）が見る画面は `/master-sheet/libero`（`routes/master-sheet_.libero.tsx` → `caos/LiberoBoard.tsx`）で、同じ盤面を読むだけです（下の「リベロビュー」）。閲覧の 2 つの画面はヘッダーの「タイムライン」「リベロ」で行き来でき、操作の画面のヘッダーの「リベロ」はリベロビューを別のタブで開きます。旧リポジトリ `cafeore-tkb/CaOS` から公開していた [GitHub Pages の版](https://cafeore-tkb.github.io/digital-master-sheet-pages/) は、こちらに切り替えたら止めます。

## 画面

- **A**: NOW線を基準に、6人のレーンと時間軸で進行・待機カードを確認する管制盤
- **C**: 担当者ごとに現在の抽出と待機を横に並べ、次に空く担当者を確認する比較案
- **D**: 紙のマスターシートを画面上に再現する案。6人を列、注文番号を行とした表に、右の注文カードを選んで枠をタップするか、列へドラッグして割り振ります（[cafeore-pos#699](https://github.com/cafeore-tkb/cafeore-pos/pull/699) のコンセプトを移植）
- 最上段のヘッダーからA/C/Dを切り替えます。
- 補助情報は右側パネルに表示し、管制盤全体を隠しません。
- iPad で画面全体が動かないよう、CaOS の 3 つの画面（`/master-sheet`・`/master-sheet/view`・`/master-sheet/libero`）を開いているあいだは、ページのスクロール・はね返り・ピンチとダブルタップの拡大を止めます（`caos.css` の `html:has(.caos-root)` で `overflow: hidden`・`overscroll-behavior: none`・`touch-action: pan-x pan-y`、盤面は `h-dvh` で見えている高さに収める。`hooks/useFixedViewport.ts` で viewport に `maximum-scale=1, user-scalable=no` を足し（入力欄を押したときの自動の拡大も止まる）、Safari の `gesturestart`・`gesturechange` を止める）。枠の中のスクロールとスクロールバー・カードのドラッグ・入力欄は今まで通りです。

### 管制盤A・C・Dの比較

3案とも同じ注文データ・業務ルール（オーダー番号順、指名、最大2杯、`次へ` で完了）を共有し、違うのは見せ方と割当の操作だけです。

| | A：タイムライン | C：ドリッパー行 | D：マスターシート |
|---|---|---|---|
| 担当者の並び | 6レーン（横軸＝時刻） | 6行（左半分） | 6列（表の列） |
| 待機列の見え方 | 時間軸上のカード位置で全件 | 現在＋待機を横並びで全件 | 注文番号の行に全件（全注文番号に行があり、列を上から読むと担当者の順番） |
| 時間の情報 | NOW線と時刻目盛り、開始・終了予定、次に空く上位3人 | 現在の残り時間、次に空く上位3人 | 列見出しの残り時間のみ |
| 列の状態 | ドリッパーの番号の色と札（空き・待機・抽出中・まもなく・継続中、待っている指名の杯数）。3案とも同じ `DripperIndicator`。押すと列の操作（交代・待機をまとめて移す） | 同じ | 同じ |
| 「次へ」 | 右端に固定 | 抽出中のカードのすぐ右 | 表の下に固定 |
| 完了済みの表示 | NOW線の左（過去90秒）に薄く | 右の注文の列に薄く（いちばん古い未割当の注文から後ろ） | すべて元の行に薄く残す（行は動かさず下へ積む） |
| 未割当の置き場所 | 下段の横帯（注文番号を左から横に並べ、同じ注文のカードは細幅・1 行表示で縦に並べる。「未割当」タイトル右のスクロールバーで全件を見る） | 右の注文の列（いちばん古い未割当の注文から。その上に直近にドリッパーに置いた注文を 3 件、割当済みのカードは灰色で「3rd 2番目」の札を付けて残す） | 右の注文カード（全件） |
| 未割当の単位 | 抽出カード | 抽出カード | 注文（割当済み分も薄く表示） |
| 割当操作 | タップで1〜6ボタン／なぞり／ドラッグ | タップで1〜6ボタン／なぞり／ドラッグ | カードを選んで表の「ここに配置」をタップ／列へドラッグ |
| 割当後の移動・戻し | レーン間ドラッグ、タップで1〜6／×で戻す | 詳細モーダル | 列間ドラッグ、右の注文内容へドラッグで戻す、詳細モーダル |
| 1杯カードの統合 | あり（未割当でタップ、待機・抽出中へドラッグ） | あり（同じ） | あり（右の注文内容でタップ。統合した2注文の行を、間の行ごと大きな枠で囲む） |
| 主な実装 | `ControlViewA`（`DispatchBoard` + `UnassignedStrip`） | `ControlViewC`（右は `OrderQueuePanel`） | `ControlViewD` |

- **A：タイムライン**　時間の流れを最も正確に表す基準案です。待ち時間の偏りや「誰がいつ空くか」が位置で読めて、ドラッグで再配置できます。代わりに情報量が多く、横スクロールやカードの小ささで一覧性が落ちやすくなります。
- **C：ドリッパー行**　担当者を行にして、現在の抽出と待機列を横に並べる案です。未割当を右半分に全件並べます。待機列が長くなると行内の横スクロールになります。
- **D：マスターシート**　紙運用をそのまま置き換える案です。行＝注文番号（未割当や抽出のない番号も詰めずに1行ずつ）なので「どの注文を誰が淹れるか」と注文ごとの杯数が表で揃い、紙に慣れた人が移行しやすいです。淹れ終わっても行は動かず、新しい注文は下へ積まれていきます。割当は2回のタップか列へのドラッグで済み、割当後もドラッグで列を移したり未割当に戻したりできます。統合した1杯同士は、2注文の行とその間の行をまとめて囲む大きな枠で表示します。注文が増えると表が縦に伸びてスクロールが要ります（開いたときは淹れ終わっていない最初の注文付近を表示）。

## cafeore-pos 連携

- 注文は常に cafeore-pos と同じDBから取り込みます（画面内でモック注文を作る機能はありません）。ヘッダーのDBアイコンの点が接続状態で、緑は接続済み、黄は接続中（最初の注文が届くまでを含む）・再接続中です。その下に重ねたプリンターのアイコンの点は、この端末のシールのプリンター（印刷の設定の `label_printer_ip`）の接続状態で、緑は接続完了、黄は接続中、赤は未接続です。未接続のときは、ヘッダーの下（「未送信」「未印刷」と同じ所）にレジと同じ「ラベルプリンター未接続」と、証明書を許可するページ（`https://<プリンターの IP>`）の案内を出します。
- 実データテスト中は cafeore-pos の注文を使わず、ブラウザの中の練習の盤面で動かします（下の「実データ・テストプレイ」）。テストの盤面のあいだ（テスト中も、終えて実績を見ているあいだも）は盤面の上に「テストの盤面です」の帯と「本番に戻る」を出し続け、ヘッダーの「テスト」も本番と違う色にします。「本番に戻る」・リセット、またはテストを終えたあとに実績のパネルを閉じると、テストの盤面を捨てて cafeore-pos の注文に戻ります。
- 盤面は注文のカップ（`order_cups`）の列で持ちます。CaOS が決めたこと（ドリッパーの番号 `dripper`・ドリッパーの中の順番 `dripper_position`・同じカードで淹れるカップの印 `drip_id`・抽出の開始 `brew_started_at` と終了 `brew_finished_at`）をカップに書き、注文の応答（`OrderResponse` の `cups`）に載ります。CaOS 以外の画面は読みません。
- カードの状態は時刻で決まります（終了あり＝終わり、開始あり＝抽出中、どちらも無くドリッパーあり＝待機、ドリッパーなし＝未割当）。マスター（`/master`）でカップを全部準備完了にしたカードも終わりです。
- 抽出の開始・終了の時刻はサーバーの時刻で、サーバーが付けます（iPad の時計は使いません）。列の先頭（抽出中）に入れて始めるときは、書き込みの after に時刻の代わりに「始める」の印（`start_brew`）を送ります。抽出中のカードも動かせ、先頭でない所・未割当に動かすと始めた時刻が消え、先頭に入れ直すと今から始め直します。終わったカードは動かせません（終えるのは「次へ」）。
- 画面は、POS の画面全体で共有している WebSocket（`/api/ws/orders`、root の `OrdersWSProvider`）の注文から、今日（日本時間。注文の作成日時で区切る）のカードを組み立てます（`@cafeore/common` の `buildCaosCards`）。未割当は、抽出が要り（商品の種類の「カップを作る」と「抽出が要る」が両方オン。`@cafeore/common` の `cupNeedsBrew`。API と同じ決まり）まだ準備完了でないカップを、注文ごと・商品ごと・指名の番号ごとに最大2杯で組み立てます。注文の編集・削除で消えたカップはカードから抜けます。CaOS 用に別の接続は張りません。
- カードの名前は商品の略称をそのまま出します。カードの豆は、カードの商品のアイテムの在庫（`GET /api/inventory` の kind が item のもののうち、抽出が要る（`cupNeedsBrew`）アイテムのもの。豆キューに出すのも同じ。`logic/beans.ts` の `dripItemStatuses`）を引き、在庫対象の名前をそのまま出します（豆はカードの札）。カードはいちばん大きく商品と杯数（何が何杯か。杯数の札はいつもカードの右上）、次に注文番号を出します（A のタイムラインと C のドリッパーの列は、カードの高さのまま注文番号を大きく出します。統合したカードは後ろにもう 1 枚重ねた枠で出します。分けた注文のカードの位置・合計杯数はカードに出しません。ほかの場所にも同じ注文があるかは、カードを押して注文を選んだとき（未割当のカード、ドリッパーの待機のカードの 1〜6 のボタン・詳細、抽出中・終わりのカードの緊急の入力。閉じると選択を外します）に、どこにあっても同じ注文のカードに選択中の黄の輪が付くことで分かります）。未割当のカードだけは、注文番号と杯数をいちばん大きく、商品を次の行に小さく出します（統合したカードの長い番号「#120+#121」は、杯数の札と同じ大きさで字の間を詰め、それでも入らなければ省略して、杯数の札をカードの外へ押し出しません）。指名は「指名 2nd」（番号の無い自由記述だけの古い明細は「指名 名前」）、上級生のみのカードは「★上級生」の札を出します。
- 指名は、レジで選んだドリッパーの番号（注文の明細の `dripper`。1st〜6th は 1〜6）です。番号のあるカードはその番号のドリッパーにだけ置けます（1〜6 のボタン・ドラッグ・D の「ここに配置」。`@cafeore/common` の `caosDripperAllowed`・`assignWrites`、サーバーの `PUT /api/caos/cups` の両方で確かめます）。1 枚のカードに違う番号のカップは入れません（指名なしのカップは指名のカードに入れられ、カードはその番号のままです）。指名のカードの色は、POS の色の設定の画面「CaOS（指名）」から引きます（無ければ「マスター」の色）。地の色は商品の色だけに使い、指名は黒い点線の枠と札で出すので、指名の色が商品の色と近くても見分けられます。
- 操作（割当・ドリッパーの移動・先頭へ・途中への差し込み・未割当に戻す・統合）は、カップの書く前と書いたあとの値を `PUT /api/caos/cups` で送ります（`assignWrites`・`unassignWrites`・`mergeWrites`）。書いたカップの注文は、つないでいる画面に配られます。決まりに合わない操作は、押したときに画面がサーバーと同じ決まりで確かめて止め、理由が POS の通知（sonner の toast）で出ます。
- 画面を先に動かします（楽観的な更新。`hooks/useCaosOutbox.ts`・`@cafeore/common` の `caos-outbox.ts`）。盤面を書き換える操作（割当・移動・先頭へ・未割当に戻す・統合・外す・まとめて移す・次へ・緊急の取り消し・「1つ戻す」・担当者の交代と入れ替え・上級生の印）は、押した瞬間に画面が変わり、書き込みは後ろで送ります。
  - 押した操作はまずこの端末の localStorage に 1 件ずつ残し（シールの未印刷と同じ置き方。`~/lib/device-store.ts`）、盤面はサーバーから届いた注文と担当者に、残っている操作を古い順に重ねて出します（重ねるのは実データテストと同じ、サーバーの決まりをブラウザで行う関数）。抽出の始めた時刻は仮に端末の今で出し、サーバーの値が届いたら差し替わります。
  - 送るのは古い順に 1 つずつです（同じ端末のタブは 1 つだけが送ります。Web Locks で決め、閉じたらほかのタブが引き継ぎます）。送る直前に書き込みの書く前の値をサーバーの今の値に差し替え、カードの場所（ドリッパー・カード・抽出中か・終わりか）が押したときと同じなら送ります（順番の数・時刻はサーバーが決めるので比べません）。通ったら、その結果の注文がサーバーから届くまで（5 秒まで）は重ねたままにし、次を送りません（一瞬前に戻って見えないように）。送れずに遅れて始めたカードの「次へ」は、サーバーの始めた時刻から 10 秒（時計の差に 1 秒みて 11 秒）たつまで待って送ります（サーバーの 10 秒の決まりで断られないように。画面は押したときに 10 秒を確かめています）。
  - 送れなかった（つながらない・返事が 10 秒来ない・5xx・ログインが切れた 401・403・時間切れ 408・混んでいる 429）ときは、1 秒から倍にして 15 秒までの間をあけて何度でも送り直し、そのあいだ後ろの操作は待ちます。共有の WebSocket がつながっていないあいだは送らず、つなぎ直したらサーバーから全部の注文と今日の担当者が届き直してから送ります（担当者は注文のあとに届くので、注文が届いてから 3 秒まで待ちます。今日の担当者がまだ無ければサーバーは送らないので、3 秒で待つのをやめます）。前の日に押して残っていた操作は、重ねも送りもせずに捨てて知らせます。再読み込み・タブを閉じても残り、次に開いたら送ります。返事が届かなかったものは、サーバーの盤面がもうそのとおりなら送らずに済ませます。
  - ほかの iPad が先に変えた（409）ときは、1 秒待ってサーバーの今の盤面で確かめ直し、カードの場所が同じ（番号がずれただけ）ならその値でもう一度送ります。もうそのとおりなら済みにします。場所が違えば、決まりに合わない（400 など）ときと同じく送り直さずに捨て、盤面はサーバーの今に戻り、「「割当 #038 → 2nd」は通らなかったので、盤面を戻しました」と理由を通知で出します（その操作は「1つ戻す」からも消えます）。捨てた操作のあとに押した操作も、場所が合わなければ同じく捨てます。
  - 担当者の交代（見出しの「交代」・交代の画面で選ぶ・名前を入れる・空きにする）と入れ替えは、サーバーが書く前の値を確かめないので、送る直前にサーバーの今の担当者が押したときの担当者のままかを画面が確かめます。ほかの iPad が先に替えていれば送らずに捨て、盤面はサーバーの今に戻り、「1st の交代は、ほかの iPad が先に替えていたので取りやめました」と通知で出します（「1つ戻す」からも消えます。続けて押した交代も同じく捨てます）。上級生の印を直すのは、名前が同じときだけ書くので確かめません。押したときの担当者を持たない前の版の交代（端末に残っていたもの）は、確かめずに送ります。
  - 押してから 2 秒を過ぎても送れていない操作があれば、ヘッダーの下に「未送信 N 件」と「もう一度送る」を出します（シールの「未印刷 N 件」と同じ所）。
  - 実データテスト中の操作は練習の盤面の中だけで、残しも送りもしません（テストの前に押した本番の操作は送ります）。閲覧だけの画面は送りません。
  - 緊急（入れ直し）を足すのと、緊急の取り消しを「1つ戻す」で足し直すのは、入れ直しの id をサーバーが決めるので、今まで通り応答を待ちます。
- 順番（`dripper_position`）は整数で、サーバーが決めます。画面が送るのは「どのドリッパーの、どのカードの前に入れるか」（after の `insert_before`。`null` なら最後）だけです。サーバーは前に入るカードの番号に入れ、そのドリッパーでそれより後ろの終わっていないカップを +1 します。列から抜けたカードの番号は詰めません。
- 列の先頭は抽出中です。待機のカードの「先頭」ボタンで列の先頭へ（今から始まり、抽出中だったカードは始めた時刻を消して待機の先頭へ下がります）、待機・抽出中のカードの上（左の部分）にドラッグして落とすとそのカードの前へ（抽出中のカードの前は列の先頭。同じ列の中の入れ替えにも使えます）、列や 1〜6 のボタンに落とすとその列の最後へ入ります。抽出中も待機も無い列に入れたら、そのまま始めます（抽出中が無く待機のある列の先頭は待機の先頭で、「次へ」で始めます）。
- 抽出中のカードも、待機のカードと同じくなぞるとすぐ掴んで動かせます（A のタイムライン・D の表。D は右の注文内容に落とすと未割当へ）。押すと今までどおり緊急（入れ直し）のパネルが開き、そこにも「1〜6 に移す」「未割当に戻す」が出ます。先頭でない所（同じ列の待機・別の列の待機）や未割当に動かすと始めた時刻を消して待機・未割当にします。同じ列の中で下げたときは先頭になった待機のカードが今から始まり、別の列・未割当へ動かしたときは元の列の次は始めません。統合したカード・指名・上級生のみ・緊急（入れ直し）も同じ決まりです（抽出中のカードはほかのカードに統合せず、分けません）。実データテストの練習の盤面も同じ決まりです。
- 統合（`canMergeCards`・`mergeWrites`）：同じ商品の 1 杯どうしを 2 杯の同時抽出にまとめます。指名は同じ番号か片方だけ、緊急（入れ直し）は入れ直しどうしだけです（サーバーも断ります）。動かすカードは未割当か待機、入るカードは未割当・待機・抽出中です。抽出を始めたカードにも 1 杯を足せ（開始の時刻はそのカードのまま。始めてから `CAOS_LATE_MERGE_SEC`（30 秒）を過ぎたカードへは、どの画面から統合しても、実データテストでも［やめる］［統合する］で確かめます（`caosLateMerge`。API は確かめません。確かめは「次へ」の確かめと同じ右上の表示で、ドラッグで落としたときもカードは決めるまで元の場所のままです）。終わったカードには入れません）、入るカードの場所（ドリッパー・順番）のままです。操作は、未割当のカードを開いて「統合する」の出たカードを押すか（相手が 1 枚か、注文番号がいちばん近い相手が 1 枚に決まるときは、開いたカードをもう一度押しても統合します。開いたカードに統合の印と相手の番号「#012」が出ます。`quickMergePartner`）、未割当・待機のカードを、統合できる待機・抽出中のカードの上にドラッグして落とします（待機・抽出中のカードは右の部分。左の部分はそのカードの前へ。抽出中のカードの前は列の先頭）。管制盤 A・C・D で同じです（D は右の注文内容の中だけ）。
- 統合の解除（`splitWrites`）：ほかの注文と統合した未割当・待機のカードは、開くと 1 杯ずつ「#007 外す」が出ます（同じ注文の同じ商品の 2 杯は、はじめから 1 枚のカードなので分けません）（A・C の未割当と A の待機はカードの上、C・D の待機は詳細のパネル）。外した 1 杯は未割当に戻り、残りの 1 杯はそのままの場所です（どちらを外すかで、統合先を入れ替えられます）。抽出中のカードは分けません（間違えたら緊急で入れ直します）。
- 待機をまとめて移す（`moveQueueWrites`）：各列のドリッパーの番号を押して開く列の操作の「この列の待機を移す」で、そのドリッパーの待機を全部、別のドリッパーの最後へ並びのまま移します（1 回の `PUT /api/caos/cups`）。移す先に置けないカード（指名・上級生のみ）は残し、通知で知らせます。移す先が空いていれば先頭をそのまま始めます。
- `次へ` は `POST /api/caos/drippers/{dripper}/next` です。抽出中のカードを終え、そのカードのカップだけを準備完了にし（POS のカップの準備完了と同じ。注文の準備完了はカップから決まります）、待機の先頭を始めます。抽出を始めてから 10 秒（`CAOS_NEXT_COOLDOWN_SEC`）はその列の「次へ」を押せません（画面のボタンは押せなくなり、サーバーも断ります。二度押し・ほかの iPad と続けて押すのを防ぎます）。抽出時間の半分もたっていないカードの「次へ」は、隣の列の押し間違いかもしれないので「3rd の #007 を終えますか？」と確かめてから進めます。確かめは画面の右上（管制盤 A の右端の「次へ」の列と、右のパネルを避けた所）に出し、背景を暗くせず盤面の操作は止めません。続けてほかのドリッパーでも押せば並べ（同じドリッパーなら置き換え）、8 秒何もしなければ消えます（やめる扱い。何も送りません）。抽出を始めて 30 秒を過ぎたカードへの統合の確かめも同じ所に同じ決まりで出し（同じカードの統合をもう一度すれば置き換え）、「次へ」と統合の確かめは種類によらず新しいものを上にして 1 列に並べます（`hooks/useToastConfirms.ts`）。
- 提供の画面・マスターでカップを準備完了・提供済みにしたら、そのカップ（入れ直しも）の抽出中のカードの「次へ」をサーバーが進めます（カードを終えてほかのカップも準備完了にし、待機の先頭を始めます。`advanceReadyCaosCards`）。「入れ終わりました」を言わなくても進み、手動の「次へ」は提供が押し忘れたときの補助です。注文の状態を書いたあとに別のトランザクションで行い、CaOS で断られても提供の操作は戻しません。提供を取り消しても、終えたカードは戻しません。
- 緊急（入れ直し）は、マスター（`/master`）のカップの「緊急」・ヘッダーの「番号で緊急」か、CaOS のヘッダーの「緊急」・抽出中・終わりのカードを押して開く入れ直しのパネルから足します（どれも同じ入力で、注文番号・入れ直すカップ・理由を入れます。カードから開くとそのカードのカップを全部選んでおき、注文をまたいで統合したカード（#011+#012 など）なら、ほかの注文のカップも注文番号を添えて出すので、全部も一部も入れ直せます（シールは杯ごとに刷ります）。理由は自由に書くか、前の日までも含めてよく使われた理由（`GET /api/cup-emergencies/reasons`）を押します。`POST /api/cup-emergencies`）。入れ直しは `cup_emergencies` の 1 行で、カップの列（最初の抽出の記録）は変えません。入れ直しはカップと同じ列を持ち、未割当のいちばん上（A の横帯の先頭、C の注文の列の先頭の「緊急」の行）に、赤い「緊急」の札と理由のカードで出て、割当・移動・統合・「次へ」はふつうのカードと同じ操作・同じ決まりです（書き込みの `cup_ids` には入れ直しの id。指名・上級生のみは入れ直したカップのもの）。入れ直しは準備完了で終わりにしません。押した端末が、レジで刷るのと同じそのカップのシールを 1 枚、印刷の設定のシールのプリンターに刷ります（刷れなければ端末に残して送り直し、ヘッダーの下に「未印刷 N 件」を重ねて出す）。実データテスト中も同じ入力・同じ操作で入れ直せますが、練習の盤面の中だけで足し・取り消し・戻し（`@cafeore/common` の `addCaosPracticeEmergencies`・`cancelCaosPracticeEmergency`）、API には書かず、シールも刷りません（未印刷にも積みません）。入れ直しで使う豆（アイテムの在庫）とカップは、足したときの在庫の設定で在庫から減ります（棚卸しの前か後かは、入れ直しの抽出を始めた時刻で決めます。まだ始めていなければ、まだ使っていません）。
- まだ抽出を始めていない（未割当・待機の）入れ直しは取り消せます（`DELETE /api/cup-emergencies/{id}`。マスターの「緊急を取り消す」、CaOS で開いた入れ直しのカードの「取り消す」、管制盤 C・D の待機の詳細のパネル。どれも 2 回押しで決めます）。減らした在庫は戻り、全部の端末に共有の WebSocket の `{"type":"cup_emergency_cancelled"}` で知らせが届き、各端末はこの知らせを受けたときだけ、残っている未印刷のそのシールを消します（注文の一覧から消えたことでは消しません。知らせを受け損ねた端末は刷ってしまいますが、刷るべきシールを刷らないよりよいとしています）。
- 「1つ戻す」（ヘッダーの右の「戻す」）：この画面が最後にした操作（割当・移動・並べ替え・未割当に戻す・統合・次へ・緊急・緊急の取り消し・見出しの「交代」）を、10 秒のあいだ戻せます。押せるあいだはボタンが濃くなり、何を戻すかと残りの秒が出ます。本番は `POST /api/caos/undo` で、カップの今の値がその操作のあとのままのときだけ操作の前の値に書き戻します（ほかの端末があとで変えていた・提供済みになったら断り、理由が通知で出ます）。「次へ」を戻すと、終えたカードは抽出中に、始めたカードは待機に戻り、その「次へ」で付けた準備完了が外れます。抽出中のカードを動かしたのを戻すと、消した・付け直した始めた時刻が前の時刻に戻ります。緊急を戻すと入れ直しを取り消し（`DELETE /api/cup-emergencies/{id}`）、緊急の取り消しを戻すと同じカップ・同じ理由で入れ直しを未割当に足し直し、戻した端末がそのカップのシールを刷り直します（刷れなければ端末に残して送り直す）。入れ直しの「次へ」を戻しても、入れ直したカップの準備完了は外しません。見出しの「交代」を戻すと、今の担当者が交代したあとのままのときだけ前の人（空きも）に戻します（`PUT /api/caos/lanes/{dripper}`。ほかの画面が替えていたら断ります。上級生のみのカードの確かめは替えるときと同じです）。実データテストでは、練習の盤面を操作の前に戻します。
- 豆キューは在庫の画面（`/inventory`）と同じカード（`components/organisms/inventory/StockCard`）で、そこからの棚卸し・入荷は POS の在庫に記録します（実データテスト中は記録しません）。
- API の URL は POS と同じ `VITE_API_BASE_URL` です（未設定ならローカルの `http://localhost:8080`）。origin も POS と同じなので、API の `FRONTEND_ORIGINS` に足すものはありません。

## リベロビュー

- リベロが次にお湯を持っていく人を一目で決められるよう、1st〜6th の抽出中のカードの「入れ始めてからの時間」（抽出の開始 `brew_started_at` から。秒まで、毎秒進む）と、その長い順の順位（1・2・3…）を大きく出します。未割当は出しません。
- 各行には担当者の名前、何を何杯（商品の略称・杯数。地の色はカードと同じ色の設定）と注文番号、予定の抽出時間（`@cafeore/common` の `caosBrewSec`）に対する進み具合の帯を添えます。
- 進み具合を予定の抽出時間までの 4 段に分け、長いほど行の地・枠・順位・帯を濃い紫にします（`caos.css` の `--caos-elapsed-1`〜`4`）。予定の抽出時間を過ぎたら継続中の赤（`--caos-overtime`）にし、帯の横に過ぎた時間（「予定 5:00 ＋0:40」）を出します。決まりは `logic/libero.ts`（`liberoLanes`。経過と継続中はほかの画面の列の状態と同じ `laneStatus` から引きます）です。
- 抽出していない（待機だけ・空き）ドリッパーは薄い灰色で、順位も経過も出しません。
- 並びはヘッダーで切り替えます。「ドリッパー順」（1st〜6th のまま。ドリッパーの並びと同じ位置）と「経過の長い順」（いちばん上が順位 1。抽出していないドリッパーは下に番号の順）。経過の長い順は URL の `?order=elapsed` で、テレビなどで開いたままにできます。
- 閲覧の画面（`/master-sheet/view`）と同じく、いつも cafeore-pos の本番の盤面を映し（実データテストの盤面は映しません）、書き込みは送りません。iPad の横置き（1180×820）からテレビ（1920×1080）まで、文字は画面の高さに合わせて大きくします。

## ドリッパーの担当者と交代

- 「今そのドリッパーに誰がいるか」（名前と、上級生か）はサーバーが日本時間の日付ごとに持ちます（API の表 `dripper_assignees`。`api/internal/handlers/caos_lanes.go`）。全部の iPad に共有の WebSocket の `{"type":"caos_lanes"}` で届き（今日の 6 つ全部）、列の見出しに「1st 山田★」のように出します（上級生に ★。担当者がいなければ番号だけ）。閲覧だけの画面（`/master-sheet/view`・`/master-sheet/libero`）も名前を出しますが、交代はできません。
- 替えるのは人が CaOS で行います（`PUT /api/caos/lanes/{dripper}`）。押したらその場で替わります（抽出中かどうかは見ません。待機のカードも動きません）。
  - 列の見出し（管制盤 A・C・D）と列の操作のパネル（ドリッパーの番号を押して開く）の「交代」は、押したらすぐ次の人に替わります。次の人は sohosai-shift の予定（下の並び）で、今の担当者が出てくる一番うしろの予定より後ろの最初の人です（前の予定の人には戻りません。今の担当者が予定にいなければ先頭から）。次の人はボタンに「交代 → 鈴木」のように出します（A・D は幅が狭いので「交代 →」の下に名前）。次の人がいない（合言葉が無い・予定にその番目の人がいない・予定の人がもう入っている）ときは押せない見た目で「次の人なし」と出し、押すと理由を通知で出します。替えたあとは「1つ戻す」で 10 秒のあいだ前の人に戻せます。二度押しで 2 人ぶん進まないよう、替えてから 1 秒は同じドリッパーの「交代」を押しても替えません。
  - ヘッダーの「ドリッパー」の各ドリッパーの「交代」は交代の画面を開き、候補から選ぶ・名前を入れる・空き（担当者なし）にする・ほかのドリッパーの担当者と入れ替える（`POST /api/caos/lanes/swap`）ができます。
- 替えるたびに、サーバーが交代の記録（表 `dripper_assignee_changes`。時刻・ドリッパー・前の名前・後の名前・後の人が上級生か。入れ替えは 2 行）を足します。抽出の統計のためのもので、画面には出しません。
- 名前の候補は sohosai-shift の予定から出します。今の枠・次の枠（本番の 30 分ごとの枠）と、オペ練の今と次のラウンドの、そのドリッパーの番目の人です（この順。今そのドリッパーにいる人と空きは除きます。`laneCandidates`、すぐ替える次の人は `nextLaneCandidate`）。候補に無い人はヘッダーの「ドリッパー」の「交代」で自由に入れられます。予定の時刻どおりに自動で替えることはしません。
- 上級生かは、sohosai-shift の上級生の名簿（`seniors`）に名前があるかで、画面が判定してサーバーに持ちます。交代した時点で判定し、予定を読み直したとき（5 分ごと・手で読み直したとき・合言葉を入れたとき。読めたときだけ）にも、今の担当者の分を新しい名簿に合わせます（名前は変えず上級生かだけ。`POST /api/caos/lanes/seniors`。交代ではないので交代の記録は足しません。`hooks/useSeniorRefresh.ts`）。名簿に載った人は上級生にし、名簿から消えた人は外します。ただし外す人のドリッパーに指名の無い上級生のみのカードが待っていれば自動では外さず、ヘッダーに知らせ（★に斜線の印）を出し、押すと交代と同じ確認をしてから外します（カードが無くなれば、次に読み直したときに外します）。読めない・合言葉が無い・名簿が空のときは何も変えません。閲覧だけの画面と実データテスト中は書きません（テストを終えてから合わせます）。判定するのは画面で、サーバーは名簿を持たず、送られた値（`senior`）をそのまま信じます（`PUT /api/caos/cups` の上級生のみの確かめもこの値で行います）。
- 上級生のみのカードは、担当者が上級生のドリッパーにしか置けません（画面の `seniorOnlyBlock` とサーバーの `PUT /api/caos/cups`・`POST /api/caos/undo` の両方で確かめます。別のドリッパーへ置くときだけで、同じドリッパーの中の順番の入れ替えは確かめません。実データテストでは確かめません）。上級生でない人（担当者なしも）に替えるとき、そのドリッパーに指名の無い上級生のみのカードが待っていれば、［まだ変えない］［変える］で確かめます（見出しの「交代」ですぐ替えるときも同じ）。どのドリッパーにも上級生がいなければヘッダーに知らせます。
- 指名と上級生のみがぶつかるとき（上級生のみのカードの指名のドリッパーの担当者が上級生でない）は、指名を優先します。指名のあるカード（指名のカップが 1 つでも入ったカード）は、指名のドリッパーの担当者が上級生でなくても置けます。統合は統合したあとのカードで確かめるので、指名の無い上級生のみのカードも、指名のカードに入れればそのドリッパーに置けます。待機をまとめて移すときも同じ決まりで確かめます。
- 画面は `hooks/useCaosLanes.tsx`（担当者と交代の流れ。すぐ替えたのは `hooks/useCaosUndo.tsx` の「1つ戻す」に覚える）・`hooks/useShiftFeed.ts`（予定の読み込み）・`hooks/useSeniorRefresh.ts`（読み直したら上級生かを合わせる）・`components/LaneParts.tsx`（見出しの名前と「交代」・ヘッダーの知らせ）・`components/LaneDialogs.tsx`（交代・確認・合言葉）、決まりは `@cafeore/common` の `caosLanes.ts` と `caosShiftFeed.ts` です。

### sohosai-shift の合言葉の入れ方

1. sohosai-shift で CaOS へ配信し、合言葉を受け取ります。
2. 各 iPad の CaOS のヘッダーの鍵のボタン（またはヘッダーの「ドリッパー」の「交代」の中の「合言葉」）を押し、合言葉を入れて「保存」します。その端末にだけ覚えます（`localStorage`。ビルドには入れません）。
3. 予定は Firestore の REST（`https://firestore.googleapis.com/v1/projects/sohosai-shift/databases/(default)/documents/caosFeeds/{合言葉}`）で 5 分ごとに読み直します。
4. 合言葉が無い・読めない端末でも、ヘッダーの「ドリッパー」の「交代」で名前を入れれば交代できます（候補が出ず、見出しの「交代」が押せないのと、上級生と判定できないだけです）。

## 実データ・テストプレイ

- ヘッダーの「テスト」（実データテスト）から、過去の祭の実注文を使ったテストプレイを開始できます。
- データは開始の画面で手元の JSON ファイルを選んで読み込みます（ドラッグでも可）。読める形は [cafeore-tkb/sohosai-analysis](https://github.com/cafeore-tkb/sohosai-analysis) の `YYYY/data/day*.json`（`{ orders: [...] }`）と、cafeore-pos の `GET /api/orders` の応答を保存したものです。day1・day2・day12 のように複数選ぶと、重なる注文は 1 件にまとめます。
- 読み込みはこの端末のブラウザの中だけで、写すのは練習に使う項目だけです（`@cafeore/common` の `caosPracticeData.ts`）。担当者名・コメント・お預かりなどは読み込むときに落とします。サーバーには送らず、画面を開き直したら選び直しです。テストプレイ中は POS の注文の取り込みを止め、API にも書かないので、本番の盤面・注文・在庫には混ざりません。本番に戻ると練習の盤面（テストで作った緊急も）は消えます。
- 開始前に時間帯と30分／1時間を選択します。テストは 10x で始まり（1 時間分の注文が 6 分で流れる）、ヘッダーの `1x / 2x / 5x / 10x` に合わせて、時計・タイムライン・注文到着・抽出時間が一緒に進みます。一時停止・速さ・リセットのボタンはテスト中（終了後の実績表示中も）だけ出します（本番の盤面は実時間なので）。
- 練習の盤面は、本番と同じ形の注文とカップ（ドリッパー・順番・カード・抽出の時刻の列）をブラウザの中だけで持ちます（`hooks/useTestPlay.ts`）。カードの組み立てと操作の書き込みは本番と同じ関数（`buildCaosCards`・`assignWrites` など。`useCaosSession` が本番と同じものを呼ぶ）で、書き込みを当てる（番号を決め、後ろをずらす）のと「次へ」は API と同じ決まりの `@cafeore/common` の `applyCaosPracticeWrites`・`advanceCaosPracticeDripper` で行います。緊急（入れ直し）も練習の盤面の中だけで足し・取り消します。時刻は練習の時計の今です。サーバー・本番の盤面・注文・在庫・印刷には何も送りません。
- 実データの品物には、テストを始めるときに種類の設定（カップを作る・抽出が要る・上級生のみ）を付けます。注文したときの設定があればそれ、無ければ POS の今の商品の種類から名前で引きます（`logic/historical.ts` の `withPracticeItemTypes`）。どちらにも無い品物はカップにせず、実績の杯数にも数えません。カップを作る種類の品物を 1 杯ずつカップにし（POS が注文を保存したときと同じ）、抽出が要るか・上級生のみかは本番と同じく種類の項目で決めます。種類の ID（色の設定を引く）は POS の商品の種類から引きます（`toPracticeOrders`）。
- 指名は実データの指名を写し、練習の盤面でも本番と同じ札（「指名 2nd」の札と点線の枠）・ドリッパーの番号の「指名 N」・決まり（指名の番号のドリッパーにしか置けない・違う番号は 1 枚のカードにしない・指名なしの 1 杯は指名のカードに入れられ、そのカードは指名のドリッパーへ）で出ます。cafeore-pos の注文は明細の `dripper` をそのまま使います。2024・2025 年の Firestore 版の注文は品物の `assignee`（自由記述）で、「1st」「1st 名前」「1」のように番号があればその番号にし、名前だけのものは本番の番号の無い古い明細と同じく指名なし（札に「指名 名前」と出すだけ）にします。練習には担当者がいないので上級生のみの確かめはせず、指名の無い上級生のみのカードもどのドリッパーにも置けます。
- 「終了・実績」を押すと、売上、商品構成、ピーク、提供時間、担当量、分割注文の仕上がりΔを表示します。提供時間は練習の結果（抽出の要るカップが全部準備完了になった時刻）です。
- 過去の注文データはリポジトリに入れません。

## 開発

POS の一部なので、コマンドも POS と同じです（`pnpm pos dev` で開き、`/master-sheet` に行く）。型チェックとビルドも `pnpm pos typecheck`・`pnpm pos build` に含まれます。

lint は POS と同じ決まりです（`biome.json` に CaOS だけの除外はありません）。スタイルは `caos.css` で `.caos-root` の中に閉じ、POS のほかの画面に漏らさないようにしています。

## コードの分け方

- `components/`：部品（表示だけ）。受け取った値を出し、押されたら受け取った関数を呼ぶ。カードは `OrderCard` 1 つで、管制盤 A・C・D と右のパネルで共通。見出し・列の番号と状態（`DripperIndicator`）・「次へ」・空きスロット・置いた場所の札は `BoardParts`、右のパネル（割当・詳細・補助のタブ）は `SidePanels` の `SidePanel`。
- `logic/`：盤面の決まり（純粋な関数）。カードと列の型は持たず、`@cafeore/common` の `buildCaosCards` で組み立てた `CaosCard` と `caosLane` の列（`lanes` の `Lane`）をそのまま使う。カードの名前・注文番号・色・分割の表示（`cards`）・列の時刻（`queue`）・D の表（`sheet`）・A の目盛りと置く時刻（`timeline`）・実績の集計（`analytics`）・実データテスト（練習の注文と実績。`historical`）・カードの豆（`beans`）。カードの組み立てと書き込みの決まりそのものは `@cafeore/common` の `caos-board.ts`・`caosPractice.ts`。実データの注文は `@cafeore/common` の `PracticeDataOrder`。
- `hooks/`：状態と副作用。本番の盤面（`useLiveBoard`。注文を読み、送れていない操作を重ねる）、送れていない操作を端末に残して送る（`useCaosOutbox`）、POS の在庫の読み込み（`useBeanInventory`）、実データテスト（`useTestPlay`。練習の盤面と時計。読み込んだ JSON は `usePracticeData`）、それらをまとめる `useCaosSession`、選んでいるもの（`useBoardSelection`。右のパネルは同じ位置に出るので、開いているもの 1 つ（`OpenPanel`）だけを持つ。D の `useSheetSelection`）、ドラッグと落とす先（`useCardDrag`。待機のカードの前への差し込みは `dropTargetAt`。カードはどの向きになぞってもすぐ掴む）、カードを並べた枠のスクロールバー（`useScrollBar`。部品は `components/ScrollArea`）、未割当のカードの操作（`useUnassignedPick`。A の横帯と C の注文の列で共通）、A の横スクロール（`useTimelineScroll`）など。`App.tsx` はフックを呼んで部品に渡すだけ。
