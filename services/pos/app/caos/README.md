# CaOS — Cafeore Operating System

コーヒー提供現場で、6人のドリッパー（抽出担当者）へ注文を割り当て、進行状況を一画面で把握するためのタッチ操作向けの画面です。iPadの横画面を想定し、管制盤を常に表示したまま操作できます。

画面・操作・業務ルール（割当・指名・最大2杯・統合・`次へ`・先頭へ・途中への差し込み・カードの色・タッチ操作）は、[画面設計・操作要件](./DESIGN_REQUIREMENTS.md)にまとめています。

## 操作の保存と再読込

- 割当・着手・統合などは、端末へ永続保存できてから画面に反映し、すぐDBへの送信を始める。端末の容量不足・保存不可では操作を受け付けず、理由を表示する。画面だけ進めて再読込で消える状態を作らない。
- 同じ端末のタブ間では、送信処理の間だけWeb Locksで排他する。画面を開いている間ずっと送信権を持つ方式は使わない。通信回復・画面復帰でも再送する。送信ロックは `cafeore:caos-sender:v2` とし、旧版の生存中のタブが保持しているロックから分離する。キューの保存キーは維持する。ロック取得をブラウザに拒否された場合も送信は止めず、APIの競合判定を使う。
- 再接続時は注文が届けば盤面操作を送れる。担当者の交代・入れ替え・上級生属性の更新だけは、担当者の再受信（最大3秒）を待つ。
- DB保存前はヘッダーのDBアイコンを黄色にし「保存待ち N」を表示する。接続済みというだけで保存完了とは扱わない。未送信の一覧には直近のHTTPエラー等も表示する。通信障害は端末に残して再送する。競合・ルール違反は理由を通知する。
- APIの成功応答はDBトランザクションの完了後。成功後の盤面への反映待ちは、応答時刻と操作前の値を端末にも保存して別タブ・再読込でも引き継ぐ。送信済みフラグの保存に失敗しても、以前の未送信操作を消さない。
- WebSocketの反映を次の操作が待つのは最大5秒。これはDBコミット前の待ち時間ではなく、保存済みのサーバー値を次の操作に使うための待ち時間。通信中断を含めたDB保存完了の時間に上限は保証できない。

## 操作するタブは1つ

同じURLのサイト・同じブラウザーでは、`/master-sheet` を操作できるタブを1つに限定します。2枚目は自動で `/master-sheet/view` に移り、閲覧専用で盤面を表示します。操作用Provider・担当者変更・コメント送信・操作キューの送信処理は起動しません。通常はそのまま閲覧を続け、必要な場合だけ案内の「このタブで操作したい」から引き継ぎ手順を開きます。元のタブで保存待ちがなくなったことを確認して閉じ、「操作を引き継ぐ」を押すと所有権を再確認して操作画面を開きます。元のタブが残っていれば閲覧へ戻り、引き継げなかった理由と手順を表示します。未送信が残っている場合は、元のタブを閉じずに保存・保全を先に行います。閲覧用の `/master-sheet/view` と `/master-sheet/libero` は同時に開けます。別端末や別ブラウザーの操作は制限しません。

操作タブの所有権は Web Locks の `cafeore:caos-editor:v1` で保持します。単に別タブへ移る・画面をロックするだけでは所有権を渡しません。タブを閉じる・別の画面へ移ると解放し、ブラウザーの戻る操作で画面が復元された場合も再確認します。所有権の確認は操作用Providerをマウントする前に行います。送信処理の排他とは別のロックです。保存容量が不足しても重複判定は維持され、確認不能・非対応の場合は操作を始めず閲覧専用へのリンクを優先して出します。自動の乗っ取りやタイムアウトによる強制引き継ぎは行いません。

更新前の画面が持つ旧送信ロック `cafeore:caos-outbox:` の保持・取得待ちも起動時に確認し、存在すれば閲覧専用画面へ案内します。更新前のコード自体に重複防止を後付けすることはできないため、保全が必要な未送信を確認したうえで古い画面を閉じ、新しい画面へ切り替えてください。

`locks.request` が利用できれば操作できます。`locks.query` がない環境では、旧送信ロックも `request({ ifAvailable: true })` で短く確認し、空いていれば直ちに解放します。重複・旧タブの判定を省略したり、ロックを奪ったりしません。`request` 自体がない・拒否される場合は閲覧を案内します。2026-10-18の調査対象iPad（Safari 26.6.1）では `query` の成功を確認済みです。

旧ロックの確認が応答しない場合も、8秒のタイムアウト・画面離脱・部品の終了で自分の操作ロックを返します。遅い応答で操作画面へ戻したり、次のタブの所有権を解除したりしません。

## 操作ログ

人間が押したカード・ボタン・通知や、検索・返信・割当・統合など、操作対象が分かるイベントと、送信・保存結果・接続障害などのシステムイベントを端末から `POST /api/caos/logs` でDBへ送ります。スクロール、指の座標、pointerdown/up、毎秒の盤面状態や無関係な画面状態の変化は端末ログに保存しません。入力内容は確定した検索番号・返信・緊急理由などの業務操作に限り、入力欄の文字列を一文字ずつ収集しません。

「各種データ書き出し」の「ログを保存」（`GET /api/caos/logs/export`）は「人間のみ」「システムのみ」「混合」を選んでJSONに出力します（既定は人間のみ）。APIは `format=human|system|mixed`。各行の `category` で分類を判別できます。`entries` は時系列の操作一覧で、`time`（日本時間）、`action`（イベント名（component.activated等））、`target`（注文番号・操作対象）、`event`、`details`（カードIDや返信内容など）を含みます。過去の座標・スクロールイベントも通常の書き出しから除きます。操作を試みた記録であり、成功の証明とは区別します。

サーバーの成功履歴（コメント保存、割当・統合・抽出・緊急・担当者変更とcup単位の前後状態）は引き続き更新と同一トランザクションで保存します。監査用の元データは `GET /api/caos/logs/export?format=raw` で `entries` / `operations` / `cups` を取得できます。既存DBの履歴は消しません。`GET /api/caos/logs` はDBに保存された端末イベントの一覧（limit / offset / event / tab_id）です。

未送信の操作ログは端末に保持して再送し、`(tabId, sequence)` で重複を除きます。コンソールには出しません。DBへ届く前のログはダウンロードに含まれません。

cupの親注文・統合先・同時間窓・割当時刻などの監査用取得例は [log-queries.sql](./log-queries.sql)、操作イベントの対応は [LOGGING_COVERAGE.md](./LOGGING_COVERAGE.md) を参照してください。

## ポップアップの移動と画面切替

- マスターシートのポップアップは、見出しの取っ手をドラッグして移動できる。取っ手にフォーカスして矢印キーでも移動でき、画面端・画面サイズ変更で見出しが外へ出ないようにする。大きなパネルは画面内に収まる最大高さを設け、中をスクロールできる。移動後も高さを固定せず、検索結果や入力欄が増えたら残りの画面内で伸びる。
- ヘッダーに非表示の画面を並べる復帰トレイは置かない。右側の操作パネルは常に1画面だけとし、別のパネルを開いたら以前のパネルを置き換える。同じ起動ボタンを押した場合は、その画面を前面に戻す。
- 対象：割当・カード詳細・緊急・列操作・番号検索・補助パネル、担当交代・合言葉・テストプレイ設定、短時間完了の確認・統合/上級生の通知、コメント・音声入力・新着コメント、接続/未送信/印刷、POS共通の操作通知。カードに重ねる操作アイコンやC・Dの右側チャットは盤面内の部品。
- 右側パネルを開き直したときは盤面・カードの最新値を使い、送信時の競合判定を維持する。カード詳細・カードから開いた再抽出は、対象カードが無効になったら終了する。接続・未送信・印刷の通知は問題が解決したら非表示の状態を解除し、次の問題は改めて表示する。
- POS共通の操作通知は成功・エラー・処理中などの色とアイコン、および指定されたアイコンを引き継ぐ。表示時間は通知側の指定に従い、未指定は4秒。処理中と無期限指定は自動終了しない。自動終了では `onAutoClose` を呼び、表示中に触れている間はタイマーを止める。非表示にしても寿命は延ばさない。専用の未解決確認パネルとは区別する。
- 入力内容は別の右側パネルへ切り替えた時点で破棄する。未送信の業務操作は従来の永続キューで保持する。

## 公開

POS の画面の1つとして `/master-sheet` で配信します（<https://cafeore-pos.cafeorepos.workers.dev/master-sheet>）。入口は `services/pos/app/routes/_header.master-sheet.tsx` で、他の内部画面と共通の接続状態・オーダーストップのヘッダーを表示します。盤面はそのヘッダーの実際の高さを引いた領域に収めます。盤面を閲覧だけで映す画面は `/master-sheet/view`（`routes/_header.master-sheet_.view.tsx` → `caos/ReadOnlyBoard.tsx`）で、管制盤 A・C を切り替えて同じ盤面を映します（終わったカードは出さず、抽出中・待機だけ）。空きスロットは出さず、カードを押してもアイコンを出さず（未着手の ✋ の印は出す）、盤面への書き込みも送りません。リベロ（ドリッパーにお湯を持って回る係）が見る画面は `/master-sheet/libero`（`routes/_header.master-sheet_.libero.tsx` → `caos/LiberoBoard.tsx`）で、同じ盤面を読むだけです（下の「リベロビュー」）。閲覧の 2 つの画面はヘッダーの「管制盤」「リベロ」で行き来できます（操作の画面のヘッダーにはリベロビューへのボタンを置きません。トップページの一覧から開きます）。旧リポジトリ `cafeore-tkb/CaOS` から公開していた [GitHub Pages の版](https://cafeore-tkb.github.io/digital-master-sheet-pages/) は、こちらに切り替えたら止めます。

閲覧専用の `/master-sheet/view` はヘッダーのA・Cで表示を切り替えます。選んだビューはこの端末に保存し、廃止済みのDや不正な保存値はAへ戻します。2ビューとも空きスロット・割当・統合・分割・進行・担当者交代は使えず、カードのタップ・長押し・ドラッグでは盤面を変更しません。スクロール・通知音の切替は使え、新着カードの点滅はCにも出します。

## 画面

- **A**: NOW線を基準に、6人のレーンと時間軸で進行・待機カードを確認する管制盤 上部の時刻バーは左右スワイプ・ドラッグで表示時間帯を移動できます（指・ペン・マウス対応）。 左の担当者欄は184pxに詰め、削除した「次へ」ボタンの空きを残しません。
- **C**: 担当者ごとに「ドリップ中」「待ち1」「待ち2」「待ち3」の固定4列で表示します。待ち4以降は待ち3列の中で縦スクロールして確認できます。盤面は列幅を確保し、狭い画面では見出しごと横スクロールできます。
- Cの右側の未割当一覧は注文番号欄を48pxに詰め、番号を20pxに拡大し、カードを横3列で表示します。コメント印と緊急表示は番号の下に置きます。Cの統合カードは注文番号を `#001+#002` と連結せず、`#001` と `#002` の2つの札として横に並べます。
- 時計は見やすい濃色の表示でヘッダー左端です。操作がないときの「直前の操作なし」は表示しません。左側は時計、A/C、現在の順、右側は設定、音量、番号、提供済み一覧、緊急、DB・プリンター接続状況の順です。歯車の「設定」に実データテスト、ドリッパー、豆残量確認、sohosai-shiftの合言葉、上級生の在席状況をまとめています。実績はヘッダーには置かず、テストプレイ終了時だけ開きます。設定から開くドリッパー一覧は1st〜6thを上から縦1列で表示します。
- アイコンのファイル名は機能に合わせる。カード操作は `unassign.svg`（未割当に戻す）、`start-brew.svg`（着手）、`undo-brew-start.svg`（着手取消）、`finish-brew.svg`（完了）、`request-rebrew.svg`（入れ直し）、`view-comments.svg`（コメント閲覧）。`serving-overdue.svg` は未提供の時間超過、`open-dripper-settings.svg` はドリッパー設定を開く操作。未使用の別素材 `undo-brew-start-alternative.svg` は着手取消の代替素材として保管する。
- 最上段のヘッダーは「タイムライン」（A）と「キュー」（C）の切り替えです。操作・閲覧の両画面からDへの遷移ボタンを外し、閲覧画面に残っているDの選択はタイムラインへ戻します。
- ヘッダー全体は淡い青（`#e4eff8`）の背景です。A/Cの選択中は水色で示し、時計・通知・操作ボタンのコントラストを確保します。
- 補助情報は右側パネルに表示し、管制盤全体を隠しません。
- 小画面の「終了」「閲覧を終了」は表示せず、右上の×で閉じます。時計は秒まで48pxの濃い等幅数字で、幅240px・ヘッダーの高さ全体を使う領域の上下左右中央に表示します。時計専用の背景・枠線・影は付けず、時計の下に直前の操作は表示しません。
- iPad で画面全体が動かないよう、CaOS の 3 つの画面（`/master-sheet`・`/master-sheet/view`・`/master-sheet/libero`）を開いているあいだは、ページのスクロール・はね返り・ピンチとダブルタップの拡大を止めます（`caos.css` の `html:has(.caos-root)` で `overflow: hidden`・`overscroll-behavior: none`・`touch-action: pan-x pan-y`、盤面は `h-dvh` で見えている高さに収める。`hooks/useFixedViewport.ts` で viewport に `maximum-scale=1, user-scalable=no` を足し（入力欄を押したときの自動の拡大も止まる）、Safari の `gesturestart`・`gesturechange` を止める）。枠の中のスクロールとスクロールバー・カードのドラッグ・入力欄は今まで通りです。

### 管制盤A・Cの比較

2案とも同じ注文データ・業務ルール（オーダー番号順、指名、最大2杯、`次へ` で完了）を共有し、違うのは見せ方と割当の操作だけです。

| | A：タイムライン | C：ドリッパー行 |
|---|---|---|
| 担当者の並び | 6レーン（横軸＝時刻） | 6行（左半分） |
| 待機列の見え方 | 時間軸上のカード位置で全件 | ドリップ中・待ち1・待ち2・待ち3の固定4列。待ち4以降は待ち3列内で縦スクロール |
| 時間の情報 | NOW線と時刻目盛り、開始・終了予定、未割当タブのNEXT担当者 | 現在の残り時間、未割当タブのNEXT担当者 |
| 列の状態 | ドリッパーの番号（数字だけの細い札）の色と札（空き・待機・抽出中・まもなく・継続中・要確認、待っている指名の杯数）。2案とも同じ `DripperIndicator`。押すと列の操作（交代・待機をまとめて移す） | 同じ |
| ドリッパーのカードを押す | カードの上にその段階の操作のアイコン（未着手は ▶、着手後60秒未満は ✋、以降は 🚨・✓、終わりは 🚨。未着手は1〜6・✕、コメントがあれば💬）を出し、アイコンを押して決める。長押しで待機は詳細、抽出中・終わりは緊急のパネル | 同じ（終わったカードは出さない） |
| 完了済みの表示 | NOW線の左（過去2分半）に、点線の枠で薄く | 出さない |
| 未割当の置き場所 | 下段の横帯（注文ごとに最大3列でカードを折り返す。注文同士は1段へ並べ、見出し右の横スクロールバーで移動。下に続くカードは右の縦スクロールバーで見る） | 右の注文の列（注文番号の行に未割当のカードだけ） |
| 未提供のタブ | 下段の横帯を「未提供」にすると、まだ提供していない注文を左から横に | 右の注文の列を「未提供」にすると上から縦に |
| 未割当の単位 | 抽出カード | 抽出カード |
| 割当操作 | タップで1〜6ボタン／選択後に空きスロットをタップ／なぞり／ドラッグ | タップで1〜6ボタン／なぞり／ドラッグ |
| 割当後の移動・戻し | レーン間ドラッグ、長押しで詳細のパネル | 長押しで詳細のパネル |
| 1杯カードの統合 | あり（未割当・待機・抽出中へタップ、待機・抽出中の真ん中へドラッグ） | あり（同じ） |
| 主な実装 | `ControlViewA`（`DispatchBoard` + `UnassignedStrip`） | `ControlViewC`（右は `OrderQueuePanel`） |

- 予定の抽出時間を過ぎたとき、番号札の「継続中」は抽出開始からの経過時間（例：5:01 → 5:02）に置き換え、毎秒カウントアップする。超過状態の色は維持する。予定を2分過ぎた場合は従来どおり「要確認」と予定を過ぎた時間（+2:00）を表示する。

- **A：タイムライン**　時間の流れを最も正確に表す基準案です。待ち時間の偏りや「誰がいつ空くか」が位置で読めて、ドラッグで再配置できます。代わりに情報量が多く、横スクロールやカードの小ささで一覧性が落ちやすくなります。
- **C：ドリッパー行**　担当者を行にして、現在の抽出と待機列を横に並べる案です。未割当を右半分に全件並べます。待機列が長くなると行内の横スクロールになります。

本番の「実績」は `/dashboard` と同じ店舗運営集計を使い、CaOS向けの詳細な運用分析を表示します。15分流量・提供時間・引き継ぎ・在庫・証拠付きの業務振り返りの定義と計測範囲は [店舗運営ダッシュボード](../../../../documents/analytics/dashboard.md) を参照してください。練習中は本番データを読みません。

## cafeore-pos 連携

- 注文は常に cafeore-pos と同じDBから取り込みます（画面内でモック注文を作る機能はありません）。ヘッダーのDBアイコンの点が接続状態で、緑は接続済み、黄は接続中（最初の注文が届くまでを含む）・再接続中です。その下に重ねたプリンターのアイコンの点は、この端末のシールのプリンター（印刷の設定の `label_printer_ip`）の接続状態で、緑は接続完了、黄は接続中、赤は未接続です。直接接続が未接続で、オンラインの代理印刷キューにもアクセスできないときは、ヘッダーの下（「未送信」「未印刷」と同じ所）に「ラベルプリンター未接続」と、証明書を許可するページ（`https://<プリンターの IP>`）の案内を出します。共有 WebSocket が接続中で、代理印刷キュー API の取得に成功している間は、この案内を隠します。ただし、未印刷の依頼が 1 分以上残った場合は、代理印刷が滞っていると判断して再表示します（30 秒ごとに API を再確認、待ち時間は 1 秒ごとに判定。代理印刷レジや紙の状態を保証する判定ではありません）。警告の「隠す」を押すと、現在の未接続の案内を非表示にします。接続状態が未接続以外に変わると非表示を解除し、再び切断された場合は警告を表示します（未送信・未印刷・レジで印刷待ちの案内は残します）。
- 実データテスト中は cafeore-pos の注文を使わず、ブラウザの中の練習の盤面で動かします（下の「実データ・テストプレイ」）。テストの盤面のあいだ（テスト中も、終えて実績を見ているあいだも）は盤面の上に「テストの盤面です」の帯と「本番に戻る」を出し続け、設定画面の「実データテスト」も本番と違う色にします。「本番に戻る」、またはテストを終えたあとに実績のパネルを閉じると、テストの盤面を捨てて cafeore-pos の注文に戻ります。
- 盤面は注文のカップ（`order_cups`）の列で持ちます。CaOS が決めたこと（ドリッパーの番号 `dripper`・ドリッパーの中の順番 `dripper_position`・同じカードで淹れるカップの印 `drip_id`・抽出の開始 `brew_started_at` と終了 `brew_finished_at`）をカップに書き、注文の応答（`OrderResponse` の `cups`）に載ります。CaOS 以外の画面は読みません。
- カードの状態は時刻で決まります（終了あり＝終わり、開始あり＝抽出中、どちらも無くドリッパーあり＝待機、ドリッパーなし＝未割当）。カードが終わるのは CaOS の「次へ」（`brew_finished_at`。カードの ✓）だけで、提供の画面でカップを準備完了（提供可能）・提供済みにしても、抽出中・待機のカードはそのままです（提供済みのカップのあるカードには「提供済」（一部なら「提供済 1/2」）の札を付けます）。準備完了・提供済みのカップを盤面に出さないのは、まだドリッパーに置いていない未割当だけです。
- 終わったカードは、管制盤 A のタイムラインの NOW 線より左にだけ、点線の枠・地の色なしで薄く残します（抽出中・待機と見分けるため）。管制盤 C・閲覧の画面・リベロビューには出しません（その列は抽出中・待機だけ。未割当の置き場所には、もともと未割当のカードだけを置きます）。終わったカードから入れ直すときは、A のタイムラインのカードを押して 🚨（長押しでも同じパネル）か、ヘッダーの「緊急」で注文番号を入れます。
- 抽出の開始・終わりと、準備完了（提供可能）・提供は別々の時刻で持ち、どの画面がどれを書くかは次の表のとおりです。盤面（抽出の開始・終わり・待機）を書くのは CaOS（マスターシート）の操作だけで、提供の画面は準備完了・提供だけを書きます。CaOS の「次へ」は抽出の終わりだけを付け、提供可能にはしません（呼び出し画面で呼ぶのは、提供の画面で提供可能を押してから）。提供の画面で提供可能・提供を押しても、CaOS の「次へ」は進みません。

  | 時刻（列） | 意味 | 付ける | 外す |
  |---|---|---|---|
  | `brew_started_at`（カップ・入れ直し） | 抽出の開始 | CaOS：割当（空いていれば始める）・先頭へ（`PUT /api/caos/cups` の `start_brew`）、カードの ✓（終えて待機の先頭）・未着手のカードの ▶（`POST /api/caos/drippers/{dripper}/next`） | CaOS：抽出中のカードを動かす・未割当に戻す・✋（未着手に戻す） |
  | `brew_finished_at`（カップ・入れ直し） | 抽出の終わり | CaOS の「次へ」：カードの ✓（待機の先頭も始める） | （CaOS からは外さない） |
  | `ready_at`（カップ・注文） | 準備完了（提供可能。呼び出し画面で呼ぶ） | 提供の画面（`/serve`）のカップのボタン・呼び出しのベル（`PATCH /api/orders/{id}/cups/{cupId}/ready`・`PATCH /api/orders/{id}/ready`）。提供済みにしたとき、付いていなければいっしょに付く | 提供の画面の同じボタン・提供の取り消し |
  | `served_at`（カップ・注文） | 提供 | 提供の画面（`PATCH /api/orders/{id}/cups/{cupId}/served`・`PATCH /api/orders/{id}/served`） | 提供の画面・過去の注文の取り消し |

  注文の `ready_at`・`served_at` はカップから決まります（全部のカップに付いたら注文にも付く）。入れ直しは準備完了・提供を持ちません。
- 抽出の開始・終了の時刻は、操作を押した時刻でサーバーが付けます。画面は「次へ」（✓・▶）・割当・先頭へなどの書き込みに、押した時刻と送った時刻（どちらも iPad の時計のエポックのミリ秒。`press`）を付けて送ります。電波が切れていたあいだに押して後で届いた操作も、押した時刻になります。サーバーは次のように決めます（押した時刻を送らない古い画面からの書き込みは、今までどおりサーバーの今）。
  - 送った時刻がサーバーの今より 5 秒より後（iPad の時計が進んでいる）か、30 秒より前（遅れている。30 秒までは通信にかかった長さかもしれないのでずれとみない）なら、サーバーの今から「押してから送るまでの長さ」を引いた時刻にします。そうでなければ押した時刻のまま（同じ iPad で押した開始と終了の差が、通信にかかった長さでずれないように）
  - サーバーの今より後（未来）ならサーバーの今。今日（日本時間）より前でもサーバーの今（画面は前の日に押した操作を送りません）
  - 同じドリッパーで前の抽出を終えた時刻より前なら、その終えた時刻（ほかの iPad が先に進めた列に、前に押した操作が後から届いたとき）
- 列の先頭（抽出中）に入れて始めるときは、書き込みの after に時刻の代わりに「始める」の印（`start_brew`）を送ります。抽出中のカードも動かせ、先頭でない所・未割当に動かすと始めた時刻が消え、先頭に入れ直すと今から始め直します。終わったカードは動かせません（終えるのは「次へ」）。
- 画面は、POS の画面全体で共有している WebSocket（`/api/ws/orders`、root の `OrdersWSProvider`）の注文から、今日（日本時間。注文の作成日時で区切る）のカードを組み立てます（`@cafeore/common` の `buildCaosCards`）。未割当は、抽出が要り（商品の種類の「カップを作る」と「抽出が要る」が両方オン。`@cafeore/common` の `cupNeedsBrew`。API と同じ決まり）まだ準備完了でないカップを、注文ごと・商品ごと・指名の番号ごとに最大2杯で組み立てます。注文の編集・削除で消えたカップはカードから抜けます。CaOS 用に別の接続は張りません。
- カードの名前は商品の略称をそのまま出します。カードの豆は、カードの商品のアイテムの在庫（`GET /api/inventory` の kind が item のもののうち、抽出が要る（`cupNeedsBrew`）アイテムのもの。豆残量確認に出すのも同じ。`logic/beans.ts` の `dripItemStatuses`）を引き、在庫対象の名前をそのまま出します（豆はカードの札）。カードは未割当・待機・抽出中・終わりとも（A・C と右のパネルで同じ）、いちばん大きく左上に注文番号と、右上に杯数の札（何番が何杯か。提供を合わせるため、何を入れているかより何番を入れているかを先に読む）、次の行に商品を小さく出します（1 杯のカードは統合の判断に商品が要るので、2 行目でも読める大きさ。`OrderCard` の `SIZES` の `no`・`item`。幅の狭いカードでは緊急の札を先に縮めます。統合したカードは、後ろにもう 1 枚重ねた枠で出します。分けた注文のカードの位置・合計杯数はカードに出しません。ほかの場所にも同じ注文があるかは、カードを押して注文を選んだとき（未割当のカード、ドリッパーのカードの長押しで開く待機の詳細・抽出中・終わりのカードの緊急の入力。閉じると選択を外します）に、どこにあっても同じ注文のカードに選択中の黄の輪が付くことで分かります）。統合したカードの長い番号「#120+#121」は、杯数の札と同じ大きさで字の間を詰め、それでも入らなければ省略して、杯数の札をカードの外へ押し出しません。指名は「指名 2nd」（番号の無い自由記述だけの古い明細は「指名 名前」）、上級生のみのカードは「★上級生」の札を出します。
- 指名は、レジで選んだドリッパーの番号（注文の明細の `dripper`。1st〜6th は 1〜6）です。番号のあるカードはその番号のドリッパーにだけ置けます（1〜6 のボタン・ドラッグ。`@cafeore/common` の `caosDripperAllowed`・`assignWrites`、サーバーの `PUT /api/caos/cups` の両方で確かめます）。1 枚のカードに違う番号のカップは入れません（指名なしのカップは指名のカードに入れられ、カードはその番号のままです）。指名のカードの色は、POS の色の設定の画面「CaOS（指名）」から引きます（無ければ「マスター」の色）。地の色は商品の色だけに使い、指名は黒い点線の枠と札で出すので、指名の色が商品の色と近くても見分けられます。
- 操作（割当・ドリッパーの移動・先頭へ・途中への差し込み・未割当に戻す・統合）は、カップの書く前と書いたあとの値を `PUT /api/caos/cups` で送ります（`assignWrites`・`unassignWrites`・`mergeWrites`）。書いたカップの注文は、つないでいる画面に配られます。決まりに合わない操作（指名・2 杯まで・終わったカードなど）は、押したときに画面がサーバーと同じ決まりで確かめて止め、理由が POS の通知（sonner の toast）で出ます。
- 画面を先に動かします（楽観的な更新。`hooks/useCaosOutbox.ts`・`@cafeore/common` の `caos-outbox.ts`）。盤面を書き換える操作（割当・移動・先頭へ・未割当に戻す・統合・外す・まとめて移す・次へ（▶・✓）・未着手に戻す（✋）・緊急の取り消し・担当者の交代と入れ替え・上級生の印）は、押した瞬間に画面が変わり、書き込みは後ろで送ります。
  - 押した操作はまずこの端末の localStorage に 1 件ずつ残し（シールの未印刷と同じ置き方。`~/lib/device-store.ts`）、盤面はサーバーから届いた注文と担当者に、残っている操作を古い順に重ねて出します（重ねるのは実データテストと同じ、サーバーの決まりをブラウザで行う関数）。抽出の始めた・終えた時刻は仮に押した時刻で出し、サーバーの値が届いたら差し替わります。
  - 送るのは古い順に 1 つずつです（同じ端末のタブ間で、送信処理中だけ Web Locks を取ります。待機中はほかのタブも送信できます）。送る直前に書き込みの書く前の値をサーバーの今の値に差し替え、カードの場所（ドリッパー・カード・抽出中か・終わりか）が押したときと同じなら送ります（順番の数・時刻はサーバーが決めるので比べません）。通ったら、その結果の注文がサーバーから届くまで（5 秒まで）は重ねたままにし、次を送りません（一瞬前に戻って見えないように）。注文は 1 つずつ届くので、注文をまたぐ書き込み（統合など）で一部の注文だけ届いたあいだは、届いた注文のぶんを除いて残りを重ねます（統合したカードが一瞬分かれて見えないように）。どの操作も押した時刻をいっしょに送ります（送り直しても押した時刻のまま）。「次へ」は、サーバーの始めた時刻が押したときに見ていたより後にずれていて（ほかの iPad が先に進めた列・iPad の時計が進んでいる）、押した時刻ではサーバーの 10 秒の決まりで断られるときだけ、捨てずに始めた時刻の 11 秒後（時計の差に 1 秒みる）に押したことにして、その時刻まで待って送ります。
  - 送れなかった（つながらない・返事が 10 秒来ない・5xx・ログインが切れた 401・403・時間切れ 408・混んでいる 429）ときは、1 秒から倍にして 15 秒までの間をあけて何度でも送り直し、そのあいだ後ろの操作は待ちます。共有の WebSocket がつながっていないあいだは送らず、つなぎ直したらサーバーから全部の注文と今日の担当者が届き直してから送ります（担当者は注文のあとに届くので、注文が届いてから 3 秒まで待ちます。今日の担当者がまだ無ければサーバーは送らないので、3 秒で待つのをやめます）。前の日に押して残っていた操作は、重ねも送りもせずに捨てて知らせます。再読み込み・タブを閉じても残り、次に開いたら送ります。返事が届かなかったものは、サーバーの盤面がもうそのとおりなら送らずに済ませます。
  - ほかの iPad が先に変えた（409）ときは、1 秒待ってサーバーの今の盤面で確かめ直し、カードの場所が同じ（番号がずれただけ）ならその値でもう一度送ります。もうそのとおりなら済みにします。場所が違えば、決まりに合わない（400 など）ときと同じく送り直さずに捨て、盤面はサーバーの今に戻り、「「割当 #038 → 2nd」は通らなかったので、盤面を戻しました」と理由を通知で出します（その操作はヘッダーの「直前の操作」からも消えます）。捨てた操作のあとに押した操作も、場所が合わなければ同じく捨てます。
  - 担当者の交代（見出しの「交代」・交代の画面で選ぶ・名前を入れる・空きにする）と入れ替えは、サーバーが書く前の値を確かめないので、送る直前にサーバーの今の担当者が押したときの担当者のままかを画面が確かめます。ほかの iPad が先に替えていれば送らずに捨て、盤面はサーバーの今に戻り、「1st の交代は、ほかの iPad が先に替えていたので取りやめました」と通知で出します（「直前の操作」からも消えます。続けて押した交代も同じく捨てます）。上級生の印を直すのは、名前が同じときだけ書くので確かめません。押したときの担当者を持たない前の版の交代（端末に残っていたもの）は、確かめずに送ります。
  - 押してから 2 秒を過ぎても送れていない操作があれば、ヘッダーの下に「未送信 N 件」と「もう一度送る」を出します（シールの「未印刷 N 件」と同じ所）。「未送信 N 件」を押すと、送れていない操作の一覧（押した時刻と操作の名前）を開き、1 件ずつ（×）か「全部消す」（2 回押し）で消せます。消した操作は送らず、盤面はサーバーの今に戻ります（ヘッダーの「直前の操作」からも消えます。`hooks/useCaosOutbox.ts` の `discard`・`components/UnsentOps.tsx`）。今送っていて返事を待っている操作（`createCaosOutbox` の `inFlight`）は、もうサーバーに届いているかもしれないので消せず、「送信中」と出します（「全部消す」もそれを除きます）。一覧は外を押すと閉じます。
  - 実データテスト中の操作は練習の盤面の中だけで、残しも送りもしません（テストの前に押した本番の操作は送ります）。閲覧だけの画面は送りません。
  - 緊急（入れ直し）を足すのは、入れ直しの id をサーバーが決めるので、今まで通り応答を待ちます。統合したカードから入れ直したときに 1 枚のカードにまとめる統合は、足した入れ直しが全部盤面に届いたとき（応答より先に届いていれば、応答のすぐあと）に、ほかの操作と同じく端末に残して後ろで送ります（入れ直しは注文ごとに届くので、先に届いた 1 杯のカードが一瞬（手元で 0.1 秒ほど）出てから 1 枚になります）。
- 順番（`dripper_position`）は整数で、サーバーが決めます。画面が送るのは「どのドリッパーの、どのカードの前に入れるか」（after の `insert_before`。`null` なら最後）だけです。サーバーは前に入るカードの番号に入れ、そのドリッパーでそれより後ろの終わっていないカップを +1 します。列から抜けたカードの番号は詰めません。
- 列の先頭は抽出中です。待機のカードの「先頭」ボタンで列の先頭へ（今から始まり、抽出中だったカードは始めた時刻を消して待機の先頭へ下がります）、「待機の先頭」ボタンで抽出中のすぐ後ろへ、番号のボタン（今のドリッパーでも）でその列の最後へ入ります（`@cafeore/common` の `CaosPlace` の `"front"`・`"queueFront"`・無し）。ドラッグでは、列の待機・抽出中のどのカードの上にも落とせ、カードの左の端（幅の 30%）はそのカードの前（`{ beforeKey }`）、右の端（30%）は後ろ（`{ afterKey }`）、真ん中（40%）は統合です（統合できる相手のときだけ。できない相手なら真ん中は近いほうの端。`logic/lanes` の `dropSideAt`・`hooks/useCardDrag` の `dropTargetAt`）。抽出中のカードの前は列の先頭（今から始まる）、後ろは待機の先頭です。落とす前に、指に付いた写しに「#003 の前へ（今から始める）」「#003 の後ろへ（待機の先頭）」「#003 と統合」の札を出し、指の下のカードの左右の縁に入れる所の線、統合なら統合の色の枠を出します（`OrderCard` の `DropMark`）。同じ列の中の入れ替えにも使え、管制盤 A・C で同じです。列のカードの無い所や 1〜6 のボタンに落とすとその列の最後へ入ります（札「→ 3」）。運んでいるカード自身の列の空いた所（A のタイムラインの右の空いた所など）に落としても、ほかの列と同じくその列の待機の最後へ入り、札は「3rd の最後へ」です（抽出中のカードなら、抜けたあと待機の先頭が今から始まります）。もう列の最後にある（動かしても同じ場所の）カードと、掴んだカード自身の上で離したときは何もせず、札も出しません。抽出中も待機も無い列に入れたら、そのまま始めます（抽出中が無く待機のある列の先頭は待機の先頭（未着手）で、▶ で始めます）。

## リベロビュー

- 画面を縦長の6列に分け、**右端から1・2・3・4・5・6**の固定順に並べます。経過順への並び替えは行いません（古い `?order=elapsed` のURLも固定順になります）。
- 列の上部にドリッパー番号と担当者名（抽出開始から60秒未満は担当者名とその下の現在・NEXTの情報も赤文字）、中央に抽出中の注文番号・杯数を大きく表示します。ホットは赤、アイスは青で示し、ホット／アイスの文字は表示しません。混在したカードは全カップを数え、赤・青の独立した背景要素を杯数比率で並べ、それぞれの背景色を1秒で滑らかに変え、赤の杯数＋青の杯数を表示します（読み上げでは種別も伝えます）。統合した注文は番号をすべて表示します。
- 予測残り時間を「あと」とともに毎秒表示し、「いま淹れています」は表示しません。共通の杯数別抽出時間（`caosBrewSec`）と開始時刻に基づく目安であり、実際の完了を判断する値ではありません。残り時間の割合が減るにつれて中央の背景を白から濃い赤（ホット）／青（アイス）へ変え、終了間際ほど急に濃くなる指数曲線を使います。背景の色面と進行バーは抽出済みの割合で同期し、右から左へ広がります。混在時の赤青比率は色面の中で維持します。番号・杯数・残り時間・NEXTはグリッドで位置をそろえます。リベロの番号・杯数・時間・NEXTの行は、内容に必要な高さを下限にする。長い名前や複数の番号が収まらない場合は、その領域内で縦スクロールでき、隣の行には重ねない。抽出中は色面の境界が文字を横切るため、単色・混在とも文字の周囲だけ白い下地と濃い文字にします（開始60秒未満は赤文字）。NEXTの単色背景では濃さに合わせて白黒を切り替えます。混在時は番号・杯数・残り時間・見出しの文字の周囲だけに白い下地を付け、濃い文字を載せ、左右どちらの背景色やアニメーション途中の色にも依存しない読みやすさを保ちます。予定を過ぎても完了するまでは「あとちょっと」と表示します。
- 下部の「NEXT」には、その列の待機先頭1件の注文番号・杯数を表示します。背景はホットが赤、アイスが青です。6列の待機先頭を注文番号の若い順にまとめ、先に完成させたい注文ほど濃く、最後を薄く等間隔に色分けします。同じ注文番号を含むカード（統合したカードでつながるものも含む）は同じ濃さにそろえます。これは同じ注文を近い時刻に、原則番号順に完成させるための目印で、割当や待機順を自動変更するものではありません。待機がなければ「予定なし」。抽出中がなければ中央は灰色の「開始待ち」または「空き」とし、待機を抽出中として扱いません。
- 閲覧の画面（`/master-sheet/view`）と同じく、本番の盤面を読むだけで書き込みは送りません。未割当や完了した抽出は出しません。列を押しても何も起きません。文字は画面幅に合わせて拡大し、長い番号や名前は折り返します。
- 閲覧の 2 つの画面は、新しく入ったカードを通知音と 4 秒の点滅（`caos.css` の `.caos-arrival`）で知らせます（`hooks/useViewBoard.ts`）。閲覧の画面はタイムラインに入ったカード（割り当てた・抽出を始めた。`logic/timeline.ts` の `timelineArrivals`）そのものを、リベロビューは抽出を始めたカード（`brewStarts`。待機に入っただけのカードは知らせません）のドリッパーの列を点滅させます。音はヘッダーで「音あり」「音なし」を切り替え、その端末に覚えます（はじめは音なし）。iPad は画面に触れるまで音を出せないので、出せない間（開き直したあとなど）はヘッダーに「音あり（触れると鳴る）」と出し、画面のどこかに触れたら鳴るようになります。閲覧の画面の未割当の横帯は「たたむ」でたためます（その端末に覚えます）。たたむと、空いた高さをタイムラインが使い、ドリッパーの列が高くなります（「ひらく」で元に戻ります）。

## 交代候補と対応ドリップの目印

- 交代ポップアップは最初に従来の予定候補を表示する。学年ボタンを押すと、配信名簿のその学年の人を表示する（現在の担当者は除く）。「予定の候補」で戻る。上級生の印と自由入力・入替は従来通り。
- 学年はsohosai-shiftの `members: [{name, grade}]` を使用する。古い配信に名簿がないときは、予定にある氏名を「学年未登録」で残す。氏名や上級生の印から学年を推測しない。学年候補を使うにはシフト側の名簿対応を反映し、改めて「配信」する。
- `drips` の対応一覧を読み、操作の画面A・Cの担当者名ボタンの下に、できない抽出だけを注意札で表示する。1・2杯とも不可は「アイス×」、1杯だけ不可は「アイス1×」、2杯だけ不可は「アイス2×」（ホットも同様）。全対応・担当者なし・未登録は札を出さない。未登録を対応不可と判定しない。
- 未割当カードの1〜6のボタンは、カードの種別・杯数が担当者の対応一覧にないとき数字をグレーにする。ボタンは押せるままで、ドラッグやAPIの条件も変えない。従来の指名先以外の制限はそのまま。混在カードは種類別の杯数で確認する。

## ドリッパーの担当者と交代

- 「今そのドリッパーに誰がいるか」（名前と、上級生か）はサーバーが日本時間の日付ごとに持ちます（API の表 `dripper_assignees`。`api/internal/handlers/caos_lanes.go`）。全部の iPad に共有の WebSocket の `{"type":"caos_lanes"}` で届き（今日の 6 つ全部）、列の見出しに「1 山田★」のように、数字だけの細い番号の札の横に名前を大きく出します（上級生に ★。A・閲覧・リベロは入らない名前を 2 行まで折り返して、6 文字ほどは省かずに出す。担当者がいなければ番号だけ）。漢字4文字以内の名前は1行で表示し、幅が足りない場合は交代アイコン・上級生の印を次行へ回します。極端に狭い枠では4文字以内でも枠内で省略し、5文字以上の名前を1行表示する箇所では名前を省略して上級生の印を同じ行に残します。リベロビューは各列の上部に番号を大きく表示します。閲覧だけの画面（`/master-sheet/view`・`/master-sheet/libero`）も名前を出しますが、交代はできません。
- 替えるのは人が CaOS で行います（`PUT /api/caos/lanes/{dripper}`）。押したらその場で替わります（抽出中かどうかは見ません。待機のカードも動きません）。
  - 列の見出し（A・C）と列の操作パネルは、現在の担当者名と支給の交代アイコン `change-dripper.svg` を1つのボタンにする。次の担当者の予告が出ている間はその人へ即時交代する。予告が出ていない場合（10分前の時間帯以外・次の枠が空き・同じ担当者・予定未取得など）は、ドリッパータブの「交代」と同じ選択モーダルを開く。次のシフトの実際の開始時刻の10分前から「次：鈴木」の予告を添える（本番の枠・オペ練の開始時刻を使い、同じ担当者・空きの予告は出さない）。予告は未開始の枠だけを対象とし、開始時刻になったら消す（手動で別の担当者に替えていても今の枠の人を「次」として出さない）。予告中はその人へ交代する。自動交代はせず、替えた操作は「直前の操作」に出す。二度押し防止は1秒。閲覧専用画面は現在の名前だけを表示する。
  - ドリッパータブの「交代」は、名前ボタンと同じアイコン・角丸・白背景・枠線で統一し、最低96×52px、文字16px・アイコン24pxに拡大する。こちらは従来どおり交代の選択画面を開く。
  - 歯車の設定画面にある「ドリッパー」の各ドリッパーの「交代」は交代の画面を開き、候補から選ぶ・名前を入れる・空き（担当者なし）にする・ほかのドリッパーの担当者と入れ替える（`POST /api/caos/lanes/swap`）ができます。
- 替えるたびに、サーバーが交代の記録（表 `dripper_assignee_changes`。時刻・ドリッパー・前の名前・後の名前・後の人が上級生か。入れ替えは 2 行）を足します。抽出の統計のためのもので、画面には出しません。
- 名前の候補は sohosai-shift の予定から出します。今の枠・次の枠（本番の 30 分ごとの枠）と、オペ練の今と次のラウンドの、そのドリッパーの番目の人です（この順。今そのドリッパーにいる人と空きは除きます。`laneCandidates`、すぐ替える次の人は `nextLaneCandidate`）。候補に無い人は歯車の「ドリッパー」から自由に入れられます。予定の時刻どおりに自動で替えることはしません。
- 上級生かは、sohosai-shift の上級生の名簿（`seniors`）に名前があるかで、画面が判定してサーバーに持ちます。交代した時点で判定し、予定を読み直したとき（5 分ごと・手で読み直したとき・合言葉を入れたとき。読めたときだけ）にも、今の担当者の分を新しい名簿に合わせます（名前は変えず上級生かだけ。`POST /api/caos/lanes/seniors`。交代ではないので交代の記録は足しません。`hooks/useSeniorRefresh.ts`）。名簿に載った人は上級生にし、名簿から消えた人は外します（外す人のドリッパーに指名の無い上級生のみのカードがあっても外し、カードに警告の印が付きます）。読めない・合言葉が無い・名簿が空のときは何も変えません。閲覧だけの画面と実データテスト中は書きません（テストを終えてから合わせます）。判定するのは画面で、サーバーは名簿を持たず、送られた値（`senior`）をそのまま持ちます（`PUT /api/caos/cups` は上級生かを見ません）。上級生の在席状況は歯車の設定画面で確認します。
- 上級生のみのカードも、担当者が上級生でない（担当者なしも）ドリッパーに置けます（ドラッグ・1〜6・統合・まとめて移すのどれでも。画面もサーバーの `PUT /api/caos/cups` も止めません）。置いたら右上に「上級生のみの #012 を上級生でない 3rd 佐藤に置きました」と知らせ（`@cafeore/common` の `nonSeniorPlacement`・`nonSeniorMerge`。別のドリッパーへ置くときだけで、同じドリッパーの中の順番の入れ替えでは知らせません）、上級生でない担当者のドリッパーで待っている・抽出中のあいだは、カードの「★上級生」の札を赤い「⚠上級生」にします（`seniorOnlyOffSenior`。交代で上級生にすれば消えます）。実データテストには担当者がいないので出しません。担当者のいないドリッパーに置いたときは知らせず、警告の印だけです（その列に誰も立っていないので。担当者を空きに替えるときは、下のとおり知らせます。どちらもわざとです）。送った操作が断られて盤面が戻ったときは、その操作の知らせ（上級生のみ・時間のたった統合）も一緒に消します。まとめて移したときは「上級生のみのカード 2 枚を上級生でない 3rd 佐藤に移しました」と 1 つにまとめます。上級生でない人（担当者なしも）に替えるとき、そのドリッパーに指名の無い上級生のみのカード（抽出中・待機。警告の印と同じ数え方）があっても止めずに替え、POS の通知で「交代 1st → 佐藤：このドリッパーに指名の無い上級生のみのカードが1枚あります（佐藤さんは上級生ではありません）」と知らせます（見出しの「交代」ですぐ替えるときも同じ）。どのドリッパーにも上級生がいなければヘッダーに知らせます。
- 指名と上級生のみがぶつかるとき（上級生のみのカードの指名のドリッパーの担当者が上級生でない）は、指名を優先し、知らせも警告の印も出しません。指名のあるカード（指名のカップが 1 つでも入ったカード）は指名のドリッパーにしか置けません。統合は統合したあとのカードで見るので、指名の無い上級生のみのカードも、指名のカードに入れれば知らせません。
- 画面は `hooks/useCaosLanes.tsx`（担当者と交代の流れ。すぐ替えたのは `hooks/useLastAction.tsx` の「直前の操作」に覚える）・`hooks/useShiftFeed.ts`（予定の読み込み）・`hooks/useSeniorRefresh.ts`（読み直したら上級生かを合わせる）・`components/LaneParts.tsx`（見出しの名前と「交代」・設定内の担当者状態）・`components/LaneDialogs.tsx`（交代・合言葉）、決まりは `@cafeore/common` の `caosLanes.ts` と `caosShiftFeed.ts` です。

### sohosai-shift の合言葉の入れ方

1. sohosai-shift で CaOS へ配信し、合言葉を受け取ります。
2. 各 iPad の CaOS のヘッダーにある歯車から「合言葉入力」を押し、合言葉を入れて「保存」します。その端末にだけ覚えます（`localStorage`。ビルドには入れません）。
3. 予定は Firestore の REST（`https://firestore.googleapis.com/v1/projects/sohosai-shift/databases/(default)/documents/caosFeeds/{合言葉}`）で 5 分ごとに読み直します。
4. 合言葉が無い・読めない端末でも、歯車の「ドリッパー」から名前を入れれば交代できます（候補が出ず、見出しの「交代」が押せないのと、上級生と判定できないだけです）。

## 実データ・テストプレイ

- 歯車の設定画面にある「実データテスト」から、過去の祭の実注文を使ったテストプレイを開始できます。
- データは開始の画面で手元の JSON ファイルを選んで読み込みます（ドラッグでも可）。読める形は [cafeore-tkb/sohosai-analysis](https://github.com/cafeore-tkb/sohosai-analysis) の `YYYY/data/day*.json`（`{ orders: [...] }`）と、cafeore-pos の `GET /api/orders` の応答を保存したものです。day1・day2・day12 のように複数選ぶと、重なる注文は 1 件にまとめます。
- 読み込みはこの端末のブラウザの中だけで、写すのは練習に使う項目だけです（`@cafeore/common` の `caosPracticeData.ts`）。担当者名・コメント・お預かりなどは読み込むときに落とします。サーバーには送らず、画面を開き直したら選び直しです。テストプレイ中は POS の注文の取り込みを止め、API にも書かないので、本番の盤面・注文・在庫には混ざりません。本番に戻ると練習の盤面（テストで作った緊急も）は消えます。
- 開始前に時間帯と30分／1時間を選択します。テストは 10x で始まり（1 時間分の注文が 6 分で流れる）、盤面の上の「テストの盤面です」の帯の `1x / 2x / 5x / 10x` に合わせて、時計・タイムライン・注文到着・抽出時間が一緒に進みます。一時停止・速さのボタンはこの帯（テストの盤面のあいだだけ出る）に置きます（本番の盤面は実時間なので。やめるのは「本番に戻る」）。
- 練習の盤面は、本番と同じ形の注文とカップ（ドリッパー・順番・カード・抽出の時刻の列）をブラウザの中だけで持ちます（`hooks/useTestPlay.ts`）。カードの組み立てと操作の書き込みは本番と同じ関数（`buildCaosCards`・`assignWrites` など。`useCaosSession` が本番と同じものを呼ぶ）で、書き込みを当てる（番号を決め、後ろをずらす）のと「次へ」は API と同じ決まりの `@cafeore/common` の `applyCaosPracticeWrites`・`advanceCaosPracticeDripper` で行います。緊急（入れ直し）も練習の盤面の中だけで足し・取り消します。時刻は練習の時計の今で、本番と同じく同じドリッパーで前の抽出を終えた時刻より前にはしません。サーバー・本番の盤面・注文・在庫・印刷には何も送りません。
- 実データの品物には、テストを始めるときに種類の設定（カップを作る・抽出が要る・上級生のみ）を付けます。注文したときの設定があればそれ、無ければ POS の今の商品の種類から名前で引きます（`logic/historical.ts` の `withPracticeItemTypes`）。どちらにも無い品物はカップにせず、実績の杯数にも数えません。カップを作る種類の品物を 1 杯ずつカップにし（POS が注文を保存したときと同じ）、抽出が要るか・上級生のみかは本番と同じく種類の項目で決めます。種類の ID（色の設定を引く）は POS の商品の種類から引きます（`toPracticeOrders`）。
- 指名は実データの指名を写し、練習の盤面でも本番と同じ札（「指名 2nd」の札と点線の枠）・ドリッパーの番号の「指名 N」・決まり（指名の番号のドリッパーにしか置けない・違う番号は 1 枚のカードにしない・指名なしの 1 杯は指名のカードに入れられ、そのカードは指名のドリッパーへ）で出ます。cafeore-pos の注文は明細の `dripper` をそのまま使います。2024・2025 年の Firestore 版の注文は品物の `assignee`（自由記述）で、「1st」「1st 名前」「1」のように番号があればその番号にし、名前だけのものは本番の番号の無い古い明細と同じく指名なし（札に「指名 名前」と出すだけ）にします。練習には担当者がいないので、上級生のみのカードの知らせと警告の印は出しません。
- 「終了・実績」を押すと、売上、商品構成、ピーク、提供時間、担当量、分割注文の仕上がりΔを表示します。提供時間は練習の結果（抽出の要るカップが全部抽出を終えた時刻。練習には提供の画面が無いので、提供可能の代わりに使います）です。
- 過去の注文データはリポジトリに入れません。

## コードの分け方

- `components/`：部品（表示だけ）。受け取った値を出し、押されたら受け取った関数を呼ぶ。カードは `OrderCard` 1 つで、管制盤 A・C と右のパネルで共通。見出し・列の番号と状態（`DripperIndicator`）・空きスロット・置いた場所の札は `BoardParts`、カードの上の操作のアイコンと印は `CardActions`、右のパネル（割当・詳細・補助のタブ）は `SidePanels` の `SidePanel`。
- `logic/`：盤面の決まり（純粋な関数）。カードと列の型は持たず、`@cafeore/common` の `buildCaosCards` で組み立てた `CaosCard` と `caosLane` の列（`lanes` の `Lane`）をそのまま使う。カードの名前・注文番号・色・分割の表示（`cards`）・列の時刻（`queue`）・A の目盛りと置く時刻（`timeline`）・実績の集計（`analytics`）・実データテスト（練習の注文と実績。`historical`）・カードの豆（`beans`）・注文番号の検索（`search`）・注文のコメント（`comments`）。カードの組み立てと書き込みの決まりそのものは `@cafeore/common` の `caos-board.ts`・`caosPractice.ts`。実データの注文は `@cafeore/common` の `PracticeDataOrder`。
- `hooks/`：状態と副作用。本番の盤面（`useLiveBoard`。注文を読み、送れていない操作を重ねる）、送れていない操作を端末に残して送る（`useCaosOutbox`）、POS の在庫の読み込み（`useBeanInventory`）、実データテスト（`useTestPlay`。練習の盤面と時計。読み込んだ JSON は `usePracticeData`）、それらをまとめる `useCaosSession`、選んでいるもの（`useBoardSelection`。右側で現在開いている1つの`OpenPanel`を持つ）、ドラッグと落とす先（`useCardDrag`。列のカードの前・後ろ・統合は `dropTargetAt`。カードはどの向きになぞってもすぐ掴み、動かさずに 0.6 秒押し続けたら長押し。ドラッグしないカードの長押しは `useCardHold`）、カードを並べた枠のスクロールバー（`useScrollBar`。部品は `components/ScrollArea`）、未割当のカードの操作（`useUnassignedPick`。A の横帯と C の注文の列で共通）、A の横スクロール（`useTimelineScroll`）、注文番号の検索（`useOrderSearch`）、コメントの知らせ（`useCommentNotices`）・予定を大きく過ぎた抽出の音（`useForgottenBrewAlert`）など。`App.tsx` はフックを呼んで部品に渡すだけ。

対応抽出の判定は、カップを作り抽出が必要な商品のみを対象に、ホット・アイス各1杯／2杯の4種類を参照する。ミルク・その他は数えない。盤面は最大2杯なので、3杯以上の不正なカードでは能力を推測せずグレー表示を付けない（操作の制限は追加しない）。学年絞り込み中にその学年が配信から消えた場合は、シフトの予定の候補に戻る。

## 同じ注文を見つけるハイライト

- 操作用タイムラインのカード本体をタップすると、同じ注文IDのカードの枠と番号の数字を強調します。統合カードでは小さい番号から明るいオレンジ `#F59E0B`・赤みのあるオレンジ `#EA580C` を割り当てます。番号部分のボタンはその注文だけを強調し、カードの割当・統合・開始などは呼びません。カード本体の従来の操作メニュー・統合・ドラッグ・長押しは維持します。
- `#012＋#013`を選んでいて`#013＋#014`のカードがある場合、後者の#013と対応する半分の枠だけを強調します。#014の別カードへは連鎖しません。番号から片方だけに絞っても、その番号に割り当てた色は維持します。
- タイムラインでは該当ドリッパーの固定見出しにも同色の番号を表示します。画面外に完全に隠れたカードは、見出し内の左右の方向・対象注文の杯数から移動できます。指名・商品の色・緊急表示は残し、白い縁取りで区別します。タイムラインの高さや目盛りは変えません。時間差の数値・閾値警告・点滅は追加しません。
- カード外のタップまたは「解除」でハイライトだけを解除します。方向ボタン・番号の案内は解除対象から除外します。スクロール・ドラッグ・カードの移動・統合解除・消失では解除せず、本番/練習の切替と日付変更ではリセットします。表示用の状態は操作対象・コメントの選択から分離し、DB・API変更やハイライトによる業務操作の送信はありません。キュー表示・閲覧専用画面の操作は変更しません。

### 入れ直し元の破棄

入れ直しが登録された未完了の元抽出には、通常の操作メニューと同じ中央・直径40pxのゴミ箱ボタンを表示します。押すと対象の注文番号・商品・杯数を確認し、確定するとその杯だけを終了カードへ移します。統合相手・新しい入れ直し・提供状態・在庫は変更せず、待機の先頭も自動開始しません。ラベル再発行だけの場合は候補にしません。入れ直し自体を再び入れ直した場合にも、その元の抽出単位を対象にします。

`POST /api/caos/discard` は元カードの値を楽観ロックで確認し、更新と同じトランザクションで既存の操作履歴に `brew.discard` を保存します。破棄した抽出の終了時刻・対象unit ID・前後の値を履歴で識別できます。DBの列・表は追加しません。送信は既存の永続アウトボックスを使い、再送は固定の終了カードIDで重複を防ぎます。練習モードも同じ対象判定で処理します。

現在の提供時間グラフは初回抽出開始と提供時刻の集計です。正常抽出だけの時間や破棄数を集計する場合は、`brew.discard` の対象unit IDで区別してください。グラフ側の集計方式はこの変更では拡張しません。
### オーダーストップ・受付再開

操作画面のヘッダーで、提供済み一覧と緊急の間に「受付中／受付停止中」を表示します。押すと確認パネルが開き、停止・再開を確定できます。既存マスターと同じ `/api/master-status`・履歴・WebSocket配信を利用し、マスター側の操作も残します。これは受付停止を知らせる機能で、レジの注文入力・送信やCaOSの抽出操作をロックするものではありません。停止中の紫の共通ヘッダーも引き続き表示します。

未取得・切断中・送信中は操作できません。取得失敗時は「受付状態を再取得」から読み直せます。練習中と閲覧専用画面には切替操作を出しません。確認後に他端末の更新を受けたらパネルを閉じ、再度確認してもらいます。

CaOSは確認した状態の `type` と `created_at` を `expected` として送ります。APIは同一トランザクション内のロックで最新状態と比較し、違えば409を返します。失敗・競合時は状態を読み直すだけで、受付切替の自動再送・オフライン予約は行いません。同じ状態の連打でも履歴は増えません。DBスキーマの変更はありません。`expected` を省略する従来のマスター画面のリクエスト形式も引き続き利用できます。
