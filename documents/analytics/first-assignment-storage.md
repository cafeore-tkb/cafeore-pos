# 初回割り振り時刻の保存（Draft）

ダッシュボード再構成PR #1060 から独立させたDB・API・commonの変更案。UIの表示・分析への接続は含まない。#1060 はこの変更なしで動作する。

## 変更内容

- `order_cups` と `cup_emergencies` にNULL許容の `assigned_at` を追加する。起動時の既存 `AutoMigrate` が反映する。列・テーブルの削除はない。
- CaOSの割当書込と同じトランザクションで、未設定の時だけ操作時刻を保存する。再割当や未割当戻しで上書きしない。
- APIレスポンスはoptionalかつnullable。commonのモデルもoptionalで、旧レスポンスの欠落は未計測として受け入れる。
- 元のPRで必須だったレスポンス項目は、旧API・旧JSONとの互換性のため任意項目に修正した。

## Draftとして残す判断事項

1. 既存の `CaosOperationCup.AssignedAt` と成功履歴の集計で足りるか確認する。保持列を追加するなら、読み取り効率と二重管理の必要性を説明する。
2. 導入前から割り振り済みの杯では、次の移動時刻を真の初回と誤認し得る。既存データの区別・計測開始点を決めてから本番へ出す。
3. 入れ直し側の列を実際に何に使うかを確定する。
4. 既存DBからの移行、旧版との混在、初回・再割当・未割当戻し・入れ直し・注文編集・トランザクション失敗を実DBで検証する。
5. 旧版へ戻した際の `findSchemaDrift` と `/status`・デプロイ確認の挙動を検証する。追加列は旧モデルにない列として検知されるが、起動自体は止めない。

## 検証範囲

旧レスポンスの欠落・null・日時の変換、スキーマとの整合性はTypeScriptの単体テストで確認する。ローカル端末にGo/Postgres環境がないため、DB移行とCaOS書込の結合試験は未実施。CIのPostgres結合試験と上記の確認を完了するまで、マージ・デプロイの準備完了とはしない。
